# F-09 · Database explorer & SQL editor (proposed Tracker ID: R-507)

**Status:** specified. **Depends on:** F-01, F-02 (a running preview is what creates the database).

## Why this is real, not a mock

`localrun/run.py` already **creates a clean per-app PostgreSQL database and applies the generated
migrations** before starting a generated app. So a project in preview has a real schema with real
rows. Showing it is honest; the only work is exposing it safely.

Lovable's Database page is one of the features that makes their product feel complete
(`Lova-08`, `Lova-09`). Ours can be equally real because we already run the migrations.

## Design

### Connection and safety

- The agent-engine owns the connection (it created the database) and exposes read/query endpoints;
  the control-plane never talks to a generated app's database directly.
- Access is per project and requires ownership (F-01).
- The database URL is never returned to the browser.
- **psycopg is not available** (the agent-engine is standard-library only). Two options, decided
  at implementation time and recorded:
  1. Run queries through the project's own Postgres container via
     `docker exec … psql --csv` (the pattern `scripts/db.sh` already uses) — zero new dependency;
  2. Add `psycopg` to the agent-engine's optional preview extra, which is already an opt-in,
     toolchain-dependent path (preview mode installs Node and pnpm; a Python driver is no worse).
  Start with (1) because it keeps `task verify` offline and dependency-free; revisit if `psql`
  parsing proves brittle.

### Query rules

- **Explorer** queries are generated by us (`SELECT … FROM <table> ORDER BY … LIMIT … OFFSET …`),
  with the table name validated against `information_schema` — never interpolated from user text.
- **SQL editor** accepts arbitrary SQL but:
  - runs inside a transaction that is **rolled back** unless the user ticks "Write mode";
  - has a statement timeout (`SET LOCAL statement_timeout = 10s`);
  - returns at most 500 rows;
  - refuses `DROP DATABASE`, `CREATE ROLE`, `COPY … TO PROGRAM` and anything outside the project's
    own database;
  - every statement is logged (F-08) with its duration and row count.
- Write mode shows a clear warning: this changes your app's real data.

### API

| Method | Route | Behaviour |
| --- | --- | --- |
| `GET` | `/projects/{id}/db/tables` | Tables with row counts and column metadata. |
| `GET` | `/projects/{id}/db/tables/{table}?limit=&offset=&order=` | A page of rows. |
| `POST` | `/projects/{id}/db/query` | `{sql, write?}` → columns, rows, duration, truncated flag. |
| `GET` | `/projects/{id}/db/schema` | The applied migration SQL, for reference. |

All return 409 with "Start the preview to create this project's database" when no database exists
yet — the honest state, not an empty table.

### UI

Reference: Lovable Database (`Lova-08`, `Lova-09`) and SQL editor (`Lova-16`).

- **Manage → Database**: left list of tables with row counts; right pane a virtualised grid with
  column headers, type badges, sortable columns, pagination, and a JSON viewer for `jsonb` cells.
  Null renders as a muted `NULL`, not an empty cell.
- **Manage → SQL**: a code editor (the existing `code-highlight.ts` tokenizer reused for SQL), Run
  (⌘↵), a Write-mode switch with the warning, a results grid, timing and row count, and an error
  panel showing PostgreSQL's message verbatim.
- Both show "Preview isn't running" with a Start button when there is no database.

## Acceptance criteria

- [ ] For a project in preview, the table list matches the generated migration's tables and the
      row counts match reality.
- [ ] Read-only queries cannot mutate data (verified: an `UPDATE` without Write mode leaves the
      row unchanged).
- [ ] A slow query is cut off by the statement timeout with a clear message.
- [ ] Table names are validated; an injection attempt through the explorer's table parameter fails
      closed (test).
- [ ] No database URL or credential reaches the browser (test).
- [ ] Gates as usual; live smoke against a real generated app with seeded rows.
