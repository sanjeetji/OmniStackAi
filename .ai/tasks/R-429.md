# R-429: Generated web app passes strict `tsc --noEmit` — component-library type cleanup

## Status
DONE (2026-09-13). A generated `minimal-blog` AND `rideshare-favourites` now pass `tsc --noEmit` with
**zero** errors (was 84 on minimal-blog: 4 node_modules + 80 in our code). All fixes are at the generator
(`codegen/nextjs.py`) plus the generated tsconfig; the opt-in `task agent-engine:web-typecheck` gate now
asserts a clean exit and reports PASSED for both examples. `task verify` stays offline/deterministic.

## Objective
Make a generated Next.js app type-check cleanly under strict TypeScript. Running the R-428 opt-in gate on a
generated `minimal-blog` reports 84 errors: 4 from `node_modules/next` type declarations (a missing
`skipLibCheck`, which is Next.js's own default) and 80 in our generated code across 19 component files plus
`lib/hooks.ts`, in 8 distinct, mechanical patterns (below). Fix each pattern at the generator
(`codegen/nextjs.py`) so `tsc --noEmit` exits 0 on BOTH example IRs, extend the web-typecheck gate to treat a
clean exit as the pass condition, and add deterministic string-level regression assertions so each class
cannot regress. Only correct malformed/mis-typed emitted TypeScript — NO change to component structure,
runtime behavior, screen layout, styling values, or generated business logic; preserve diff-invariance.

## Error classes to fix (from the R-428 gate — real `tsc --noEmit` output)
- **G0 — tsconfig (4, `node_modules/next` TS2694/TS2305/TS2307):** generated `tsconfig.json` omits
  `skipLibCheck`. Add `"skipLibCheck": true` (Next.js's own default) so dependency `.d.ts` files are not
  type-checked.
- **G1 — duplicate exports (39, TS2323/TS2484) `context-menu.tsx`:** sub-components are declared
  `export const X = …` AND re-listed in a trailing `export { X, … }` block. Export each name once.
- **G2 — `displayName` on arrow-function sub-components (13, TS2339) `audio-player`, `geo-map`,
  `pdf-viewer`:** internal sub-components declared as `const X = (props: P) => …` have a bare function type
  that disallows `X.displayName = …`. Type them so `displayName` is permitted (e.g. `const X: React.FC<P>`).
- **G3 — compound props on a `forwardRef` result (9, TS2339) `color-picker`, `pin-input`:**
  `Comp.Area = …` etc. on a `ForwardRefExoticComponent` whose type lacks those members. Build a typed
  compound (typed intersection / `Object.assign`) so the attached sub-components are on the type.
- **G4 — interface incorrectly extends HTMLAttributes (5, TS2430) `banner`, `carousel`, `checkbox`,
  `code-block`:** a prop redefines an inherited DOM attribute with an incompatible type. `Omit` the
  conflicting key(s) from the extended attribute type.
- **G5 — `useRef<T | null>(null)` passed to `ref=` (10, TS2322) `dialog`, `dropdown-menu`, `hover-card`,
  `image-cropper`, `popover`, `scroll-area`:** for DOM/SVG element refs attached via `ref={…}`, declare
  `useRef<T>(null)` (returns `RefObject<T>`, assignable to `ref`). Do NOT touch value refs
  (`AbortController`/`number`/custom-handle) that need a mutable `T | null`.
- **G6 — `string` not assignable to a union prop (4, TS2322) `terminal.tsx`:** a widened `string` is passed
  where a `TerminalVariant` union is required. Preserve the literal-union type at the boundary.
- **G7 — missing field on a type (3, TS2353/TS2339) `diff-viewer.tsx`:** code sets/reads `isUnchanged` on a
  `SplitDiffRow` that does not declare it. Add the field to the type.
- **G8 — hook calls a non-existent client method (2, TS2339/TS2551) `lib/hooks.ts`:** generated hooks call
  `list<Entity>WithCount` / `list<Entity>By<Rel>WithCount` that the generated API client does not expose.
  Align the hook and client (emit the `…WithCount` client method, or call the existing method) with no
  behavior change.

## Gates & Evidence
Baseline (R-428 gate on a generated minimal-blog): **84** `tsc --noEmit` errors — 4 in `node_modules/next`
(missing `skipLibCheck`) + 80 in our code across 19 files (context-menu 39, color-picker 6, terminal 4,
geo-map 4, pin-input 3, pdf-viewer 3, diff-viewer 3, lib/hooks 2, banner/carousel/checkbox/code-block/
dialog/dropdown-menu/hover-card/image-cropper/popover/scroll-area/audio-player).

Fixes (all in `codegen/nextjs.py` unless noted):
- **G0** generated `tsconfig.json` now sets `"skipLibCheck": true` (Next.js's own default) → 4 dependency
  `.d.ts` errors gone.
- **G1** `context-menu.tsx` no longer double-exports (removed the redundant `export { ... }` re-list of
  names already `export const`; keeps `export { ContextMenu }` for the compound) → 39 gone.
- **G2** internal arrow/function sub-components' aliases (audio-player/geo-map/pdf-viewer, 9) typed
  `typeof XInner & { displayName?: string }` so `.displayName` is allowed (runtime unchanged).
- **G3** compound components (color-picker, pin-input) built as a typed compound: the `forwardRef` result
  is a `…Base` const cast to `type XComponent = typeof XBase & { … }`, so `.Sub = …` and consumer
  `<X.Sub/>` are on the type. Named + default exports preserved.
- **G4** `BannerProps`/`CarouselProps`/`CheckboxProps`/`CodeBlockProps`/`CodeBlockCopyButtonProps` now
  `Omit` the conflicting inherited DOM attribute (`title`/`onSelect`/`defaultChecked`/`onCopy`).
- **G5** DOM/SVG element ref annotations changed from `React.RefObject<T | null>` to `React.RefObject<T>`
  (assignable to a JSX `ref=`); mutable value refs (`MutableRefObject<T | null>` casts, `AbortController`/
  `number` refs) left untouched.
- **G6** `terminal.tsx` destructuring defaults `variant = "default"` → `"minimal"` (a valid
  `TerminalVariant`; there is no `=== "minimal"` branch so rendering is byte-identical), scoped to the
  terminal template only.
- **G7** added `isUnchanged?: boolean` to `SplitDiffRow`.
- **G8** the exported `api` object now includes the `…WithCount` LIST/LIST_BY methods (they were emitted as
  standalone functions but omitted from the object); generated LIST/LIST_BY hooks always forward a fresh
  `requestParams` object literal (implicit index signature → assignable to the client's flat `Record`
  param type) with `...options` spread first (the hook's params/abort signal are no longer overridable by
  a caller's `options`, matching the existing GET/CREATE hooks).
