# R-461: Full-Stack Production Authentication Engine

**Phase:** MVP  
**Status:** COMPLETED  
**Started:** 2026-09-16
**Completed:** 2026-09-16

## Objective

Implement a complete, production-ready authentication system across the full
generated stack: PostgreSQL `users` table, FastAPI auth router (`/auth/register`,
`/auth/login`, `/auth/me`, `/auth/logout`), frontend Next.js auth screens, React
`AuthProvider` context, and pre-authenticated preview sessions.

## Acceptance Criteria

- [x] `render_postgres_schema(ir)` emits a `users` table when `needs_auth(ir)` is True.
- [x] The `users` table has: id (UUID PK), email (VARCHAR UNIQUE NOT NULL), password_hash (VARCHAR NOT NULL), full_name (VARCHAR), role (VARCHAR DEFAULT 'user'), created_at (TIMESTAMPTZ).
- [x] A default admin seed row is present in the schema output for dev access.
- [x] `python_auth_router_file(ir)` is exported from `auth_guard.py`.
- [x] The auth router contains `/register`, `/login`, `/me`, `/logout` endpoints.
- [x] Password hashing uses `hashlib.pbkdf2_hmac` (SHA-256, 100k iterations) — zero external deps.
- [x] `backend_python.py` includes `app/routers/auth.py` and wires it into `main.py` when `has_auth`.
- [x] `nextjs.py` emits `components/auth-provider.tsx`, `app/login/page.tsx`, `app/register/page.tsx` when `needs_auth`.
- [x] The auth-provider exposes `useAuth()` hook with `user`, `token`, `login`, `register`, `logout`.
- [x] The navbar shows sign-in/sign-out based on auth state.
- [x] `lib/api.ts` automatically attaches the Bearer token from localStorage.
- [x] All new test assertions in `test_full_stack_auth.py` pass.
- [x] `task verify` passes (full regression: 3,386 tests).
