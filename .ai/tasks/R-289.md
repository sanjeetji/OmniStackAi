# R-289 — Debounced Live Subcollection Search

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic codegen)

## Objective

The top-level collection search is live + debounced (R-280), but the subcollection (master-detail) search
shipped submit-only (R-281) to avoid per-subcollection state. Now that R-286 made the
`useList<Child>By<Parent>` hook race-safe (superseded LIST_BY requests are aborted, stale completions
ignored), a live search-as-you-type is safe. R-289 brings the subcollection search to parity: each
subcollection gets a controlled search input backed by component state that commits to the hook's
`setSearch` after a fixed 300ms debounce; the form submit still commits immediately (Enter).

## Requirement

In `nextjs.py`, reusing the R-280 debounce pattern:

- Add `_subcol_search_names(s_var) -> (state, setter)` deriving `<s_var>Search` / `set<S_var>Search`.
- Add `_subcol_search_state(s_var)` emitting, at component level (next to each `const <s_var> =
  useList<Child>By<Parent>(selectedId)`): `const [<state>, <setter>] = useState("");` and a
  `setTimeout(..., 300)` + `clearTimeout` debounce `useEffect` that commits `<state>.trim()` to
  `<s_var>.setSearch`, guarded by `<state> !== (<s_var>.params.q ?? "")`.
- Make `_subcol_controls`'s search input controlled (`value={<state>}` + `onChange={<setter>}`), drop
  `name="q"`/`defaultValue`/FormData, and keep the form `onSubmit` committing `<s_var>.setSearch(<state>.trim())`.
- Call `_subcol_search_state(s_var)` at both subcollection hook-declaration sites (collection
  master-detail `_collection_screen_page` and detail `_detail_screen_page`); both screens already import
  `useState` + `useEffect`.

Do not change the hook, IR, backend, or API client. Preserve sort/filter/pagination and description-only
stability.

## Acceptance criteria

1. Each subcollection emits its search `useState` + a 300ms debounce `useEffect` calling `<s_var>.setSearch`.
2. The subcollection search input is controlled (`value`/`onChange`); the form `onSubmit` commits
   `<s_var>.setSearch(<state>.trim())`; no `defaultValue`/`new FormData` remains in the subcollection form.
3. Both render sites carry it; entities without a subcollection emit none.
4. Sort/filter/pagination unchanged; description-only IR changes byte-identical.
5. Focused tests + updated R-281 tests + full offline gates + both demos pass.
