## Objective

Sixth task of the approved 7-task Phase D roadmap (plan record:
`/Users/sanjeet_kumar/.claude/plans/hi-fancy-shannon.md`). Build real compile-error reporting for
the first time in this codebase — the founder's explicit choice over a placeholder, given its own
task (not folded into R-481) because it is genuinely new backend work, comparable in size to R-476.
Confirmed by exhaustive grep during the original planning research: `verify/compile.py` has a real
`CompileError`/`CompileReport`/`compile_web_project()`, but its only caller anywhere in the codebase
was a standalone CLI script — never the Studio's own `_build()`/`_edit()` path. A build made through
the Studio today produces no compile report, stored nowhere, retrievable by no build id.

## Design

- **On-demand, not automatic.** `node_modules`/`tsc` only exist in a generated repo after a
  live-preview install (confirmed live during this session's own R-478/R-479 smoke tests, which
  needed a real `pnpm install` before any Node toolchain existed) — a first compile check could be a
  real, minutes-long, network-dependent operation. Running it automatically on every build/edit
  would make the fast, network-light core loop slower and more toolchain-dependent than today.
  Instead: an explicit "Check for problems" trigger (`POST`), same opt-in shape as R-478's preview
  routes.
- **New `services/agent-engine/.../studio/problems.py`** (mirrors `files.py`'s shape exactly):
  `check_build_problems(root_dir, *, runner=None)` resolves `root_dir/apps/web` (the same
  `apps/web` convention `localrun/plan.py`'s `build_run_plan` already uses to detect a web target),
  raises `NoWebTargetError` if there's no `package.json` there, calls
  `verify/compile.py`'s real `compile_web_project()`, and remaps its `VerifyError` (raised when
  `node_modules/.bin/tsc` doesn't exist) into a clear, actionable `ToolchainNotInstalledError` —
  never silently installs dependencies as a side effect of a "check problems" click. `runner` passes
  straight through to `compile_web_project`, so this module's own tests need no real toolchain
  either, mirroring `verify/compile.py`'s own test style exactly.
  `StudioProblemsStore` is a bounded, thread-safe, in-memory `OrderedDict`-as-LRU map of build id →
  last `CompileReport.to_dict()`, mirroring `StudioSessionStore`'s own bounded-LRU idiom (so a
  repeated `GET` doesn't have to recompile).
- **New agent-engine routes** (`studio/server.py`, mirroring the existing `_build_id_for_suffix` +
  handler pattern used for `/files`/`/file`/`/turns`/`/edit`): `POST /api/build/{id}/problems`
  (triggers a fresh check via `problems_check_fn`, stores and returns the report) and
  `GET /api/build/{id}/problems` (returns the last stored report via `problems_get_fn`, or a real
  404 if none exists yet). Error mapping: `BuildNotFoundError` → 404 (both routes),
  `NoWebTargetError` → 400 (parallel to `EditNotSupportedError`'s exact semantics: "not applicable
  to this build"), `ToolchainNotInstalledError` → 409 (a real resource-state conflict, not a
  malformed request — a status code not otherwise used by this API surface, so a client can
  distinguish "install dependencies first" from every other failure mode), `ProblemsNotCheckedError`
  → 404 (GET only). Both routes wired in `live_serve.py`'s always-on `control_kwargs` (build-only
  mode included) — checking/reading problems needs the build's own installed `node_modules`/`tsc`
  (from a *prior* live-preview install), but not a *currently running* preview, the same reasoning
  `edit_fn`/`turns_fn` already established for build-only availability.
- **Control-plane (Go)**: new routes `POST /jobs/build/{id}/problems` (write-deadline extended via
  a new `defaultProblemsTimeout`, 90s — a real local `tsc` compile can take real time on a larger
  app, well above ordinary observed single-app compile times, well below `verify/compile.py`'s own
  much larger internal default of 600s meant for pathological cases this route doesn't need to wait
  out) and `GET /jobs/build/{id}/problems` (plain `proxyGet`) — same generic-proxy shape as every
  other Job API route, **no credit debit** (a local `tsc` run is not a model call).

## Acceptance Criteria

- [x] `POST /jobs/build/{id}/problems` and `GET /jobs/build/{id}/problems` require authentication
      (401 with no session) and otherwise proxy the agent-engine's response verbatim.
- [x] A real `tsc` run through a real installed toolchain returns a real, non-empty (or genuinely
      clean) `CompileReport`.
- [x] A build with no installed toolchain returns a clear, actionable error (409), not a crash or a
      long silent hang (no accidental `pnpm install` side effect).
- [x] A repeated `GET` after one `POST` returns the same stored report without recompiling.
- [x] No credit debit occurs on either route.
- [x] agent-engine `task verify` and control-plane `go build`/`vet`/`test` both clean; repo
      `task verify`/`lint`/`security:quick`/`env:check` all pass.
