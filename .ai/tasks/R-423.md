# R-423: Studio build history + re-preview a recent build

## Status
DONE

## Objective
Give the local Studio a bounded, in-session memory of recent builds and let the operator re-open/re-preview
any of them. Add a dependency-free, thread-safe `StudioBuildHistory` (Python stdlib only) that records each
successful build as a bounded, secret-free entry (id, prompt (truncated), app name, entities, file_count,
target_dir, commit_sha, created_at) capped at a fixed number of most-recent entries. Expose it over the
existing stdlib Studio server: `GET /api/history` returns the recent builds newest-first, and (trusted-local
preview mode only) `POST /api/history/preview` with `{id}` re-previews that build's already-materialized repo
through the R-422 `StudioPreviewManager` (returning the same bounded preview payload). Wire history recording
into the live build path in both build-only and preview modes; wire the re-preview route only in trusted-local
preview mode (build-only returns 404). Add a "Recent builds" list to the Studio page that loads on start,
refreshes after each build, and re-previews on click, rendered with `textContent` only (no HTML injection).
Preserve collision-free preview ports, status/stop/restart controls, trusted-local `studio:preview`, build-only
`studio:serve`, single-session cleanup, PostgreSQL, and offline deterministic verification.

## Requirements
- Add a bounded, thread-safe `StudioBuildHistory` (fixed max recent entries; oldest evicted) recording only a
  bounded, secret-free view of each successful build; injected clock for deterministic tests.
- Expose `GET /api/history` (recent builds, newest-first) over the stdlib Studio server via an injected handler;
  unset handler returns 404.
- Expose `POST /api/history/preview` with `{id}` to re-preview a recorded build's repo via the R-422 manager;
  wired only in trusted-local preview mode; unset handler 404; unknown/missing id returns a bounded error.
- Record every successful build into the history from the live build path (both Studio modes).
- Add a Studio-page "Recent builds" surface that lists history, refreshes after a build, and re-previews on
  click without HTML injection.
- Keep R-421/R-422 studio, preview, server, and local-run contracts compatible and single-session cleanup intact.
- All verification deterministic/offline via injected fakes; `task verify` runs no generated code, Docker,
  PostgreSQL, package install, model, or external network.

## Acceptance Criteria
- `StudioBuildHistory.record` returns an id, `list` is newest-first and bounded, `get` finds by id, and the
  public view is JSON-safe and secret-free with a bounded prompt.
- `GET /api/history` returns `{builds: [...]}` when wired and 404 when not; `POST /api/history/preview` with a
  known id returns a preview payload (via the manager) and 404 when the route is not enabled; a missing/unknown
  id returns a bounded error without a crash.
- A successful build is recorded and appears in `GET /api/history`.
- The Studio page exposes a recent-builds list wired to `/api/history` and re-preview to `/api/history/preview`.
- Existing studio/preview/server/local-run contracts remain compatible; focused + full verify + lint + security
  + env + both builder demos pass; 0 model calls in verify.
