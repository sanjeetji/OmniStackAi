# R-235 — Verifiable-engineering verify plans

## Requirement

Add the platform's "verifiable engineering" backbone (Brief §26/§27/§77): a deterministic **verify
plan** per generation target — the ordered ladder of gate commands (install → typecheck → lint → test
→ build) the generated code for that target is engineered to pass. A verify plan is pure, validated
data (commands classified by gate kind), mirroring the runtime preview/deploy plan pattern. Map an
Application IR to the verify plans for its assembled monorepo apps (`apps/web`, `services/api`), and
add an opt-in `run_verify` executor that runs a plan fail-fast and returns a structured report.
Deterministic and offline; nothing is installed/built/run by `task verify`. Committed directly to
`main`. New IDs continue after the workbook backlog's R-010..R-219 (this is R-235).

## Acceptance criteria

- `verify_plan(target, app_dir)` → a `VerifyPlan` for each supported target (`nextjs-web`,
  `nextjs-admin`, `backend-python`, `backend-go`); unknown target → `UnsupportedVerifyTargetError`.
- A `VerifyPlan` is validated, ordered, and classifies each step by gate kind
  (install/typecheck/lint/test/build); `plan.gates()` reports the kinds present; commands are
  control-free and secret-free.
- `verify_plans_for_ir(ir)` → the verify plans for the IR's assembled apps, each bound to its monorepo
  directory, consistent with the assembler (`assembled_targets`).
- `run_verify(plan)` executes a plan fail-fast → a `VerifyReport` (per-step status + return code);
  opt-in, never run by tests or `task verify`.
- `task agent-engine:verify-plan` prints a target's plan; `task verify` stays green.
- Offline tests cover per-target plans, gate classification, unknown-target error, IR→plans mapping,
  and plan validity / no secrets.

## Design notes

- New `omnistackai_agent_engine.verify` package: `plans.py` (`VerifyStepKind`, `VerifyStep`,
  `VerifyPlan`, reusing the vetted `Command` from `runtime.contracts`); `gates.py` (per-target recipe
  table, `verify_plan`, `verify_plans_for_ir`, `run_verify`, `VerifyReport`); `errors.py`.
- `codegen/assembler.py` gains an additive, behavior-preserving `assembled_targets(ir, registry=None)`
  that returns the `AssembledApp` list; `assemble_project` is refactored to call it (output identical).
- Standard-library only; no vendor SDK; keys/secrets never referenced. Nothing run by the planning code.

## Model and cost trace

Deterministic; no model call, no install/build/run. No cloud key set; cloud_calls zero.
