# R-256 — Wire PUT handlers (full-replace update) with validation in Go and FastAPI backends

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L2  

## Objective

Wire `PUT /entities/{id}` endpoints to full-replace update handlers in both Go and FastAPI backends:
- In `route_wiring.py`, extend `wire_endpoint` to map `PUT` endpoints (with single trailing id param and matching `request_schema`) to `Op.UPDATE`.
- In Go handlers, wire the `PUT` handler to decode body, enforce `validateStruct` (if entity has rules), call `store.Update<Entity>`, returning 404 on not-found or 200 on success.
- In FastAPI routers, wire `@router.put` with payload validation, calling `update_<table>` and returning 404 on not-found or 200 on success.
- Negative wiring: PUT without path param, with multiple params, or with mismatched schema stays 501 scaffold.
- Rule-free entities: no `validateStruct` guard in Go PUT handler.
- Example IRs unchanged.

## Acceptance criteria

1. `PUT /entities/{id}` with matching `request_schema` wires to `Op.UPDATE` (not 501).
2. Go handler for PUT:
   - Decodes body into `models.<Entity>`.
   - If entity has validation rules, guards with `if !validateStruct(w, m) { return }`.
   - Calls `store.Update<Entity>(r.Context(), h.DB, id, m)`.
   - Returns 404 if nil, 200 + `writeJSON` on success.
3. FastAPI router for PUT:
   - Emits `@router.put`.
   - Calls `await <repo>.update_<entity>(<id>, payload.model_dump())`.
   - Raises 404 if row is None, returns row on success.
4. Negative wiring: PUT without param, mismatched entity, etc. stays 501 scaffold.
5. Rule-free entity emits no `validateStruct` call in Go PUT handler.
6. Example IRs (`minimal-blog`, `rideshare-favourites`) unchanged.
7. `task verify` green; ≥420 tests; 0 network calls; no DB.
