# R-225 — Application IR v1 (framework-neutral intermediate representation)

## Requirement

Build the first real product primitive: the **Application IR** (Brief §9) — the framework-neutral
source of truth between user intent and generated targets. Every codegen framework adapter (Next.js,
Go/Python, Flutter, RN, native) will consume it. This task is the **data model only** (no codegen,
no agents), fully doable offline. New IDs continue after the workbook backlog's R-010..R-219 (this is
R-225).

## Acceptance criteria

- Models: application (name, description, platforms), `project_strategy`, `roles`, `entities`
  (fields + relations), `apis`, `screens`, and `acceptance_criteria` — immutable, validated records.
- Validation: non-empty bounded identifiers; unique entity/field/role/screen ids; valid enums;
  well-formed API method + path; cross-references (a relation targets an existing entity; a screen's
  role references an existing role). Violations raise stable typed errors.
- Versioning: the IR carries a schema version; `to_dict()`/`from_dict()` round-trip losslessly and
  `from_dict` rejects an unknown/newer version with a stable error (migration hook).
- Standard-library only; framework-neutral; no network/infra.
- Offline tests cover valid construction, each validation rule, cross-reference errors, round-trip
  serialization, and version rejection. `task verify` stays green.

## Design notes

- New package `omnistackai_agent_engine.application_ir`: `ir.py` (enums + frozen dataclasses +
  `ApplicationIR` with cross-validation + `to_dict`/`from_dict` + `IR_SCHEMA_VERSION`), `errors.py`
  (`ApplicationIRError`, `InvalidIRError`, `UnsupportedIRVersionError`).
- Mirrors the Brief §9 minimum model; extensible for flows/integrations/build_matrix in later tasks.
