# R-424: Live preview status — liveness-aware status + Studio polling

## Status
DONE

## Objective
Make the Studio's view of a running preview stay accurate over time. Add `LocalAppSession.is_alive()` (true
only when the session is not stopped and every owned background process is still running). Make
`StudioPreviewManager.status()` liveness-aware: when the active preview's processes have exited on their own,
it stops/forgets the dead session and reports a bounded, secret-free "stopped" state instead of a stale
"ready". Have the Studio page **poll** the existing `GET /api/preview` route while a preview is running and
re-render the preview surface when the state changes — without reloading the already-embedded iframe when the
preview URL is unchanged (no flicker). Reuse the R-422 `GET /api/preview` route and the R-421/R-422 manager;
no new routes, server, or live-serve wiring. Preserve collision-free preview ports, status/stop/restart and
history controls, trusted-local `studio:preview`, build-only `studio:serve`, single-session cleanup,
PostgreSQL, and offline deterministic verification.

## Requirements
- Add `LocalAppSession.is_alive()`: false when stopped or when it owns no process; true only when every owned
  background process is still running (`poll()` is None).
- Make `StudioPreviewManager.status()` refresh liveness under its lock: if the active session is no longer
  alive, stop/forget it and set a bounded, secret-free "stopped" state; otherwise return the current state.
- The Studio page polls `GET /api/preview` on an interval while a preview is `ready`, re-rendering on change;
  polling stops when the state is not `ready`, and the embedded iframe is not reloaded when the URL is unchanged.
- Do not add new routes, change the server signature, or change `live_serve` wiring.
- Keep all verification deterministic/offline via injected fakes; `task verify` runs no generated code,
  Docker, PostgreSQL, package install, model, or external network.

## Acceptance Criteria
- `is_alive()` is false when stopped, false with no processes, false when any process has exited, and true
  when all processes are running.
- `status()` returns the live "ready" state while the session is alive; once the session's processes exit,
  `status()` returns a bounded "stopped" state and the dead session is stopped exactly once.
- Existing status/stop/restart/replace behavior is unchanged when the session stays alive.
- The Studio page polls `GET /api/preview` while a preview is running and re-renders on state change without
  reloading an unchanged iframe.
- Existing studio/preview/server/history/local-run contracts remain compatible; focused + full verify + lint
  + security + env + both builder demos pass; 0 model calls in verify.
