# R-253 — Wire PATCH/update handlers with validation in Go and FastAPI backends

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L3  

## Objective

Close the missing PATCH/update CRUD verb. Every `PATCH /entities/{id}` whose `request_schema`
names a known repo entity is currently emitted as a `501 scaffold`. R-253 wires a real,
validated update handler in both backends.

## Acceptance criteria

1. `PATCH /entities/{id}` + matching `request_schema` → `Op.UPDATE` (not 501).
2. Go store: `Update<Entity>(ctx, db, id, m)` — `UPDATE … SET … WHERE id=$N RETURNING …`; nil on
   not-found.
3. Go handler: decode → `validateStruct` (if rules) → `store.Update` → 404/200; ordering
   assertable by string position.
4. FastAPI repo: `update_<table>(id, data)` — parameterized `UPDATE … RETURNING *`; `None` when
   not-found.
5. FastAPI router: `@router.patch` → `update_<table>` → 404 on None.
6. Negative wiring: PATCH without param, no entity, non-PATCH same shape → 501.
7. Rule-bearing entity: `validateStruct` before `store.Update`.
8. Rule-free entity: no `validateStruct` in update handler.
9. Example IRs: unchanged (no PATCH endpoints in either).
10. `task verify` green; ≥360 tests; 0 network calls.
