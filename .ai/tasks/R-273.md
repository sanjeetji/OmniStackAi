# R-273 — Global Responsive Navigation Shell & Header Navbar in Generated Next.js Web App

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L2  

## Objective

Deliver a global, responsive navigation shell and header navbar for generated Next.js web applications (`apps/web`):
1. Emit `components/navbar.tsx` as a client component (`"use client"`) using Next.js `usePathname` for route detection.
2. Render application branding (`ir.name`) with an avatar logo badge linking to the home overview page (`/`).
3. Render navigation links for all collection and form screens in `ir.screens`, indicating the active route via dynamic path comparison.
4. Render role badges for screens with non-default roles (e.g. `admin`, `moderator`).
5. Render a prominent `+ New {Entity}` / `+ Create` quick-action CTA button on the right side of the navbar when a create form screen exists in the IR.
6. Integrate `<Navbar />` into `app/layout.tsx` above `{children}`, wrapping all pages in a cohesive layout with typography and background tokens.
7. Maintain strict diff invariance across `ir.description` changes; 100% offline, zero npm dependencies.

## Acceptance criteria

1. NextjsWebAdapter generates `components/navbar.tsx` in `apps/web`.
2. `app/layout.tsx` imports and renders `<Navbar />` above `{children}`.
3. `components/navbar.tsx` has `"use client";` at the top and imports `usePathname` from `"next/navigation"`.
4. Header renders brand name (`ir.name`) and logo badge linking to `/`.
5. Header renders "Overview" navigation link pointing to `/`.
6. Header renders navigation links for all collection and form screens with correct `href` (`/{screen.id}`).
7. Detail screens (`ScreenType.DETAIL`) are excluded from horizontal top nav to keep navigation focused.
8. Active navigation link is visually distinguished based on `pathname`.
9. Non-default screen roles render a badge adjacent to the screen link.
10. Renders a `+ {Entity}` or `+ Create` button linking to the first create form screen when available.
11. Clean fallback when `ir.screens` is empty.
12. Strict diff invariance across `ir.description` modifications.
13. Stage 0 verification (`task verify`), `task lint`, `task security:quick`, `task doctor`, and builder demos pass.
