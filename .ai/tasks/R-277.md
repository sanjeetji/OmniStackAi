# R-277 — Form Screen Dirty State Tracking, Unsaved Changes Guard & Reset Confirmation in Generated Next.js Forms

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Enhance generated Next.js form screens (`apps/web/app/<screen>/page.tsx`) with deterministic dirty
state tracking (`isDirty`), an amber "Unsaved changes" visual indicator badge, confirmation-guarded
Cancel and Reset actions, and a native browser `beforeunload` event listener protecting against
accidental data loss:

1. Import `useMemo` from `"react"`.
2. Compute `baselineData` comparing against `initialValues` in create mode or `initialData` in edit mode.
3. Calculate `isDirty` indicating whether any editable field in `formData` differs from `baselineData`.
4. Render an amber "Unsaved changes" visual badge (`#fef3c7` / `#92400e`) when `isDirty && !success`.
5. Cancel button guards against leaving with unsaved changes via `confirm()` dialog when `isDirty`.
6. Reset button guards against resetting modified fields via `confirm()` dialog when `isDirty`.
7. Register a native window `beforeunload` event listener while `isDirty && !submitting && !success`.
8. Post-submit success clears dirty state warnings so navigation links execute without prompts.
9. 100% offline, zero new external npm dependencies, zero new IR fields, strict diff invariance.

## Acceptance criteria

1. Form screen imports `useMemo` from `"react"`.
2. `isDirty` is computed by comparing `formData` with `baselineData`.
3. "Unsaved changes" badge is rendered when `isDirty && !success`.
4. Cancel button binds confirmation guard when `isDirty` is true.
5. Reset button binds confirmation guard when `isDirty` is true.
6. `beforeunload` event listener is registered and cleaned up via `useEffect`.
7. Strict diff invariance: changing only `ir.description` produces byte-identical output.
8. Stage 0 verification (`task verify`), `task lint`, `task security:quick`, and builder demos pass.
