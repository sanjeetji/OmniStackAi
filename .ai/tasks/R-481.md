## Design

- **New `app/studio/studio-tabs.tsx`**: owns `activeTab` (`"preview"|"files"|"code"|"problems"`)
  and a lifted `selectedFile` state. Renders `<StudioPreview>` unchanged inside the Preview tab
  (moved out of its previous always-visible placement in `studio-chat.tsx`).
- **Files and Code stay separate** (founder's explicit choice, honored exactly): **Files** is a
  lightweight clickable list (`FilesTab`) — clicking a file sets `selectedFile` *and* switches to
  the Code tab, so Files stays fast/simple while still leading somewhere real. **Code** (`CodeTab`)
  is the full syntax-highlighted reader, with its **own** `<select>` file switcher so a technical
  user can jump straight to a file without detouring through Files first — both tabs read/write the
  one lifted `selectedFile`.
- **New `app/studio/code-highlight.ts`**: a hand-rolled, dependency-free tokenizer porting the
  *approach* (not the exact generated code) of `codegen/nextjs.py`'s own generated
  `tokenizeCodeLine`/`normalizeLang` — the same regex-driven, single-pass-per-line algorithm
  (comments → strings → numbers → identifiers → whitespace → operators/punctuation → fallback
  char), scoped down to what a generated app actually contains: TypeScript/TSX/JavaScript (full
  keyword/type highlighting), JSON/CSS (generic string/number/punctuation splitting, no
  language-specific keywords), Markdown and unknown extensions (plain text). Matches the R-475
  icon-decision precedent: a small, fixed highlighting surface doesn't clear the bar for a new
  dependency.
- **Problems tab** (`ProblemsTab`): an explicit "Check for problems" button (on-demand, per R-480's
  own design — never automatic), a loading state while the real `tsc` run happens, then either a
  clean "No problems found" state or a real list of errors grouped by file (reusing the rendered
  diagnostic strings `CompileReport.to_dict()` already produces, no client-side re-formatting). The
  last stored report is hydrated on mount via a `GET`, so re-opening the tab doesn't lose prior
  results. R-480's `ToolchainNotInstalledError`/`NoWebTargetError` messages surface verbatim in the
  error banner — the real, specific, actionable text, not a generic failure.
- **`studio-workspace.tsx`** loses its inline `FileBrowser` (moved into the Files/Code tabs) —
  keeps just the name/description/stats/entities/usage header, now sitting above the tab bar.
- New `lib/control-plane.ts` additions: `ProblemsReport` type, `checkBuildProblems()`,
  `getBuildProblems()`. New proxy route `app/api/jobs/build/[id]/problems/route.ts` (GET+POST in
  one file, mirroring the existing single-file multi-method route pattern).
- Wired into `studio-chat.tsx`: `<StudioTabs buildId previewVersion workspace />` replaces the
  previous direct `<StudioPreview>` placement, inside the same `.studio-workspace-column`.
