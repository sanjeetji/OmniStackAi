# R-261 — Full-Text / Keyword Search Filtering on LIST Endpoints

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L2  

## Objective

Implement keyword and full-text search filtering across the entire platform on `Op.LIST` and `Op.LIST_BY` endpoints (`q` query parameter):

1. **Go Backend (`codegen/data_access.py` & `codegen/backend_go.py`)**:
   - Helper `parseSearch(r *http.Request) string` extracts and trims `q := strings.TrimSpace(r.URL.Query().Get("q"))`.
   - `store.List<Entity>(..., q string)` and `store.Count<Entity>(..., q string)` apply parameterized `ILIKE` queries (`WHERE (field1 ILIKE $1 OR field2 ILIKE $1 ...)`) with wildcard pattern `"%" + q + "%"`.
   - Subcollections `store.List<Entity>By<Rel>(..., q string)` and `store.Count<Entity>By<Rel>(..., q string)` scope queries to `<rel>_id = $1 AND (field1 ILIKE $2 OR ...)`.
   - Whitelist protection: only fields of type `FieldType.STRING` and `FieldType.TEXT` are queried. If an entity has no string/text fields, the search clause is safely omitted.
2. **Python FastAPI Backend (`codegen/data_access.py` & `codegen/backend_python.py`)**:
   - Route functions accept `q: str | None = None` query parameter.
   - `count_<table>(q=q)` and `list_<table>(limit, offset, sort, order, q=q)` apply parameterized `WHERE (field1 ILIKE %s OR ...)` using `f"%{q}%"`.
   - Subcollections `count_<table>_by_<rel>(..., q=q)` and `list_<table>_by_<rel>(..., q=q)` scope queries by relation and search pattern.
3. **Next.js Typed Client (`codegen/nextjs.py`)**:
   - `lib/api.ts` adds `q?: string` to `params` in `list<Entities>`, `list<Entities>WithCount`, `list<Entities>By<Rel>`, and `list<Entities>By<Rel>WithCount`.
4. **OpenAPI 3.1 Specification (`codegen/openapi.py`)**:
   - Declares `q` query parameter on all `Op.LIST` and `Op.LIST_BY` operations.
5. **Offline & Pure**:
   - 0 platform dependencies, 0 network, 0 cloud model calls, 0 DB connection.
