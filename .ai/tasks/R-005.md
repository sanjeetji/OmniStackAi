# R-005 — ModelProvider contract and registry

## Requirement

Create the Python agent-engine's vendor-neutral model-provider boundary before implementing any
provider adapter. This is the explicit next dependency in Brief Sections 18.3, 75, 83, 84, and 91.

The supplied tracker omits R-005 through R-009. This task is reconstructed from the brief with the
founder's standing instruction to continue one Tracker ID at a time.

## Acceptance criteria

- Immutable typed records validate provider/model identifiers, capabilities, requests, responses,
  token usage, provider health, model discovery, and stream events.
- A runtime-checkable async `ModelProvider` protocol exposes identity, health, discovery,
  generation, and streaming without importing a provider SDK.
- A deterministic registry lists providers by ID and rejects invalid, duplicate, and unknown providers.
- Standard-library tests cover record validation, protocol substitutability, deterministic order,
  duplicate registration, and unknown lookups.
- Repository and CI commands compile and test the contract without network access.
- No adapter, routing/fallback, external Python dependency, deployable service, database change,
  infrastructure, product logic, or native work is added.

## Expected blast radius

documentation, portable task state, changelog/handoff, and tracker evidence may change.
