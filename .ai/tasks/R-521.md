# R-521: Generated apps run again: web compiles, previews seed, sign-up and login work (core-loop hotfix)

**Phase:** MVP (core loop protection, found during R-520)
**Status:** COMPLETED
**Started:** 2026-09-21
**Completed:** 2026-09-21

## Objective

Every prompt-built app's home page returned 500 and its sign-up could never succeed. The R-513…R-517
commit (`1fe1015`) left four defects in `codegen/nextjs.py`, found by running the generated app's
own `tsc` on a live project:

| # | Generated file | Defect | Effect |
|---|----------------|--------|--------|
| 1 | `components/toast.tsx` | `Object.assign(toastFn, {` closed with `};` (TS1005) | Syntax error: every page that imports the toast provider (the root layout) fails to compile, so the home page returns 500 |
| 2 | `components/toast.tsx` | the `useToast` fallback `toast` is a plain object, not a callable `ToastFn` (TS2322) | Type error (`next build` fails) |
| 3 | `app/register/page.tsx` | Python's `{ir.roles && (` leaked into the TSX (TS2304) | `ReferenceError: ir is not defined` when the sign-up page renders |
| 4 | `app/register/page.tsx` | `register(fullName, email, password, role)`, but `register` takes one `RegisterData` object (TS2554) | Sign-up posts a bare string, so registration always fails |

### Found while verifying the fix live (the new smoke preview check caught the first one)

| # | Where | Defect | Effect |
|---|-------|--------|--------|
| 5 | `codegen/seed_sql.py` | model fixtures put labels like `"user123"` in `uuid` columns | `invalid input syntax for type uuid`: the seed migration aborts, so **the preview never starts** (depends on what the model writes) |
| 6 | `codegen/auth_guard.py` (Python API) | the auth router imports `get_db_pool` (does not exist) and is written for asyncpg while the app uses psycopg | `/auth/register` and `/auth/login` return 500: **nobody can sign up or log in** |
| 7 | same | `/auth/register` stores the role sent by the client | once #6 is fixed, **anyone could register as admin** |
| 8 | same | `/auth/reset-password` sets a new password from an email address alone | once #6 is fixed, **anyone could take over any account** |
| 10 | console `/preview` proxy | request bodies were streamed; Node's fetch turns a 401 reply to a streamed body into a network error | every failed login through the preview showed 502 instead of 401 |
| 9 | `codegen/nextjs.py` | a duplicate, shadowed `_forgot_password_page` holding a stale copy of the broken register page | dead code (no output effect), a trap for future edits |

## Fix

- 1 and 2: close with `});`. The fallback uses `Object.assign(() => {}, {success, error, info})`.
- 3 and 4: `register({ full_name: fullName, email, password })`. The form offers no role choice
  (see 7).
- 5: a non-UUID label in a `uuid` column is rendered as `uuid5(label)`. The same label always gives
  the same UUID, so linked rows stay linked. Real UUIDs and other columns stay exactly as authored.
- 6: register and login use the app's own `app.db.connect()` (psycopg, `%s` placeholders).
- 7: self-registration always gets `DEFAULT_ROLE = "user"`. The request's role is ignored and
  admins assign other roles.
- 8: `/auth/reset-password` answers 501 `password_reset_not_configured` until signed, emailed reset
  links exist. The forgot-password page shows that error.
- 9: the shadowed definition is removed. Generated output is byte-identical (sha256 over all 343
  files of both example IRs, before and after).
- 10: the proxy buffers request bodies (both the single-app and multi-app paths).
- Regression tests: `test_generated_web_app_integrity.py` (toast balance, `.ts` balance, no Python
  leaks, register call shape, no role picker, auth router uses psycopg, no client role, reset
  refused), `test_seed_sql.py` (uuid labels), `test_toast_notifications.py` unchanged and passing.
- `scripts/smoke-core.sh` gains a **preview check**: start the preview, then `GET /preview/<id>`
  must return 200 (`SMOKE_SKIP_PREVIEW=1` skips it).
