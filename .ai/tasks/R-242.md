# R-242 — Real JWT verification in the generated auth guard

## Requirement

Upgrade the R-241 guard from a bearer-presence check to real token verification (Brief §9/§27/§55/§64):
the generated guard decodes and verifies a **JWT (HS256)** using a `JWT_SECRET` read from the
environment — `401` on a missing/invalid/expired token, `500` when the secret is unset (never a
fabricated default). The generated projects gain the JWT dependency and a `JWT_SECRET` placeholder in
`.env.example` (empty). The IR roles stay surfaced; per-endpoint role **enforcement** needs an IR field
and is a follow-up. Emitted only when the IR has an `auth=true` endpoint. Deterministic and offline —
no token is signed/verified at generation time. Committed directly to `main` (this is R-242).

## Acceptance criteria

- Python guard imports PyJWT, reads `JWT_SECRET` from env, verifies with HS256, `401`s on
  missing/invalid, `500`s when the secret is unset; `requirements.txt` gains `PyJWT`, `.env.example`
  gains an empty `JWT_SECRET`. `app/auth.py` parses as valid Python.
- Go guard imports `github.com/golang-jwt/jwt/v5`, reads `JWT_SECRET`, parses+verifies (HMAC only),
  `401`s on invalid; `go.mod` gains the golang-jwt `require`, `.env.example` gains `JWT_SECRET`.
- No fabricated secret anywhere — the secret only comes from the env. The IR roles constant is retained.
  Emitted only when the IR has an `auth=true` endpoint; byte-stable; nothing runs.
- Offline tests cover the JWT verification code + dependency/env additions, the no-fabricated-secret
  property, and that all-public IRs still emit no auth artifacts.

## Design notes

- `codegen/auth_guard.py`: `python_auth_file` now imports `jwt`/`os`, verifies with `jwt.decode(...,
  algorithms=["HS256"])`, returns claims; `go_auth_file` imports golang-jwt, `jwt.Parse` with an HMAC
  keyfunc. Add `PYJWT_REQUIREMENT` and `GOLANG_JWT_REQUIRE` constants.
- `backend_python.py`: add `PyJWT` to requirements and `JWT_SECRET=` to `.env.example` when `needs_auth`.
- `backend_go.py`: append the golang-jwt `require` to `go.mod` and `JWT_SECRET=` to `.env.example` when
  `needs_auth`.
- Platform code stays standard-library only; the JWT dependency lives in the GENERATED project.

## Model and cost trace

Deterministic; no model call, no network, no token signed/verified at generation time. cloud_calls zero.
