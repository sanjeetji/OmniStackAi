## Design (each point verified against real, current documentation before writing any code)

- **Tailwind CSS v4** via `@tailwindcss/postcss`, following Next 16's own bundled guide
  (`node_modules/next/dist/docs/01-app/01-getting-started/11-css.md`, read directly because the
  console's `AGENTS.md` warns Next 16 differs from training data): `pnpm add -D tailwindcss
  @tailwindcss/postcss`, a `postcss.config.mjs` with the plugin, `@import 'tailwindcss'` at the top
  of `app/globals.css`. Next's own recommendation: Tailwind for most styling, CSS Modules only where
  utilities fall short.
- **shadcn/ui** initialized for Tailwind v4 + React 19 (confirmed supported; the 2026 default SaaS
  stack). Base primitives vendored in `components/ui/`: `button`, `input`, `label`, `card`,
  `badge`, `tabs`, `dialog`, `dropdown-menu`, `tooltip`, `skeleton`, `separator`, `scroll-area`,
  `sonner` (toasts). Chosen for accessibility primitives (focus traps, keyboard nav, ARIA) that a
  real platform needs and that hand-rolled code gets wrong — not only for looks.
- **Geist + Geist Mono** via `next/font/google`, exactly as Next 16's font guide demonstrates
  (`13-fonts.md`): self-hosted, zero layout shift, no external request at runtime. Exposed as CSS
  variables (`--font-sans`, `--font-mono`) so Tailwind's `font-sans`/`font-mono` map to them.
- **Dark-first token system** in `globals.css` using Tailwind v4's `@theme inline` + shadcn's
  CSS-variable convention, applying the loaded `redesign-existing-projects` audit: OKLCH neutral
  scale tinted to a single cool hue (no mixed warm/cool grays), **one** desaturated accent (no
  purple/blue "AI gradient"), tinted shadows, a subtle grain overlay utility, a real type scale
  with tight display tracking, `tabular-nums` for data, visible focus rings. Existing `--bg`/
  `--panel`/`--accent`… variables are kept and *re-pointed* at the new scale so every old class
  in the 858-line sheet keeps rendering — no page breaks during the transition.
- **`next-themes`** with a class strategy, `defaultTheme="dark"`, `enableSystem`; a
  `ThemeProvider` client component wraps the root layout. The toggle UI itself lands in R-495
  (Settings), per the audit's "not a sun/moon switch" guidance.
- **Lucide** (`lucide-react`) installed now; `studio-icons.tsx` is replaced in R-493, not here.
- **Root layout**: font classes on `<html>`, `suppressHydrationWarning` (required by
  `next-themes`), `ThemeProvider`, `Toaster`, improved `metadata` (title template, description),
  and a branded `app/icon.svg` (the audit's "missing favicon" item).
- **Nothing else changes visibly.** Every route (`/`, `/login`, `/register`, `/studio`,
  `/settings`, `/fabric`, plus every `/api/*` handler) must build and respond exactly as before.

## Gates & Evidence

**Real tooling drift found and worked through, not glossed over.** The installed shadcn CLI is
**v4.21.0**, materially newer than any version I knew: `--base-color` no longer exists (it's now
`--base <base|radix|aria>` choosing the *component library*, with styling from named presets), the
default preset `base-nova` is built on **Base UI** rather than Radix, and preset names are bare
(`nova`, `vega`, …), not `radix-nova`. Three non-interactive attempts failed before the right
invocation (`--template next --base radix --preset nova --yes --css-variables --no-monorepo
</dev/null`) — one of them because `timeout` doesn't exist on macOS, which silently meant that
attempt never ran at all. The **Nova preset is literally "Lucide / Geist"** — the exact icon+font
decision this task had already made independently. Radix was chosen deliberately over the new
Base UI default: it's the primitive set I can write correct code against.

**A real bug introduced by `shadcn init`, caught and fixed in the token rewrite.** Init merged its
semantic variables into the existing `:root` and **clobbered two legacy names it shares**:
`--muted` (legacy meaning: muted *text*, used 17×; shadcn meaning: a near-white *surface*) and
`--accent` (legacy: the brand/button color, used 14×; shadcn: a subtle hover surface). Left as-is,
light mode would have shown near-invisible muted text and white-on-white primary buttons. The
rewrite re-points every legacy usage (`var(--muted)` → `var(--muted-foreground)`; legacy brand
uses → a new `--brand` token; primary actions → shadcn's `--primary`) and converts the legacy
`prefers-color-scheme` dark block and the syntax-highlight colors to the `.dark` class strategy,
so `next-themes` stays authoritative. `/fabric` had one inline `var(--accent)` that would have
regressed — fixed as a one-token change (`allowed_paths` extended mid-task, recorded above).
