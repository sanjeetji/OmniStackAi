# R-249 — IR indexes + unique constraints in the generated schema

## Requirement

Deepen the persistence layer (Brief §9/§34/§42): let the Application IR express column uniqueness and
entity indexes, and render them in the generated PostgreSQL schema. Add `Field.unique` and an `Index`
record on `Entity`. Additive IR fields (empty/false defaults, no schema-version bump). Pure,
deterministic, offline — schema text only; nothing connects to or runs a database. Committed directly
to `main` (R-249).

## Acceptance criteria

- `Field.unique: bool = False` (validated, serialized). `Entity.indexes: tuple[Index, ...] = ()` where
  `Index(fields: tuple[str,...], unique: bool = False, name: str | None = None)`; each index field must
  be a declared field of the entity (construction `InvalidIRError` otherwise). Both round-trip via
  `to_dict`/`from_dict`; `normalize_ir` preserves them.
- `render_postgres_schema` emits `UNIQUE` on unique non-`id` columns (never on the PK) and one
  `CREATE [UNIQUE] INDEX <name> ON <table> (<cols>);` per entity index — deterministic default name
  (`<table>_<cols>_idx`, `_key` for unique) when unnamed; deterministically ordered; byte-stable.
- No index/unique output when none declared; nothing connects to or runs a database.
- Offline tests cover the unique column, single + composite indexes (named/unnamed, unique/non-unique),
  the id-never-unique rule, the bad-index-field construction error, and IR round-trip.

## Design notes

- `ir.py`: `Field` gains `unique` (after `validation`); new `Index` record; `Entity` gains `indexes`
  (validate each Index; index fields ⊆ entity field names). Update `to_dict`/`from_dict`. Export `Index`.
  `normalize_ir` needs no change (entities pass through as objects).
- `schema_sql.py`: `_column_lines` appends ` UNIQUE` for a unique non-id field; a new `_index_lines(ir)`
  emits the `CREATE [UNIQUE] INDEX` statements after the tables. Reuse `_table`/`table_name`.
- `examples.py`: add a non-unique `Index(("name",))` to `rideshare-favourites` `Driver` for a demo.
