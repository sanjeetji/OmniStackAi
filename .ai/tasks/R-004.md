# R-004 — Go control-plane foundation

## Requirement

Add the smallest Stage 0 Go control-plane process permitted by Brief Sections 33, 74, and 84.1.
It is a modular-monolith foundation, not a new set of microservices.

The supplied tracker omits R-004 through R-009. This task is reconstructed from the Founder Build
Sequence with the founder's instruction to continue.

## Acceptance criteria

- Typed environment configuration rejects missing required database settings and invalid durations/addresses.
- `GET /healthz` returns stable JSON liveness independently of PostgreSQL.
- `GET /readyz` performs a bounded PostgreSQL ping and returns stable JSON status without exposing
  raw database errors.
- The HTTP server has bounded timeouts, JSON structured logs, and graceful SIGINT/SIGTERM shutdown.
- Unit tests cover configuration, liveness, ready, and unavailable states.
- Local Compose builds and runs exactly PostgreSQL and the control-plane; the host port is loopback-only.
- No auth, business API, additional service, queue, cloud resource, or native work is added.

## Expected blast radius

Only the control-plane service, its local Compose integration, root/CI commands and checks,
configuration placeholders, related documentation, tracker evidence, and portable state files may
change.

## Model and cost trace

One local `qwen2.5-coder:14b` design-review call. Zero cloud calls and zero paid provider usage.
