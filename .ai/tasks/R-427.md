# R-427: Fix malformed single-brace inline styles in generated Next.js screens

## Status
DONE

## Objective
Generated Next.js screen files emit invalid JSX inline styles: several f-string templates in
`codegen/nextjs.py` write `style={{ ... }}`, which Python collapses to single-brace `style={ ... }` in the
output (JSX requires double braces). This is a hard syntax error, so any generated web app containing the
affected form/list/detail screen headers and definition lists fails to compile and returns HTTP 500 — the
Studio preview shows a blank/500 page even though the backend runs. `task verify` never caught it because it
asserts generated code as strings and never compiles the TSX. Fix every affected f-string so it emits proper
double-brace JSX (`style={{{{ ... }}}}` in an f-string), and add a deterministic regression test that
generates real projects and asserts **no** single-brace `style={ ...` appears in any generated `.tsx`. Do not
change any component template, screen layout, styling values, or logic — only correct the brace escaping.

## Requirements
- Fix all f-string inline styles in `codegen/nextjs.py` that currently emit single-brace `style={ ... }` so
  they emit double-brace `style={{ ... }}` (use `{{{{ ... }}}}` in the f-string). Do not touch non-f-string
  (regular/raw) templates, which are already correct.
- Add a regression test that generates both example IRs (and covers form/list/detail screens) and asserts no
  generated `.tsx` contains a single-brace inline style (`style={` followed by a non-`{` character).
- No change to component templates, screen structure, styling values, diff-invariance, or any other behavior.

## Acceptance Criteria
- No f-string in `codegen/nextjs.py` emits `style={ <non-brace>`; every generated `.tsx` across both example
  IRs is free of single-brace inline styles.
- The new regression test fails before the fix (proving it catches the bug) and passes after.
- Existing generation, screen, and diff-invariance tests remain green; focused + full verify + lint + security
  + env + both builder demos pass; 0 model calls in verify.
