# R-432: Opt-in model refinement for tailored ecosystems outside curated domains

## Status

DONE (2026-09-13). Third brick of the differentiating spine.

## Objective

Keep the R-430 deterministic classifier and R-431 curated domain models as the authoritative first pass.
When that pass yields `custom-application`, an explicit opt-in path may ask a cheap model-through the
platform-owned `ModelProvider` contract-to propose a tailored business domain, actors, app surfaces, at most
three material questions, and a compact typed entity model. Parse that untrusted response into bounded
framework-neutral values, reject malformed or unsafe shapes, and feed the validated entities through the
existing deterministic CRUD/IR planner so every resulting app remains `validate_ir`-clean and repository
wired. Known curated domains must bypass the model completely. Live Ollama execution is a separate command;
`task verify` stays offline and uses only injected in-memory providers.

## Requirements

- Add a pure message builder and parser for one bounded JSON refinement document. Embed the deterministic
  first-pass proposal in the model context; enumerate allowed field/relation/audience values; treat the user
  prompt as untrusted data; require 1-8 actors, 1-8 surfaces, at most 3 questions, and 1-8 entities with a
  UUID `id`; validate actor references, identifiers, fields, and relation targets through existing IR types.
  An omitted relation collection may normalize to the exact non-fabricating default `()`; all substantive
  values and every unknown key still fail closed.
  Reject raw credential/secret fields, a model-authored FK field that collides with a to-one relation's
  generated `<relation>_id`, and validation strings outside the existing supported rule grammar.
- Add `refine_ecosystem(prompt, provider, *, model_id, ...)`: run `propose_ecosystem` first; if it finds a
  curated domain, return its proposal + curated entities with source `curated` and zero provider requests;
  otherwise make exactly one provider request, parse it, and return source `model` with raw output retained
  only for the caller (never state/logging by default).
- Let R-431's `surface_to_ir`/`plan_ecosystem` accept an optional validated entity tuple without changing
  existing call behavior. Add a refinement-to-plan helper whose CRUD endpoints still resolve to real
  repositories and whose IRs pass semantic validation.
- Add an explicit local-only CLI, `task agent-engine:ecosystem:refine -- "<prompt>"`, using the existing
  environment-driven Ollama provider. It prints only bounded parsed proposal/model/plan data, never secrets
  or raw model output. It does not run in `task verify` and never falls back to cloud.
- Export the public refinement API from `intake`; use Python 3.13 standard library only.

## Acceptance Criteria

- An unknown-domain prompt with an injected valid response produces a tailored multi-app proposal and
  `EcosystemPlan`; every app IR is valid and uses the model-proposed entities rather than fallback `Item`.
- A known food-delivery prompt makes zero provider calls and produces the byte-equivalent curated plan/model.
- Invalid JSON, unknown fields/types/relations, mismatched actors, oversized collections, or more than three
  questions fail closed with `IntakeResponseError`; no partial/fabricated fallback is presented as refined.
- Focused tests and every required repository gate pass with real output. `task verify` makes zero model calls
  and remains network/toolchain/Docker/DB independent.

## Allowed Paths

The paths listed in `.ai/CURRENT_TASK.yaml` are authoritative.

## Forbidden Changes

- Never stage or commit `.claude/`.
- Do not change the deterministic classifier's behavior, curated model contents, Application IR schema,
  adapters, generated contracts, infrastructure, database engine, or execution/deployment planes.
- No new dependency, vendor SDK, hidden cloud fallback, secret handling, or live I/O in verification.

## Gates

- Focused `test_scope_refinement.py`
- `task verify`, `task lint`, `task security:quick`, `task env:check`
- Both builder demos
- Known-domain deterministic ecosystem-plan regression
- One separately invoked local-Ollama unknown-domain refinement proof when the configured local model is
  available; if it is not available, report that gate honestly rather than using cloud.
