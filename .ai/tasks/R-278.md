# R-278 — Collection Screen Boolean & Enum Field Filtering, Segmented Pill Controls & Filter Empty States in Generated Next.js Web App

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Enhance generated Next.js collection screens (`apps/web/app/<screen>/page.tsx`) with interactive,
deterministic client-side filtering for boolean fields and enum fields:

1. Detect filterable fields on the entity: boolean fields (`field.type == FieldType.BOOL`) and enum fields (`enum:a|b|c` in `field.validation`).
2. Manage filter state via `filterValues` (`useState<Record<string, string>>({})`).
3. Compute `filteredData` via `useMemo` comparing item field values against active filters.
4. Seamlessly connect `filteredData` to table row rendering, bulk selection (`allCurrentIds`), and CSV export.
5. Render a styled, accessible filter toolbar above the table when filterable fields exist:
   - For boolean fields, render segmented pill controls: `[ All ] [ {Field}: Yes ] [ {Field}: No ]`.
   - For enum fields, render a `<select aria-label="Filter by {Field}">` dropdown with `"-- All {Field}s --"` and options.
   - Render active filter count badge and a "Reset" / "Clear filters" action button when filters are active.
6. Provide an intuitive empty state when records exist in `data` but none match the active filters:
   `"No {plural} match the active filter criteria."` with a `"Clear all filters"` button.
7. Clean fallback: entities with zero boolean or enum fields emit zero filter code.
8. 100% offline, zero new external npm dependencies, zero new IR fields, strict diff invariance across `ir.description`.

## Acceptance criteria

1. Collection screens import `useMemo` from `"react"` when filterable fields exist.
2. Segmented pill controls are rendered for boolean fields with active/inactive states.
3. Dropdown selects are rendered for enum fields with active/inactive states.
4. Active filter count badge and reset button are rendered when filters are active.
5. Table rows, bulk selection IDs, and CSV export reflect `filteredData`.
6. Dedicated empty filter state is displayed when `data.length > 0 && filteredData.length === 0`.
7. Clean fallback: entities without boolean or enum fields omit filter code.
8. Strict diff invariance: changing only `ir.description` produces byte-identical output.
9. Stage 0 verification (`task verify`), `task lint`, `task security:quick`, and builder demos pass.
