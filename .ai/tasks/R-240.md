# R-240 — Route wiring: generated handlers call the repository layer

## Requirement

Turn the generated backends' `501` stub handlers into working CRUD over the R-239 data-access layer
(Brief §9/§27/§34/§42) — but only for the **unambiguous** endpoint shapes, so the platform never emits
plausible-but-wrong behaviour. Emitted only when the IR has entities and `database_strategy=postgres`;
non-DB backends keep the plain scaffolds. Deterministic and offline; nothing runs. Committed directly to
`main`. New IDs continue after the backlog's R-010..R-219 (this is R-240).

## Acceptance criteria

- `wire_endpoint(api, repo_entities)` wires only: `GET /things`→LIST, `GET /things/{id}` (single param)
  →GET, `POST /things` with a `request_schema` (no param)→CREATE, `DELETE /things/{id}`→DELETE. The
  entity is `response_schema` else `request_schema`, and must be a known repository entity. Everything
  else → `None` (stays `501`).
- Python wired routes import the repository (and the model for create) and `await` the repository call;
  create uses `payload.model_dump()`; unwired routes keep `status_code=501`. Routers parse as valid
  Python.
- Go handlers become methods on a `Handlers` struct with `*sql.DB` (`internal/handlers/handlers.go`
  with `New` + `writeJSON`); `main.go` opens `store.Open()` and registers `h.<Handler>`; wired methods
  call the `store` and decode `models.<Entity>` for create; unwired stay `501`. Non-DB Go backends keep
  free-function scaffolds unchanged.
- Only emitted when entities + postgres; byte-stable; nothing runs.
- Offline tests cover the wiring map + its `None` cases, Python/Go wired emission, and that a non-DB
  backend is unchanged.

## Design notes

- New `codegen/route_wiring.py`: `Op`, `Wiring`, `wire_endpoint`. Shared by both backends.
- `backend_python.py`: `_router_file(segment, apis, repo_entities)` collects wirings, imports the used
  repositories/models, and emits wired bodies; `generate` passes `repo_entities` (empty when no DB).
- `backend_go.py`: `_handlers_shared_file`, `_handlers_file_wired`, and a `has_db` branch in
  `_main_file` / `generate`; the README stack note switches to "pgx" when a DB is present.
- `test_backend_go_adapter.py` assertions updated free-function → method form (that test uses
  `rideshare-favourites`, which has a DB).
