# R-489: Runtime — free, self-hosted gVisor sandbox driver

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-19
**Completed:** 2026-09-19

## Objective

Fourth of the five-task sandbox-provider sequence (R-486..R-490) — **replaces the originally
planned WebContainers option**, per real research findings brought back to the founder before any
code was written: WebContainers requires a paid commercial license for any real (non-prototype)
commercial use — free use is explicitly limited to prototypes/POCs — directly contradicting the
"free, no cost or too much configuration" ask. After presenting the real licensing picture for
every candidate (E2B/Vercel Sandbox/Fly/CodeSandbox: paid-only, no self-host; raw Firecracker:
free but a multi-quarter build-your-own-orchestrator project; Daytona/E2B: open source but self-
hosting means running their full orchestrator; **gVisor: genuinely free, open source, and a small
lift to adopt — a standard Docker/OCI runtime, not a new platform to operate**), the founder
approved building a real, self-hosted `SandboxLifecycleProvider` backed by gVisor instead.

## Design (verified against real, current documentation before writing any code)

- **A genuinely different transport, not a cloud REST API**: E2B/Vercel Sandbox/Daytona are all
  remote HTTPS APIs reached via `sandbox_http.py`'s `urllib`-based transport. The local Docker
  Engine API listens on a **Unix domain socket** (`/var/run/docker.sock` by default) — `urllib`
  has no Unix-socket support, so this task adds a new, small, purpose-built sibling,
  `runtime/docker_socket.py`, using a stdlib `http.client.HTTPConnection` subclass that connects
  via `socket.AF_UNIX` instead of TCP — the standard stdlib idiom for talking to the Docker Engine
  API without a vendor SDK (`docker-py` itself is built the same way internally). Same safety
  invariants as `sandbox_http.py`: bounded response size, finite timeout, stable typed errors,
  and an injectable transport so tests never touch a real Docker daemon.
- **Real, confirmed Docker Engine API endpoints** (fetched directly, matching a well-established,
  extremely stable, ubiquitous API surface — not a single obscure vendor doc page): `POST
  /containers/create` (`{"Image", "ExposedPorts", "HostConfig": {"Runtime", "PortBindings"}}` →
  `{"Id": ...}`), `POST /containers/{id}/start`, `GET /containers/{id}/json` (`NetworkSettings.
  Ports` keyed by `"<port>/tcp"`, each a list of `{"HostIp", "HostPort"}`; `State.Status`),
  `POST /containers/{id}/kill`, `DELETE /containers/{id}`, `GET /info` (`Runtimes`, an object keyed
  by runtime name — used to verify `runsc` is actually registered).
- **`active` is a live local capability check, not an env-var check** — a real, honest design
  difference from every other driver in this sequence (which all check an API-key env var). This
  provider has no credential at all; `active` queries the local daemon's own `/info` and confirms
  `"runsc"` appears in `Runtimes`, defensively returning `False` (never raising) if the daemon
  isn't reachable at all.
- **A real, necessary prerequisite this driver cannot satisfy itself**: gVisor's `runsc` binary
  must already be installed and registered as a Docker runtime on the host (`runsc install`, or a
  manual `/etc/docker/daemon.json` entry plus a daemon restart) — a one-time host/ops setup step,
  analogous to how `E2B_API_KEY` etc. must be configured by the operator, just a local capability
  instead of a credential. Documented here and in the code, not silently assumed.
- **A real, necessary contract correction, found while designing this (not glossed over)**:
  `SandboxHandle.__post_init__` (`runtime/contracts.py`, from R-486) required every URL to start
  with `https://` — correct for three cloud-only providers, but wrong for a genuinely local one.
  `PreviewPlan` (the older, pre-R-486 contract) already allows `http://127.0.0.1`/`http://localhost`
  alongside `https://` for exactly this reason. Relaxed `SandboxHandle`'s validation to match
  `PreviewPlan`'s own already-established pattern — `contracts.py` added to `allowed_paths`
  mid-task once this real gap was found, following the same discipline as every prior mid-task
  scope correction this session.
- **Docker's own image ecosystem covers every target this platform generates, including Go** —
  a genuine, real advantage over Vercel Sandbox (R-487), whose runtime enum has no Go at all:
  `nextjs-web`/`nextjs-admin` → `node:22-slim`, `backend-python` → `python:3.13-slim`,
  `backend-go` → `golang:1.23-alpine`. The host port is auto-assigned by Docker (an empty
  `HostPort` in the port-binding request), then read back from the real inspect response — never
  guessed, matching this sequence's established preference for real API-returned values over
  constructed patterns wherever the API provides them.
- **Scope matches every prior driver in this sequence**: proves real lifecycle management
  (create/status/kill against a real local Docker daemon), not file-sync/install/run automation or
  wiring into the Studio's actual preview flow — the same boundary R-486/R-487/R-488 already
  established, kept consistent here.
