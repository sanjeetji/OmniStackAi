# R-518: Stabilise the core (Phase T, T-0)

**Phase:** MVP → Phase T (Template Marketplace) foundation
**Status:** COMPLETED
**Started:** 2026-09-21
**Completed:** 2026-09-21

## Objective

Before any template work, prove the platform's core loop works live: register → create a project
from a prompt → stream the build → project renamed → reopen → chat edit commits → survives a
restart. Fix whatever blocks it. The founder's condition for Phase T: "our primary goal should not
be destroyed or broken".

## What was found

`scripts/omnistack.sh up` reused the control-plane image `omnistackai/control-plane:r004`, built
2026-09-19, so none of the R-499…R-517 control-plane code had ever run against a real database.
Rebuilding it from source exposed a chain of defects. Each one below was reproduced live first.

| # | Defect | Effect | Fix |
|---|--------|--------|-----|
| 1 | `internal/projects` and `internal/seo` both registered `POST /projects/{id}/seo/audit` and `/seo/suggest` | ServeMux **panicked at startup** | Duplicates removed from projects. Route wiring moved into `newMux()`, and `cmd/control-plane/main_test.go` builds the full production route table |
| 2 | `POST /projects/{id}/opened` was called by the console but never registered (R-499 listed it) | 404/405 on every Studio load | `handleProjectOpened` (ownership check, 204) |
| 3 | Migration 000015 read `users.name` (the column is `full_name`) | Control-plane could not start on any DB that had users | `full_name`. Also added `TestNoMigrationCommentContainsASemicolon` (the runner splits on every `;`) |
| 4 | 4 queries in `projects/store.go` + `workspaces/store.go` read `u.name` | Every project GET, build stream and `/opened` returned 500 | `COALESCE(NULLIF(u.full_name, ''), …)` |
| 5 | Console `POST /api/projects` required `name` | The Studio's first message failed with 400 | `name` optional, defaults to "Untitled project" and is renamed after the build |
| 6 | Console build-stream route dropped `mention_skills` | `@skill` mentions ignored | Forwarded |
| 7 | Console `callControlPlane` called `response.json()` on 204 | Every 204 route showed as 502 | Empty body → `undefined` |
| 8 | Project proxies used `http.Client{Timeout: 15s}`, and that timeout also covers reading the body | **Every real build stream was cut at 15 s**: an empty 200, with the workspace left locked | Per-call context budgets (build/edit 5 min, preview 60 s, problems 90 s, other calls 15 s) plus `SetWriteDeadline`. Test relays a slow upstream fully |
| 9 | Agent-engine `_workspace_edit` read `diff.added_files` / `modified_files` / `deleted_files`, which `ProjectDiff` never had | **Every chat edit that changed files was committed and then answered as an error (502)**. Only no-op edits "worked" | `diff.added()` / `modified()` / `deleted()`. New `WorkspaceEditTests` reproduces the exact live error |
| 10 | `omnistack.sh up` ran a stale image | Hid 1–8 | `compose up -d --build --wait` |

## Found, not fixed here (reported to the founder)

- Cloud provider `google` fails to bootstrap ("safe input and maximum output tokens must fit the
  context window"), so the Studio falls back to local Ollama. This is a `.env` token-limit config
  issue.
- Generated preview seed fails with `invalid input syntax for type uuid: "user1"` (codegen fixture
  bug, belongs to the generated-auth/fixture hardening track).
- The IR delta engine is add-only, so an edit that modifies a field is a no-op. T-4 (code-edit
  agent) addresses this.
- 15 local commits R-499…R-517 were never pushed, and before this task they had never run live.
