# R-236 — Expand the model-provider catalog + custom OpenAI-compatible providers

## Requirement

Grow the cloud model fabric to a competitive provider picker (Brief §10-13/§64/§90). Add first-class
OpenAI-compatible adapters for **DeepSeek, xAI (Grok), Mistral, Together, Fireworks** alongside the
existing OpenAI/Anthropic/Google/OpenRouter/Groq, and add a generic env-driven **custom provider** path
(any OpenAI-compatible base URL + key) so a user can plug in an endpoint with no code change — the
platform's advanced equivalent of the reference "Add custom provider". Every provider stays
key-activated (no key → inactive, no cloud call); local Ollama stays the always-on sub-L3 default.
Committed directly to `main`. New IDs continue after the backlog's R-010..R-219 (this is R-236).

## Acceptance criteria

- New built-in specs (`deepseek`, `xai`, `mistral`, `together`, `fireworks`) are OpenAI-compatible with
  an HTTPS base URL, a distinct key env, a model env, and a default model; each registers only when its
  key is present.
- A custom provider is declarable from the environment (`OMNISTACKAI_CUSTOM_PROVIDERS` +
  `OMNISTACKAI_CUSTOM_<ID>_BASE_URL` / `_API_KEY` / `_MODEL`) and becomes a first-class provider with no
  code change; invalid config (bad id, missing/non-HTTPS base URL, collision with a built-in) → a clear
  `InvalidProviderConfigurationError`.
- `resolve_provider_specs()` merges built-ins + custom; bootstrap registers, selects (cloud tier), and
  chains (fallback) any built-in or custom provider by its key; the overview lists every provider with
  `active` reflecting only key presence (never the value).
- The price book has illustrative, operator-overridable defaults for the priced new providers;
  unknown/custom models are recorded as unpriced.
- Offline tests cover the new specs, adapter dispatch shape, custom-spec parse + errors, spec
  resolution/merge, bootstrap registration/selection/fallback, and no-key-leak. `task verify` green.

## Design notes

- `cloud.py`: add the new `CloudProviderSpec` entries (kind `openai`); add `custom_provider_specs_from_env`
  and `resolve_provider_specs` (built-ins ∪ custom). No new adapter class — the OpenAI-compatible adapter
  already serves them.
- `bootstrap.py` / `overview.py`: iterate `resolve_provider_specs()` instead of the raw dict, so custom
  providers are registered/selectable/listed. `accounting.py`: add default prices for the priced ones.
- Keys are read from env only, never logged/stored/returned. No network call anywhere in the change.
