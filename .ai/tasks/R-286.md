# R-286 — Race-Safe Generated Subcollection Refetches

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic code generation; 0 model calls)

## Objective

Prevent stale generated LIST_BY responses from overwriting the current child list when a parent ID or
subcollection query state changes rapidly.

## Scope and impact

- Extend only the existing Next.js subcollection hook generator plus focused offline tests.
- Reuse the established R-280 AbortController pattern while ensuring deselection cancels before the
  empty-parent return and caller options cannot override the internal signal.
- No Application IR, backend, dependency, database, external request, model, infrastructure, or
  native/mobile change.

## Acceptance criteria

1. Filterable and non-filterable `useList<Child>By<Parent>` hooks own an AbortController ref.
2. Each refetch aborts the prior request before checking for a missing parent ID.
3. LIST_BY calls preserve params and parent scoping and use the internal signal after caller options.
4. Aborted success/error/finally paths cannot mutate newer request state.
5. Effect cleanup aborts on dependency change or unmount; public hook signatures stay unchanged.
6. Focused tests, all subcollection tests, and every recorded offline gate pass.
