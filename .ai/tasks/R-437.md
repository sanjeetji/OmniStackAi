# R-437: Deterministic Solution Pack configuration application

## Status

DONE (2026-09-14). Eighth differentiating-spine brick; fourth Solution Pack task.

## Objective

Implement the first deterministic application layer above R-436. An exact-pinned manifest may update only
the fresh baseline Application IR's project name and description using explicit bounded text; the result is
validated and accompanied by immutable provenance. AI-delta entries remain reviewable, explicitly unapplied
intent. No source generation, build, provider, or model path is part of this task.

## Requirements

- Extend current manifests with a typed `desired_text` field and increment the manifest schema version.
  Continue to strictly parse and losslessly serialize legacy R-436 schema 1.0 documents without this field.
- Permit `desired_text` only for `configuration` + `update` + `project` changes targeting `project:name` or
  `project:description`; apply the Application IR's corresponding 128/4000-character and control rules.
- Never infer a value from `summary` or acceptance criteria. An applicable configuration change without an
  explicit desired value fails closed.
- Revalidate the manifest's exact registry recommendation, load a fresh pack IR, reject duplicate writes to
  one target, apply changes deterministically, then require a `validate_ir`-clean result.
- Reject every other configuration operation/target in this first application allowlist. AI-delta entries
  are never applied and are reported separately as pending.
- Return a frozen JSON-safe result containing the exact base pin/digest, derived digest, ordered applied and
  unapplied change IDs, and the derived IR. The registered baseline must remain byte-identical.
- Preserve registry/recommendation/ecosystem/build output and use Python 3.13 standard library only.

## Acceptance Criteria

- Project name and description updates produce a new valid immutable Application IR from `minimal-blog`.
- Repeated application is byte-stable; empty and AI-only manifests keep the base digest unchanged.
- The baseline can be loaded afterward with its original digest/content, proving no mutation.
- Missing/invalid values, unsupported configuration entries, duplicate target writes, invalid manifests, and
  stale pins fail closed before a result is returned.
- Legacy manifest 1.0 JSON remains accepted and lossless; current manifests emit the new schema deterministically.
- Focused regressions and all repository gates pass with real output and zero model calls.
