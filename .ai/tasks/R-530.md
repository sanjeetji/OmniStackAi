## Ops app design

- **Stack:** the same as the other apps: Next 16, React 19, Tailwind 4, `@ridenow/shared`,
  lucide-react.
- **Look:** a light, dense, desktop-first control room. A dark ink sidebar, a cool slate canvas,
  8 px radii, compact 13–14 px tables, "signal blue" for actions and RideNow amber for the brand.
  Instrument Sans with tabular figures. It must look nothing like the rider app (warm, rounded,
  Plus Jakarta Sans) or the driver app (dark, Sora, big touch targets).
- **Access:** admin accounts only. Sign-in sends `role: "admin"`, so rider and driver accounts get
  the API's 403 message. The session lives under its own storage key.
- **Realtime:** the admin SSE channel (`trip.updated`, `driver.status`, `driver.location`,
  `ticket.created`, `ticket.updated`, `payout.requested`, `zone.updated`) drives the live
  counters, the live map and badges in the sidebar, with polling as a fallback.
- **Pages** (all backed by existing `/admin/*` and `/support/*` endpoints; no API change is
  planned):

| Route | Content |
|---|---|
| `/login` | Admin sign-in with the demo login shortcut |
| `/` | Dashboard: KPIs with week-over-week deltas, 14-day trips and revenue chart, vehicle mix, top drivers, recent trips, live counters, work queues (pending drivers, payouts due, open tickets) |
| `/live` | Live map: online drivers (busy or free), active trips with pickup/drop, surge zones; a side list of active trips |
| `/trips`, `/trips/[id]` | Filterable, searchable, paged trips; detail with status timeline, dispatch offers, fare breakdown, ledger lines, ratings, cancel and refund |
| `/riders`, `/riders/[id]` | Search and paging; detail with wallet, trips, ledger, tickets, suspend or reactivate, wallet adjustment |
| `/drivers`, `/drivers/[id]` | Status filter and search; detail with vehicle, documents review (approve or reject with a note), approve, suspend, earnings, trips, ratings, wallet adjustment |
| `/pricing` | Vehicle types: base, per km, per min, minimum, booking fee, commission, active |
| `/zones` | Surge zones on the map, surge multiplier and active switch |
| `/promos` | Promo codes with usage and discount given; create; pause or resume |
| `/payouts` | Requests by status; mark paid or reject |
| `/finance` | Platform balance, 30-day money by kind, owed to drivers, rider wallet float |
| `/support`, `/support/[id]` | Ticket queue by status and priority; thread with reply, priority and resolve |

| `/settings` | Account, how this deployment works (mock providers and where real ones plug in), device preferences |

## Found and fixed (platform defects the live gate exposed)

1. **No preview page could load in a browser.** The proxy forwarded the upstream
   `content-encoding` although `fetch` had already decoded the body, so every navigation failed
   with `ERR_CONTENT_DECODING_FAILED`. curl never saw it because it sends no `Accept-Encoding`.
2. **No preview page was interactive.** Previews ran each app with a dev server; its hot-reload
   socket cannot pass the proxy, and a Turbopack dev app never hydrates without it (proved by
   killing `WebSocket` on a direct page load). Previews now build once and serve the production
   build — what the user will deploy — with a new "Building the apps" phase.
3. **Finder junk shipped to users.** `.DS_Store` files were copied into every project made from a
   template and counted in its digest.
4. **A project's Python tests reported 0 passed** wherever pytest is not installed: since Python
   3.11 `unittest discover` does not recurse into a non-package `tests/` folder.
5. **Git's background `gc` raced with the platform**, writing inside `.git` while a project
   directory was being copied or removed (it also made `task verify` fail here). Platform git calls
   now disable auto-gc and background maintenance.

## Found, not fixed (needs a decision)

- **Client-side navigation in previews falls back to full page loads.** The console is itself a
  Next app, so its server answers RSC navigation requests to `/preview/...` before the proxy code
  runs (proved: a bogus project id returns 307, not 404). It redirects to its own `_rsc` hash while
  the previewed app redirects to a different one, so prefetches bounce between them and abort.
  Page loads, forms and buttons are unaffected, and clicking a link still works (it reloads the
  page). A fix needs a preview path that is not a Next route: a middleware rewrite, or serving
  previews from the Studio or the control-plane. Worth its own Tracker ID.
- **`.env.example` cannot be sourced.** `OMNISTACKAI_GATEWAY_PROMPT` has an unquoted value with
  spaces and a colon, so `scripts/console.sh` (which sources `.env`) dies with
  `line 14: with: command not found` on any machine that copies the example. Fixed in the local
  `.env` only; `.env.example` was outside this task's allowed paths.

  but chat edits want a cloud model today.

**Platform work this needed, all committed here:**

1. **`OMNISTACKAI_AGENT_CALL_TIMEOUT`** (control-plane, default 5m): a local model takes longer
   than five minutes on a real edit, and the old fixed budget reported "could not reach the
   control-plane" while the edit was still running and holding the workspace lock.
2. **The edit parser tolerates how small models actually reply**: a sentence before the first
   directive, and a missing summary when the operations themselves parsed. The corrective retry now
   shows the exact format and tells the model to use real paths.
3. **A deterministic file-selection fallback** (`pick_files_by_name`): when the model names files
   that do not exist, the editor used to receive no file contents at all and then invented both
   paths and text. It now falls back to ranking real repository paths against the request.
4. **`omnistack.sh doctor` now checks every trap that has broken a fresh machine**: Python is
   3.13, Node is at least 22.18, ripgrep and Task exist, the compose plugin is reachable, `.env`
   can be sourced, the agent-engine URL is container-safe, and the cloud token budget fits its
   context window (getting that wrong silently falls back to Ollama).
5. **`.env.example` now works as shipped**: the gateway prompt is quoted (an unquoted value killed
   start-up), the agent-engine URL is `host.docker.internal`, and the Ollama budgets are usable.
6. **`docs/SETUP.md`**: every requirement, the install commands, configuration, verification and a
   troubleshooting table, linked from `README.md` and `docs/START_HERE.md` and pinned by
