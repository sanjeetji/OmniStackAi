# R-422: Collision-free Studio preview ports + status/stop/restart controls

## Status
DONE

## Objective
Make the trusted-local Studio preview robust when other local apps or a prior preview are already running,
and give the operator bounded lifecycle control. Add automatic, collision-free API/web port allocation so a
Studio preview never fails or clobbers an existing `task app:run` app on 3000/8000 (or a previous preview):
distinct free loopback ports are allocated per preview and threaded through the existing R-419 run-plan
boundary (`build_run_plan` already parameterizes `api_port`/`web_port`, and the generated web app receives
the matching `NEXT_PUBLIC_API_URL`). Add bounded `status`, `stop`, and `restart` controls to the
`StudioPreviewManager` (single remembered repo, single owned session, fixed-shape secret-free payloads) and
expose them over the existing stdlib Studio server as `GET /api/preview`, `POST /api/preview/stop`, and
`POST /api/preview/restart`, wired only in the explicit trusted-local preview mode; the build-only Studio
returns 404 for these control routes. Add matching Stop/Restart controls and a live status line to the
Studio page without HTML injection. Keep single-session cleanup, `studio:serve` build-only, `studio:preview`
trusted-local, PostgreSQL, and the existing architecture unchanged; all verification stays deterministic and
offline (no generated code, Docker, PostgreSQL, package install, model, or external network in `task verify`).

## Requirements
- Allocate two distinct, currently-free loopback ports per preview and use them for the generated app's API
  and web servers (never hard-code 8000/3000 for previews); build-only `studio:serve` and the `app:run` CLI
  are unchanged.
- Add a `start_preview_app` boundary in localrun that allocates the ports, builds the env plan with those
  ports, and delegates to the existing strict `start_app` (readiness, occupied-port rejection, cleanup).
- Extend `StudioPreviewManager` with `status()`, `stop()`, and `restart()` returning bounded, JSON-safe,
  secret-free state; `restart()` re-previews the last built repo and is a no-op idle state before any build.
- Extend the stdlib Studio server with optional injected `status_fn`/`stop_fn`/`restart_fn` handlers mapped
  to `GET /api/preview`, `POST /api/preview/stop`, `POST /api/preview/restart`; unset handlers return 404.
- Wire the control handlers to the manager only in trusted-local preview mode; keep build-only mode without
  live preview controls.
- Add Stop/Restart buttons and a status line to the Studio page (no `innerHTML` of server data; loopback-URL
  validation preserved) and keep the R-421 sandboxed iframe surface intact.
- Keep `StudioPreviewManager` owning at most one session; replacement, stop, and Studio shutdown all clean up.
- All verification deterministic/offline via injected/stubbed run, process, readiness, and port boundaries.

## Acceptance Criteria
- A preview uses automatically allocated distinct free ports; `start_preview_app` overrides the plan's
  api/web ports with the allocated ones and delegates to `start_app`.
- `StudioPreviewManager.status/stop/restart` return bounded, secret-free dicts; `restart` before any build is
  idle; `restart` after a build re-previews the last repo; `stop` reports stopped and is idempotent.
- `GET /api/preview`, `POST /api/preview/stop`, `POST /api/preview/restart` return the manager state in
  preview mode and 404 when controls are not enabled; existing `GET /`, `/healthz`, and `POST /api/build`
  behavior is unchanged.
- The Studio page exposes Stop and Restart controls that call the control routes and re-render preview state.
- Existing R-421 studio, preview, and local-run session/plan contracts remain compatible; all focused and
  full verification, lint, security, environment, and both builder demos pass; 0 model calls in verify.
