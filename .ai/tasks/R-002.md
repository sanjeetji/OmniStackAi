# R-002 — Local PostgreSQL + pgvector bootstrap

## Requirement

Add the Stage 0 control-plane database foundation from the Founder Build Sequence: a pinned,
local-only PostgreSQL image with pgvector and one versioned initial migration.

The supplied tracker omits rows R-001 through R-009. This task is reconstructed from the kickoff
kit's canonical R-002 example: “Added Postgres+pgvector via docker-compose, initial migration.”

## Acceptance criteria

- Docker Compose starts one PostgreSQL service with pgvector from a pinned image.
- The database port is bound only to loopback and credentials come from ignored local environment
  configuration.
- A versioned, transactional initial migration enables pgvector and records its schema version.
- Root task commands validate Compose configuration, start/stop the database without deleting its
  volume, and verify the extension and migration state.
- Existing Stage 0 verification continues to pass without requiring a running container.
- No Redis, application service, cloud database, orchestration platform, business schema, or native
  mobile/device-cloud work is introduced.

## Expected blast radius

Only the local environment Compose file, control-plane migrations, database helper script, root task
commands, local-development documentation/configuration, tracker evidence, and task/state records may
change.

## Rollback

Run `task db:down` to stop and remove the local container and network while preserving the named data
volume. The down migration is intentionally manual and local-development-only because it removes the
extension and migration ledger.

## Model and cost trace

Deterministic tools only. Zero model-provider calls and zero paid cloud usage.
