# R-221 — Cross-provider fallback and circuit breaking

## Requirement

Add explicit, allowlist-driven cross-provider fallback plus per-provider circuit breaking to the
Balanced gateway (Brief 18.3 fallback/circuit breakers, 89 provider outage/failover, 92). An operator
configures an ordered fallback chain; the gateway advances to the next allowed, registered,
circuit-closed candidate only on a retriable failure — never silently, never outside the chain.
Founder asked to complete both the console slice and fallback one by one; R-221 is fallback, the
Next.js console slice follows as R-222.

New model-fabric IDs continue after the workbook backlog's R-010..R-219 (this is R-221).

## Acceptance criteria

- `RoutingPolicy` accepts an optional ordered fallback chain of `ModelDescriptor`; with none
  configured the gateway behaves exactly as before (single provider, same tests pass).
- On a retriable failure (`ProviderUnavailableError`, `ProviderTimeoutError`, `ProviderHTTPError`) the
  gateway advances to the next allowlisted candidate that is registered and whose circuit is closed; a
  non-retriable error (budget, unknown model, unsupported request) is raised immediately.
- A per-provider circuit breaker opens after a configurable consecutive-failure threshold, skips the
  provider until a cooldown elapses, then half-opens; success resets it. Injectable clock, thread-safe.
- When every candidate is unavailable/skipped/failing, the gateway raises a stable
  `AllProvidersFailedError`; high-risk work is never downgraded and the chain is never left.
- Each dispatch attempt (success or failure) is recorded by the accounting ledger when configured.
- Offline standard-library tests cover fallback success, non-retriable no-fallback, circuit
  open/skip/recover, all-failed, ordering, and accounting of attempts; zero network access.
- Static `task verify` stays network-independent and green.

## Expected blast radius

New `resilience.py` (circuit breaker) and `test_fallback.py`, an optional `fallback` field on
`RoutingPolicy`, fallback iteration + optional breaker in `gateway.py`, a new `AllProvidersFailedError`,
`__init__` exports, and doc/state/tracker evidence. No change to PostgreSQL, Compose, infrastructure,
the Section 74 contract, or single-provider behavior.
