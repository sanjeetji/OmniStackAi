# R-008 — Cloud API-key ModelProvider adapters (multi-provider, key-activated)

## Requirement

Add cloud model adapters behind the existing `ModelProvider` boundary so the R-007 Balanced gateway
can escalate L3/L4 work to a cloud model. Per the founder's instruction, configure **each** provider
— Anthropic, OpenAI, Google Gemini, OpenRouter, Groq — so that adding any provider's API key makes
that LLM work with a default model the operator can override. With no keys set, the platform keeps
running on local Ollama (qwen) and makes zero cloud calls.

Reconstructed from Brief Sections 18, 18.1, 18.3, 25, 26, 27, 74, 75, 77, 84, 85, 87, 90, 91, and 92.
No key is available yet, so adapters are proven with offline tests using injected fake HTTP openers;
no paid cloud service is consumed.

## Acceptance criteria

- Each adapter implements the `ModelProvider` boundary using only the Python standard library over
  HTTPS; no vendor SDK and no external dependency are added.
- OpenAI, OpenRouter, and Groq share one OpenAI-compatible chat-completions adapter; Anthropic uses
  its Messages API; Google uses its `generateContent` API. Each maps messages, output text, finish
  reason, and token usage into the existing vendor-neutral records.
- Every adapter reads its API key only from the environment, sends it only as the provider auth
  header, and never places it in logs, errors, records, or state.
- Each provider has a documented default model overridable by environment variable, with conservative
  per-model context and output budgets.
- An env bootstrap always registers local Ollama and registers each cloud provider whose key is
  present. With no cloud key, only Ollama is registered and L3/L4 return the stable
  `no_eligible_provider` outcome (no silent local downgrade).
- `OMNISTACKAI_CLOUD_PROVIDER` selects the active L3/L4 cloud tier; selecting a provider without its
  key is a clear configuration error.
- Standard-library offline tests cover request mapping, auth-header construction, success/error
  responses, response-size and timeout bounds, key-absent deactivation, and bootstrap
  registration/selection — all with fake openers and zero network access.
- The live gateway runner still runs on local Ollama with no keys; static `task verify` stays
  network-independent and green.
