# R-230 — Go backend framework adapter (IR → Go net/http service)

## Requirement

Add a third framework adapter (Brief §42/§43/§46): `GoBackendAdapter` turns an Application IR into a
real, idiomatic Go standard-library `net/http` service as a `GeneratedProject`. Proves the one-IR →
many-targets differentiator (Next.js web + FastAPI + Go). Deterministic and offline; nothing is
installed, built, run, or written to disk. Work committed directly to `main` (only branch). New IDs
continue after the workbook backlog's R-010..R-219 (this is R-230).

## Acceptance criteria

- `GoBackendAdapter` implements `FrameworkAdapter` (target `backend-go`) and returns a
  `GeneratedProject`: `go.mod`, `main.go`, `internal/models/models.go`,
  `internal/handlers/<segment>.go`, `README.md`, `.gitignore`, `.env.example`.
- Entities → Go structs (types mapped; exported fields with `json` tags; non-required → pointer with
  `,omitempty`). IR APIs → Go 1.22 mux routes (`"METHOD /path"` with `{param}`), handlers grouped by
  first path segment, returning 501 and reading params via `r.PathValue`. `main` registers each route
  and `GET /healthz`.
- Safe, deterministically ordered paths; pure function of the IR; standard-library only (platform +
  generated Go); no install/build/run/disk write.
- Offline tests assert emitted paths + key contents, entity→struct mapping, route registration/params,
  and registry wiring. `task verify` stays green.

## Design notes

- `codegen/backend_go.py`: `GoBackendAdapter`; `FieldType`→Go type map (string/int64/float64/bool/
  time.Time/json.RawMessage), group APIs by first path segment, PascalCase handler names, `{param}`
  extraction. Mirrors `codegen/backend_python.py`. Registered via `AdapterRegistry`.

## Model and cost trace

Deterministic; no model call. No cloud key set; cloud_calls zero.
