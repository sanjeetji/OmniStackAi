## Objective

Third task of the approved 7-task Phase D roadmap (plan record:
`/Users/sanjeet_kumar/.claude/plans/hi-fancy-shannon.md`). Replace `/studio`'s one-shot prompt form
with a persistent, multi-turn chat thread on R-475's shell, wired to R-476's new
`POST /jobs/build/{id}/edit` / `GET /jobs/build/{id}/turns` routes. `buildId` (`null` vs. set) is
the single piece of state deciding whether the composer calls `/jobs/build` (first message) or
`/jobs/build/{id}/edit` (every follow-up) — same composer, same input box.

## Design

- New `lib/control-plane.ts` additions: `ChatTurn` (`{role, text, created_at}`, matching
  `session.py`'s `record_turn`/`turns_view` shape exactly — `created_at` is a `time.time()` float,
  seconds not ms), `BuildTurnsResponse` (`{turns: ChatTurn[]}`), `BuildEditResponse` (mirrors
  `_edit()`'s real response dict: `id`, `diff`, `entities`, `file_count`, `commit_sha`, `rationale`,
  `usage`, `turns`, plus `credits_spent`/`credit_balance` injected by the control-plane), plus
  `editBuild(token, buildId, prompt)` and `getBuildTurns(token, buildId)` client functions.
- New proxy routes `app/api/jobs/build/[id]/edit/route.ts` (POST, validates non-blank `prompt`, same
  shape as the existing `app/api/jobs/build/route.ts`) and
  `app/api/jobs/build/[id]/turns/route.ts` (GET, same shape as the existing `[id]/files/route.ts`).
- **New `app/studio/studio-workspace.tsx`**: the `BuildResult`/`FileBrowser` presentational pieces
  moved out of the retired `studio-form.tsx`, generalized to render from a normalized
  `WorkspaceSnapshot` (`buildId`, `name?`, `description?`, `entities`, `fileCount`, `commitSha?`,
  `usage?`, `files`) rather than directly from `BuildJobResponse`, since an edit's response has a
  different, narrower shape (no `name`/`description`/`files`).
- **New `app/studio/studio-chat.tsx`** (client component, replaces `studio-form.tsx`'s role): owns
  `messages: ChatMessage[]` (`{id, role, text, createdAt, kind: "plain"|"error"}` — deliberately
  narrower than the plan sketch's `kind` enum: see "Finding" below for why build/edit result cards
  are *not* attached per-message), `buildId: string | null`, and `workspace: WorkspaceSnapshot |
  null` (the single "latest state" the workspace panel renders — not per-message, so an edit's
  narrower response naturally patches the existing snapshot rather than needing its own duplicate
  render path).
  - `handleSend()`: `buildId === null` → `POST /api/jobs/build`; else → `POST
    /api/jobs/build/{buildId}/edit`. A build's response fully populates `workspace` (it's the only
    response with `name`/`description`/`files`); an edit's response patches
    `entities`/`fileCount`/`commitSha`/`usage` onto the existing snapshot and re-fetches
    `GET /api/jobs/build/{id}/files` (R-474's existing route) to refresh the file list, since
    `_edit()`'s response carries no `files` key.
  - **Refresh survival**: `buildId` persists in the URL (`?build=<id>` via `router.replace`) after a
    successful build. On mount, if present, hydrate `messages` from `getBuildTurns` — texts only,
    `kind: "plain"`; the `workspace` panel does **not** rehydrate (see Finding below), an honest,
    documented degradation, not silently presented as full-fidelity history.
  - Failure modes, both real and independently verified in the actual agent-engine source (not
    assumed) before being handled: `EditNotSupportedError` (400, raised by `_edit()` for Solution
    Pack/Ecosystem builds — unreachable from this UI today since only plain-prompt builds are
    creatable here, but handled so a future build kind doesn't crash) → a `kind: "error"` chat
    bubble with the real message. `BuildNotFoundError` (404, raised by `_edit()` for an unknown or
    evicted build id — genuinely reachable once URL-persistence exists, e.g. a stale `?build=`
    surviving an agent-engine restart) → clear `buildId` (and the URL param) and append a `kind:
    "error"` bubble: "This session is no longer available — start a new app."
- **Finding, verified by direct source read before design (not assumed from the plan sketch)**:
  `GET /api/build/{id}/turns` (`_handle_turns` → `session_store.turns_view(build_id)`) does **not**
  404 for an unknown/evicted build — `turns_view` returns `{"turns": []}` for a missing session
  entry (`session.py`: `if entry is None: return {"turns": []}`), not an error. Only the *edit*
  endpoint's `entry = history.get(build_id); if entry is None: raise BuildNotFoundError` can produce
  a real 404. This means turns-hydration is not itself a place `BuildNotFoundError` can surface —
  the plan sketch's "`BuildNotFoundError` ... on an edit or turns-hydration call" was half right:
  the real 404 only comes from an edit attempt on a stale `buildId`, which is exactly when the
  handling above fires. A refresh against a stale `?build=` therefore hydrates as an empty thread
  (indistinguishable from a brand-new build) rather than an error — an honest, named limitation, not
  a bug: the very next message sent against that stale id correctly surfaces the real 404 and
  recovers.
- Introduces the two-column `.studio-grid` deferred from R-475: workspace panel (left, `1fr`) + a
  ~380px chat rail (right), single column below 900px. New `globals.css` classes: `.studio-grid`,
  `.chat-rail`, `.chat-thread`, `.chat-message` (+ `--user`/`--assistant`/`--error` modifiers),
  `.chat-composer`, `.chat-send`, `.chat-empty`, `.workspace-empty`.
- `studio-form.tsx` is retired (deleted) — its role is fully replaced by `studio-chat.tsx` +
  `studio-workspace.tsx`.

## Acceptance Criteria

- [x] The composer sends the first message to `POST /jobs/build` and every subsequent message in
      the same thread to `POST /jobs/build/{buildId}/edit`, based solely on whether `buildId` is set.
- [x] `buildId` persists in the URL after a successful build; a page refresh hydrates the chat
      thread's text from `/turns` (including the build's own first turn, per R-476's fix).
- [x] `EditNotSupportedError`/`BuildNotFoundError` from an edit call are handled gracefully (a
      visible error bubble, no crash); a `BuildNotFoundError` clears `buildId` so the user can start
      a new app.
- [x] The workspace panel reflects the latest build or edit result (stats, entities, credit usage,
      file browser), refreshing its file list after an edit.
- [x] `pnpm run typecheck`/`lint`/`build` all clean; `task verify`/`lint`/`security:quick`/`env:check`
      all pass.
