# R-283 — Server-Side Collection Filter Wiring in Generated Next.js Screens

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic code generation; 0 model calls)

## Objective

Move the existing R-278 boolean/enum collection filters from page-local filtering to the generated
top-level `useList` request. The controls must send the exact R-282 `?<field>=<value>` parameters so
filtering occurs before pagination, while preserving the current toolbar, active-count badge, reset
actions, URL state, race-safe refetch behavior, and deterministic output.

## Scope and impact

- Change only Next.js source generation in `codegen/nextjs.py` and focused offline tests.
- Top-level `Op.LIST` collection screens only; subcollection `LIST_BY` hooks and backends are unchanged.
- No Application IR schema field, generated npm dependency, platform dependency, database connection,
  external request, model call, generated-app execution, infrastructure, or native/mobile work.

## Acceptance criteria

1. Generated `UseListParams` carries optional `filters: Record<string, string>`; top-level list state
   exposes `setFilter(field, value)` and `clearFilters()`, both resetting `offset` to zero.
2. Empty/`all` values remove a filter key. Active filters are flattened into the `ApiOptions.params`
   object sent to `list<Plural>WithCount`, so `requestWithMeta` emits ordinary query parameters.
3. Generated boolean pills and enum selects call `setFilter` with exact IR field names. Reset and
   empty-state recovery call `clearFilters`.
4. Client-side `useMemo`/`data.filter` is absent; the table renders `data ?? []`, and the filtered
   no-results state is based on active server filters.
5. Top-level URL hydration/sync handles only the generated allowlist of filterable field names and
   writes only active values; existing search/sort/page/pageSize behavior remains intact.
6. Entities with no boolean/enum fields emit no filter controls. Description-only IR changes keep
   generated screen, hooks, and API client output byte-identical.
7. Full offline verification, lint, security, both builder demos, and manual generated-artifact
   inspection pass.
