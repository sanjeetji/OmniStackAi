# R-525: Code-edit agent for template projects (Phase T, T-4)

**Phase:** Phase T (Template Marketplace)
**Status:** COMPLETED
**Started:** 2026-09-21
**Completed:** 2026-09-21

## Objective

Users customise their copy of a template by chat: add features, remove features, change how things
work. The agent edits the real source files, checks them, and commits. The original template is
never touched. Until now, template projects refused chat edits (R-519/R-523), because the IR delta
engine can only add, and it needs an IR that template projects don't have.

## Design (`studio/code_edit.py`)

1. **Select.** The model sees the request, the project's `omnistack.json` and a file index (paths
   and sizes, with `.git`/`node_modules`/build output excluded). It answers with JSON
   `{"plan", "files"}`: at most 12 files to read.
2. **Edit.** The model gets the plan, the runtime contract (basePath/env/migrations rules) and the
   selected files' contents (bounded: about 40k characters per file, 90k in total). It replies in a
   line-delimited format, not JSON, because code inside JSON strings is fragile:
   ```
   @@@ SUMMARY
   what changed, for the user
   @@@ WRITE path          (new file, or a full rewrite of a small file)
   …content…
   @@@ REPLACE path
   @@@ FIND
   …exact text, must occur exactly once…
   @@@ WITH
   …new text…
   @@@ DELETE path
   @@@ END
   ```
   A missing `@@@ END` means the reply was cut off: rejected, and one retry asks for a smaller
   change.
3. **Validate, then apply.**
   - Paths must be relative and inside the repo, never under `.git/`, `node_modules/` or `.next/`,
     and never a real `.env` file.
   - At most 25 operations and 200 KB per file.
   - A REPLACE must match exactly once. WRITE is not allowed on a file that was shown truncated.
   - Everything is computed in memory first, then written.
4. **Verify** only the apps that were touched:
   - `tsc --noEmit` where the app has a `tsconfig.json` and an installed TypeScript;
   - `node --check` for changed JavaScript files;
   - JSON parse for changed `.json` files;
   - `omnistack.json` revalidated.
   - Anything that cannot be checked yet (no dependencies installed) is reported as "not checked",
     never claimed as verified.
   - On failure: **one repair round** with the errors and the current files. Still failing: every
     touched file is restored and nothing is committed.
5. **Commit** only the touched paths (`git add -- <paths>`, `git rm` for deletions), never
   `git add -A`, because preview installs leave untracked `node_modules`. The turns are recorded,
   and the response has the same shape as other edits (diff added/modified/deleted, summary,
   commit, usage) plus `verification`.

**Routing:** `_workspace_edit` sends `kind: "template"` workspaces to the code-edit agent. Prompt
rebuilds of template projects stay refused. The console Studio notice becomes "your own copy;
changes are made to its code, checked and committed", and the composer is enabled.

## Out of scope

Enabling it for prompt-built apps (they keep the IR edit path; opt-in later), a diff view in the UI
(T-5), and new npm dependencies being installed mid-edit (the next preview start installs them).

## Gates

Offline tests with scripted stub providers:
- a full add / modify / delete edit;
- each validation rule;
- truncation retry;
- verification failure, then repair;
- verification failure, then rollback (repo byte-identical and HEAD unchanged);
- only touched paths committed while an untracked `node_modules` exists;
- routing.

Then `task verify`, `task lint`, `task security:quick` and `task env:check`. Live on Gemini with
the fixture template: three scripted edits (add a page, remove a feature, add a DB column with a new
migration and show it), each committed, with the preview running the change. Then
`./scripts/smoke-core.sh`.

## Found while testing live, and fixed before completion

1. **Root-relative links.** The model linked with `<a href="/about">`, which leaves the app's base
   path. Verification now flags a root-relative raw anchor in web, admin and PWA source as an error,
   so the repair round must switch to `next/link`.
2. **A whole file pasted into a REPLACE.** The page ended up containing its original top plus a
   second complete copy, with two default exports, and could not compile. It slipped through
   because `.jsx` cannot be type-checked before dependencies are installed. `structure_errors`
   now flags a duplicate import line, a second default export, and a name declared twice at the
   top level for every touched JS or TS file. The real broken file is kept as a test fixture.
   The edit rules also state that WITH replaces only the FIND text.
3. **Quota.** The daily Google quota for `gemini-3-flash-preview` ran out during testing (429
   "exceeded your current quota"; quotas are per model). `.env` now uses
   `gemini-3.1-flash-lite-preview`. The founder's key is untouched and the file is not committed.
