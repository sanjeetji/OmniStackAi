# R-229 — Python (FastAPI) backend framework adapter

## Requirement

Add the second framework adapter (Brief §42/§43/§46): `PythonBackendAdapter` turns an Application IR
into a real FastAPI backend as a `GeneratedProject`. Paired with the Next.js web adapter (R-227), one
IR now emits **web + backend together** — the multi-target differentiator. Deterministic and offline;
nothing is installed, built, run, or written to disk. New IDs continue after the workbook backlog's
R-010..R-219 (this is R-229). Work is committed directly to `main` (founder consolidated branches).

## Acceptance criteria

- `PythonBackendAdapter` implements `FrameworkAdapter` (target `backend-python`) and returns a
  `GeneratedProject` forming a coherent FastAPI app: `app/main.py`, `app/models.py`, `app/routers/*`,
  `app/config.py`, `requirements.txt`, `README.md`, `.gitignore`, `.env.example`.
- Entities → Pydantic models (types mapped; non-required fields optional with defaults). IR APIs →
  FastAPI routes grouped into routers by first path segment; `{param}` path params become typed
  function args; scaffold body returns 501. `main` includes each router + a health endpoint.
- Safe, deterministically ordered paths; pure function of the IR; standard-library only; no
  install/build/run/disk write.
- Offline tests assert emitted paths + key contents, entity→model mapping, route grouping/params, and
  registry wiring. `task verify` stays green.

## Design notes

- `codegen/backend_python.py`: `PythonBackendAdapter`; maps `FieldType`→Python type, groups APIs by
  first path segment into `app/routers/<segment>.py`, derives valid function names + path-param args.
  Registered via `AdapterRegistry`.

## Model and cost trace

Deterministic; no model call. No cloud key set; cloud_calls zero.
