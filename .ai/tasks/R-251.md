# R-251 — Field validation for Go + numeric min/max

## Requirement

Extend R-250 to the Go backend and add numeric bounds (Brief §9/§26/§27). The `field_validation` parser
gains numeric `min:<n>` / `max:<n>` rules and a `go_validate_tag` helper; the rules now flow into all
three targets — schema, FastAPI Pydantic, and Go models. Go tags are declarative (go-playground
`validate:"..."`); the schema already enforces for both backends at the DB. Additive/offline; examples
unchanged. Committed directly to `main` (R-251).

## Acceptance criteria

- `parse_field_rules` reads `min:<number>` / `max:<number>` (raw literals; non-numeric ignored).
- Schema: numeric INT/FLOAT fields render `CHECK (col >= n)` / `CHECK (col <= n)` (combined with an enum
  `CHECK` if present); string fields never get a numeric check.
- Pydantic: numeric fields render `Field(ge=n, le=n)`; string `max_length` still renders
  `Field(max_length=n)`.
- Go models: `go_validate_tag` builds `max=`/`oneof=`/`gte=`/`lte=`; each field with rules gets a
  `validate:"..."` inside its struct tag; rule-free fields keep the plain `json` tag; example IRs emit no
  validate tags.
- Offline tests cover the numeric parser, schema numeric CHECK, Pydantic ge/le, the `go_validate_tag`
  helper + emitted struct tags, and examples-unaffected.

## Design notes

- `field_validation.py`: `FieldRules` gains `minimum`/`maximum` (raw tokens, `_NUMBER`-validated);
  `go_validate_tag(field, rules)` returns the tag body.
- `schema_sql`: numeric CHECK clauses appended per field. `backend_python`: `ge`/`le` added to the Field
  constraints. `backend_go._models_file`: append ` validate:"..."` inside the struct tag when non-empty.
- No `go.mod` dependency and no `validator.Struct` call this task (declarative tags only) — that
  enforcement is a follow-up.

## Model and cost trace

Deterministic; no model call, no network, no DB connection. cloud_calls zero.
