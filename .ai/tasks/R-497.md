# R-497: Console — Lovable-grade pass (prompt-first home, prose replies, follow-up chips, file search)

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-19
**Completed:** 2026-09-19

## Objective

The founder shared 96 reference screenshots (`~/Desktop/AI_Platform_Screenshots`: Dyad 40,
Emergent 18, Lovable 38) and asked which to follow. After surveying all of them, **Lovable** is
the primary reference: a dark, dense, chat-left *project workspace* whose information
architecture is the closest to a real multi-service product — and the closest to what R-491..
R-496 already built. Dyad contributes the prompt-first home with example chips (its provider
"Needs setup / Ready" cards are already ours since R-495); Emergent contributes nothing we lack
beyond the header credits chip (already present). This task takes the four Lovable/Dyad
patterns that apply to **real** OmniStackAI behavior and leaves out everything that would be a
facade (Cloud database browser, Storage, Emails, Payments, Publish — no backend exists for any
of them).

## Design (each item maps to a specific reference screen)

1. **Prompt-first home** (Dyad `27`, Emergent `05`, Lovable's home): the dashboard's hero becomes
   a real composer — "What do you want to build?", a textarea, three example chips (the same
   real prompts the Studio's empty state uses), and a Build button that navigates to
   `/studio?prompt=<text>`. New client `components/home-composer.tsx`. The account facts and the
   streamed provider card stay below it. Nothing is auto-submitted from the home page itself.
2. **Studio picks up `?prompt=`** (`studio-chat.tsx`): when the Studio mounts with `?prompt=`
   and no `?build=`, it fills the composer and **starts the build once** (a ref guard; the
   existing `sendBuildStream` path, byte-for-byte), then clears the query from the URL — the
   build's own `?build=<id>` replace happens on completion exactly as today. Every reference
   platform submits straight from its home; this is the same real behavior, not a mock.
3. **Prose assistant replies** (Lovable `02`/`09`): assistant messages render as plain prose
   rows with a small brand-mark gutter instead of bubbles; user messages stay as right-aligned
   bubbles; error rows keep their `role="alert"` treatment. Rail type tightens to 13px like the
   reference.
4. **Follow-up suggestion chips** (Lovable `02`: "Add author names and dates", "Wire in real
   logins"): after a successful build or edit, three chips appear under the thread — real,
   generic next edits the delta engine handles (add sign-in, add search and filters, add a
   settings page) — and clicking one fills the composer. They are prompts, not fake progress.
5. **File search in the tree** (Lovable `04`'s "Search code"): a filter input above the tree in
   both the Files and Code tabs narrows the list by substring (the tree is rebuilt from the
   filtered paths); the Code viewer header gains the honest "Read only" label Lovable shows.

Out of scope, deliberately: Lovable's "More" panel sections we have no backend for; Publish/
Share; a project switcher (builds are not listed per user yet); Emergent's Web/Mobile target
tabs (mobile is a hard gate). All recorded so the founder sees exactly what was and wasn't
borrowed.

## Reference survey (how "Lovable" was chosen)

All 96 screenshots were reviewed as labelled contact sheets (12 per sheet, built with Pillow from
900px copies), then the decisive screens at full size. **Lovable** (`Lova-02` workspace, `04`
code, `09` data table, `18` usage, `30` settings): dark, dense (~13px), chat rail left (~30%),
workspace right with a compact view-switcher pill row, prose assistant replies, follow-up
suggestion chips, a "More" panel whose sub-nav is a real product's IA — the closest to a
multi-service product and to what R-491..R-496 already built. **Dyad** (`27` home, `33`
providers, `02` code): light, Electron-app feel, lavender accent; its prompt-first home with
example chips is the one pattern worth taking (its provider cards were already ours since
R-495). **Emergent** (`05` home, `13` preferences): consumer onboarding on sky gradients, a
centered prompt with Web/Mobile tabs, modal settings — least workspace-like; only its header
credits chip applies, and we already have it. Decision recorded in the founder's memory notes
and in the kickoff doc.

**Console gates**: `pnpm run typecheck` and `pnpm run lint` clean on the first run (including the
`react-hooks` rules — the auto-start effect calls `router.replace` and `form.requestSubmit()`,
DOM/router calls, never `setState`); `pnpm run build` → 25 routes, unchanged. **Repo gates**:
`bash scripts/test.sh` passes with the new R-497 block (home composer present and handing off to
`/studio?prompt=`, the Studio's `searchParams.get("prompt")` / `requestSubmit` /
`FOLLOW_UP_PROMPTS` / `autoStarted` markers, the tabs' `FileFilter` / "Search files" / "Read
only", and the guarantee that the home and Studio example prompts are identical strings);
`task verify` → `Ran 3738 tests` / `OK` / `Stage 0 verification passed.`; `task lint`,
`task security:quick`, `task env:check` pass.

**Live smoke** (console rebuilt and restarted on 4321, detached with its own log). Signed in,
`/` → 200 with the prompt-first hero: `<h1>What do you want to build, R484?</h1>` (rendered with
React's `<!-- -->` text separators, which a naive grep misses — checked raw), the composer
(`aria-label="Describe the app to build"`), the Build button, the three chips (Task tracker /
Recipe box / Simple CRM), "Open the Studio →", and below it the unchanged Start building card,
the streamed provider card (Ready) and the account cards; the old hero "Open Studio" button is
gone. `/studio?prompt=hello%20world` → 200 with the composer **server-rendered pre-filled**
(`<textarea>hello world</textarea>`) and the Send button **enabled** (no `disabled` attribute —
first checked wrongly against the button's `disabled:` Tailwind variants, then against the
attribute itself), the empty state still shown, no message yet — correct, because the
auto-start is a client effect and curl never runs it, so **no build was triggered by the smoke**.
`/studio` with no query → composer empty, Send disabled (correct). `/studio?build=5` → 200,
tabs/`aria-busy`/restored header/New app all present, and the composer **not** pre-filled (the
`?prompt=` guard never applies alongside `?build=`). `/settings`, `/fabric` → 200; `/login`
signed in → 307; `/` signed out → 307. **Server log: 0 errors, 0 warnings.**

**Honest limits**: the `?prompt=` auto-start, the follow-up chips (they appear after a completed
build) and the file filter (inside the Files/Code tab panels, which Radix does not render while
inactive) are client behavior that only a browser exercises; they are covered by the typecheck,
the source assertions and the unchanged build path, not by this smoke. The founder is asked to
type a prompt on `http://localhost:4321`, press Build, watch the Studio start it, then try a
follow-up chip and the file search.
