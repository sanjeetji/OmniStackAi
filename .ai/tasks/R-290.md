# R-290 — Optimistic Delete with Rollback in the Generated Collection Screen

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic codegen)

## Objective

The generated collection screen currently waits for the delete round-trip before the row disappears
(`handleDelete`/`handleBatchDelete` → `await remove(...)` → `refetch()`). R-290 makes deletes optimistic:
the affected rows hide immediately and reappear (with the existing error toast) only if the server
rejects. Safe because mutation hooks are deduped (R-288) and the list fetch is race-safe (R-280).
Self-contained in `_collection_screen_page`; no hook/API-client/backend/IR change.

## Requirement

In `nextjs.py` `_collection_screen_page`:

- Add `const [pendingDeleteIds, setPendingDeleteIds] = useState<string[]>([]);` next to `checkedIds`.
- Add a reconcile `useEffect(() => { setPendingDeleteIds((prev) => prev.filter((id) => (data ?? [])
  .some((x: any) => String(x.id) === id))); }, [data]);` (prunes ids once refetch removes them).
- Add `const visibleRows = displayData.filter((item: any) => !pendingDeleteIds.includes(String((item as
  any).id)));` (`displayData = data ?? []` is always defined).
- `handleDelete(id)`: after `confirm`, `setPendingDeleteIds((prev) => [...prev, String(id)]);` then the
  existing success path; in `catch`, `setPendingDeleteIds((prev) => prev.filter((x) => x !== String(id)));`
  before `toast.error`.
- `handleBatchDelete()`: `const ids = checkedIds.map(String);`, add them to pending; in `catch`,
  `setPendingDeleteIds((prev) => prev.filter((x) => !ids.includes(x)));` before the existing error path.
- Row map iterates `visibleRows` instead of `displayData`/`data`; empty-state condition unchanged.

No detail/subcollection delete change; deterministic; description-only-stable.

## Acceptance criteria

1. `pendingDeleteIds` state + reconcile effect on `[data]` present.
2. `handleDelete` optimistic add before `await remove(id)`; catch rolls back before `toast.error`.
3. `handleBatchDelete` optimistic add of checked ids; catch rolls them back.
4. Row map iterates `visibleRows` filtered by `pendingDeleteIds`; success/refetch/checked-clear preserved.
5. Entity without delete emits none; description-only IR changes byte-identical.
6. Focused + related collection tests + full offline gates + both demos pass.
