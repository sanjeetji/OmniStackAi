# R-436: Pinned declarative Solution Pack customization manifests

## Status

DONE (2026-09-14). Seventh differentiating-spine brick; third Solution Pack task.

## Objective

Define the immutable boundary between an R-435 exact-compatible baseline recommendation and future pack
customization. The manifest records only bounded semantic intent: deterministic configuration and AI-delta
changes. It pins the selected pack and compatibility query, but does not load or apply the pack, mutate an
Application IR, generate source, build, or call a model.

## Requirements

- Construct a manifest only from a selected `SolutionPackRecommendation`; reject explicit no-match results.
- Pin the selected pack id, semantic version, canonical Application IR SHA-256, exact domain, required
  capabilities, and required targets.
- Represent each change with frozen enums for source (`configuration` or `ai-delta`), operation
  (`add`, `update`, or `remove`), and semantic area (`project`, `data-model`, `api`, `screen`, `design`, or
  `capability`).
- Require an area-compatible semantic target reference, a bounded summary, and bounded acceptance criteria.
  The manifest schema must not accept file paths, patches, source blobs, commands, model output, or secret
  values.
- Bound the total change count and text sizes, reject duplicates/control characters, and canonicalize change
  order deterministically.
- Provide byte-stable canonical JSON plus strict parsing that rejects unknown/malformed fields and revalidates
  the exact pin against the immutable registry.
- Preserve existing registry, recommendation, ecosystem-plan, Application IR, and generated-output behavior.

## Acceptance Criteria

- Frozen manifest/change objects cannot be mutated.
- Selected blog-CMS recommendations create a manifest pinned exactly to `minimal-blog@1.0.0` and its digest;
  current rideshare/custom no-match recommendations cannot create one.
- Both configuration and AI-delta semantic intents round-trip losslessly through canonical JSON.
- Wrong digest/version/query, invalid target-area pairs, duplicate/excessive changes, malformed JSON, unknown
  keys, invalid enums/types, control characters, and oversized values fail closed with `SolutionPackError`.
- Tests prove the public JSON shape contains declarative metadata only and that no pack/IR mutation or model
  path was added.
- Focused regressions and all repository gates pass with real output and zero model calls.
