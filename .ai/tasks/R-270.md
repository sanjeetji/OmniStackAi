## Goal
Add multi-record bulk selection and batch deletion workflows to generated Next.js collection screens:
- Add row selection state (`checkedIds: string[]`) with `allCurrentIds`, `isAllChecked`, `handleCheckAll`, `handleToggleRow`, and `handleClearSelection`.
- Render a master selection checkbox in the table header `<thead>` with `aria-label="Select all"`, `checked={isAllChecked}`, and `onChange={handleCheckAll}`.
- Render a selection checkbox in each table row `<tbody>` with `aria-label`, `checked={checkedIds.includes((item as any).id)}`, and `onClick={(e) => e.stopPropagation()}` to prevent row selection interference.
- Adjust table `colSpan` for loading and empty state rows to account for the checkbox column (+1).
- Highlight selected table rows with a subtle active background (`#f8fafc`).
- When `checkedIds.length > 0`, conditionally render a contextual Bulk Actions toolbar above the table:
  * Displays `{checkedIds.length} {name/plural} selected`.
  * Includes a "Clear selection" button bound to `handleClearSelection`.
  * When `Op.DELETE` is wired on the entity, includes an active "Delete Selected ({checkedIds.length})" button.
- In `handleBatchDelete`:
  * Prompt user with confirmation dialog: `Are you sure you want to delete {count} {name/plural}?`.
  * Manage `batchDeleting` loading state and disable the action button during execution.
  * Execute parallel deletion across selected records via `Promise.all(checkedIds.map(id => remove(id)))`.
  * Clear selection, trigger `refetch()`, and capture errors in `batchDeleteError` with a dismissible alert banner.
- Clean up `checkedIds` when an individual row is deleted via `handleDelete(id)`.
- Maintain strict diff invariance across `ir.description` modifications.
- 100% offline, zero network calls, zero external dependencies.

## Acceptance Criteria
1. Collection screens declare `checkedIds` state, `isAllChecked`, `handleCheckAll`, and `handleToggleRow`.
2. Table header `<thead>` renders master checkbox with `aria-label="Select all"`.
3. Each table body `<tbody>` row renders a selection checkbox with `e.stopPropagation()`.
4. Table loading and empty state `colSpan` values account for the checkbox column.
5. Contextual Bulk Actions Bar is conditionally rendered when `checkedIds.length > 0`.
6. Bulk Actions Bar renders selection count badge and "Clear selection" button.
7. Bulk Actions Bar renders "Delete Selected" button when `Op.DELETE` is wired.
8. Bulk Actions Bar omits "Delete Selected" button when `Op.DELETE` is absent.
9. Batch delete executes with confirmation prompt, loading indicator, and error capture.
10. Individual `handleDelete(id)` cleans up the deleted ID from `checkedIds`.
11. Strict diff invariance maintained across `ir.description` modifications.
12. Full project generation succeeds across example IRs.
13. `task verify` (614 tests) green; zero network calls; zero external dependencies.
