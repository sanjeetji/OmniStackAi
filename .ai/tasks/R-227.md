# R-227 — Next.js web framework adapter

## Requirement

Implement the first framework adapter (Brief §16/§40/§43/§46): `NextjsWebAdapter` turns an Application
IR into a real Next.js (App Router, TypeScript) project as a `GeneratedProject`. Deterministic and
offline — emitted files are asserted in tests; nothing is installed, built, run, or written to disk.
New IDs continue after the workbook backlog's R-010..R-219 (this is R-227).

## Acceptance criteria

- `NextjsWebAdapter` implements `FrameworkAdapter` (target `nextjs-web`) and returns a
  `GeneratedProject` from an `ApplicationIR` with a correct App Router layout.
- Entities → TypeScript interfaces (field-type mapping); IR APIs → App Router `route.ts` handlers,
  `{param}` → `[param]`, one `route.ts` per route directory exporting each method; each screen → an app
  page; `app/page.tsx` overview lists the app, entities, and screens.
- Emits `package.json`, `tsconfig.json`, `next.config.mjs` (security headers), `README.md`,
  `.gitignore`, `.env.example` (placeholders only); all paths safe and deterministically ordered.
- The `GeneratedFile` path validator is **extended** to allow framework route filename characters
  (`[]()@+`) while still rejecting absolute paths, `..`, backslashes, and control chars.
- Pure function of the IR; standard-library only; no install/build/run/disk write.
- Offline tests assert emitted paths + key contents for a representative IR, dynamic-route mapping,
  entity→interface mapping, and registry wiring. `task verify` stays green.

## Design notes

- `codegen/nextjs.py`: `NextjsWebAdapter`; helpers map `FieldType`→TS, IR path→Next route dir, and
  group APIs by directory into a single `route.ts`. Registered via `AdapterRegistry`.
- Route mapping: `/favourites/drivers/{driverId}` → `app/favourites/drivers/[driverId]/route.ts`.
