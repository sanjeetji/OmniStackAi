## 1. Goal
Add child item deletion, confirmation prompts, loading/disabled states, error feedback alerts, and automatic subcollection refetching to master-detail views in generated Next.js screens:
- In `_subcollections_for_parent`: Detect when `child_entity` supports `Op.DELETE` (via `wire_endpoint` or path-based DELETE endpoint matching) and set `can_delete = True` on `SubcollectionInfo`.
- In `_collection_screen_page`:
  - Automatically import `useDelete<Child>` from `"../lib/hooks"` for each deletable subcollection, avoiding duplicate imports if the parent entity already imported `useDelete<Parent>`.
  - Instantiate delete hooks with remove, loading, and error states: `const { remove: remove<Child>, loading: deleting<Child>, error: delete<Child>Error } = useDelete<Child>();`.
  - Emit `handleDelete<Child>` handler with confirmation prompt (`confirm("Are you sure you want to delete this <Child>?")`), try/catch block, and automatic subcollection refetch (`<subcol>.refetch()`).
  - Render styled mutation error feedback banner (`{delete<Child>Error && ...}`) if a delete request fails.
  - Render an accessible Delete button on each child item card with `e.stopPropagation()`, disabled state during mutation (`disabled={deleting<Child>}`), and text `{deleting<Child> ? "Deleting..." : "Delete"}`.
- In `_detail_screen_page`: Mirror the identical child deletion hooks, handlers, error feedback banners, and child card Delete buttons in dedicated detail screens.
- Clean fallback safety: subcollections whose child entity lacks `Op.DELETE` emit zero deletion code, and entities without subcollections emit zero subcollection code.
- Strict diff invariance: zero references to `ir.description`, preventing drift in showcase snapshot diffs.
- Fully offline, 0 network, 0 external Python dependencies.
