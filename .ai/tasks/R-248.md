# R-248 — Application IR fixtures + honest migrations/0002_seed.sql

## Requirement

Close the seed-data gap honestly (Brief §26/§27): the founder declares explicit seed rows in the
Application IR (a new `Fixture` record: `entity` + `rows` of column→JSON value), and the platform emits
a deterministic `migrations/0002_seed.sql` containing exactly those values — never inventing,
defaulting, or guessing. Emitted only when the IR has fixtures and `database_strategy=postgres`, next to
the R-238 `0001_init.sql`. Pure/deterministic/offline; nothing connects to or runs a database. First
additive IR change since R-243 (default `()`, no schema-version bump). Committed directly to `main`.

## Acceptance criteria

- `ApplicationIR.fixtures: tuple[Fixture, ...]`; `Fixture(entity, rows)` validated in `__post_init__`
  (entity name; non-empty tuple of non-empty dicts; identifier columns; JSON/control-free values);
  round-trips via `to_dict`/`from_dict`; `normalize_ir` sorts+preserves fixtures.
- `validate_ir` → ERROR `unknown_fixture_entity` / `unknown_fixture_column`; WARNING
  `fixture_missing_required` (required column, other than `id`, missing from a row) — `has_errors` false.
- `render_postgres_seed(ir)` → deterministic `INSERT INTO <table> (<cols sorted>) VALUES (<literals>);`
  using only the row's columns; correct quoting (single quotes doubled, bool→TRUE/FALSE, None→NULL,
  dict/list→`'…'::jsonb`); `""` when no fixtures.
- Both backends emit `migrations/0002_seed.sql` iff fixtures + postgres; fixture-free/non-postgres IRs
  get none; `0001_init.sql` unchanged.
- Offline tests cover literal rendering, INSERT shape/order/FK column, gating, validation, round-trip.

## Design notes

- `ir.py`: `_check_fixture_value` + `Fixture` record; add `fixtures` field to `ApplicationIR` (before
  `schema_version`), wire into the validation loop, `to_dict`, `from_dict`. Export `Fixture`.
- `validate.py`: fixture cross-ref checks; **add `fixtures=` to `normalize_ir`** (else dropped).
- `codegen/seed_sql.py`: `render_postgres_seed` + `_sql_literal` (the codebase's first SQL-literal
  quoter). Both adapters append the seed file inside the existing `if has_db:` block.
- `examples.py`: add fixtures to `minimal-blog` (two Post rows + a Comment with `post_id`).
  `builder-demo.sh` prints `0002_seed.sql` when present.

## Model and cost trace

Deterministic; no model call, no network, no DB connection. cloud_calls zero.
