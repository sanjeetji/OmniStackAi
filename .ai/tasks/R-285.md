# R-285 — Server-Side Subcollection Filter Wiring in Generated Next.js Screens

**Status:** in progress
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic code generation; 0 model calls)

## Objective

Connect generated Next.js subcollection boolean/enum controls to R-284's server-side `LIST_BY` query
contract. Filtering must happen before pagination in both parent collection master-detail and dedicated
parent detail screens.

## Scope and impact

- Extend only the existing Next.js hook and subcollection-control generators plus focused offline tests.
- Reuse IR-derived filter field detection; no Application IR or backend contract change.
- No dependency, database connection, external request, model call, infrastructure, or native/mobile work.

## Acceptance criteria

1. Filterable `useList<Child>By<Parent>` hooks expose typed `filters`, `setFilter`, and `clearFilters`.
2. Active allowlisted filters flatten into the existing LIST_BY request params; changes reset pagination.
3. Both subcollection UI sites render boolean pills, enum selects, active count, Reset, and filtered-empty recovery.
4. Components render server-returned data directly and contain no page-local child filtering.
5. Non-filterable subcollections retain their existing hook/control output; description-only IR changes remain byte-identical.
6. Focused tests and all recorded offline gates pass.
