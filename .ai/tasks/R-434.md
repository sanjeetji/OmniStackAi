# R-434: Versioned baseline Solution Pack registry

## Status

DONE (2026-09-14). Fifth differentiating-spine brick; first Solution Pack task.

## Objective

Implement the smallest honest foundation for Master Architecture Specification section 5 / Stream C.
Register the two Application IR examples that are already heavily exercised by the offline suite and builder
demos as immutable, versioned Solution Pack descriptors. Reuse those IR builders directly, pin their
canonical contents and assembled targets, and provide deterministic validation and selection. Do not copy a
generated repository, claim unexecuted verification, or introduce AI-delta generation yet.

## Requirements

- Add a stdlib-only `solution_packs` package with a frozen `SolutionPack` descriptor containing a stable pack
  id, semantic version, display metadata, domain tags, capability tags, existing example-IR reference,
  canonical IR SHA-256, and exact assembled target tuple.
- Add an immutable `SolutionPackRegistry`. It must reject malformed descriptors, duplicate id/version pairs,
  missing example references, invalid IRs, canonical-digest drift, target drift, and missing verify plans.
- Register `minimal-blog` and `rideshare-favourites` at version `1.0.0`, referencing
  `application_ir.examples` rather than restating their IR or checking in generated skeleton files.
- Provide deterministic `get`, `select`, `load_ir`, collection, and JSON-safe serialization APIs. Selection
  requires an exact domain plus a required-capability subset, prefers the newest valid semantic version, and
  returns `None` when no pack honestly matches.
- Add a deterministic CLI/task that lists all registered packs or prints the selected pack for a domain and
  optional capabilities. It performs no build, install, model, network, database, or runtime action.
- Python 3.13 standard library only; no mutable global state.

## Acceptance Criteria

- Both baseline packs load fresh, `validate_ir`-clean Application IRs whose canonical digests and project
  target lists exactly match their descriptors; every declared target has an existing verify ladder.
- `blog-cms` selects `minimal-blog`; `rideshare` + `favourites` selects `rideshare-favourites`; unsupported
  domains/capabilities return `None`; repeated calls and JSON serialization are byte-stable.
- A synthetic newer version wins deterministic selection, while duplicate versions and every drift/invalid
  case fail closed with a bounded `SolutionPackError`.
- Focused tests and all repository gates pass with real output and zero model calls.
