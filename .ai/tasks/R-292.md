# R-292 — Loading Skeletons for Generated Next.js Screens

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic codegen)

## Objective

Replace the plain "Loading..." text in the generated screens' data-loading states with layout-preserving
skeleton placeholders (gray rounded bars) — a perceived-performance UX improvement. Scope: the collection
table loading state (`_collection_screen_page`), the subcollection (master-detail) list loading state
(both render sites), and the detail-screen main loading state (`_detail_screen_page`). Static inline-styled
skeletons — no CSS `@keyframes`, no new component/file, no dependency.

## Requirement

- Collection table loading: replace the single `Loading <plural>...` cell with a spanning cell that maps
  ~5 skeleton bars (`<div style={{ height: 14, background: "#e2e8f0", borderRadius: 4, margin: "10px 0",
  opacity: 1 - i * 0.15 }} />`).
- Subcollection list loading (both sites — one `replace_all`): replace the `Loading <child>...` div with a
  flex column mapping ~3 skeleton blocks (`height: 44, background: "#f1f5f9"`).
- Detail main loading: replace the `Loading <name>...` div with a flex column mapping ~4 skeleton lines of
  varying width (`height: 14, background: "#e2e8f0", width: `${88 - i * 14}%``).
- Refresh-button "Loading..." labels, empty/error states, and data rendering are unchanged. No
  hook/API-client/backend/IR change; deterministic; description-only-stable.

## Acceptance criteria

1. Collection loading maps skeleton bars; the `Loading <plural>... ` cell text is gone.
2. Subcollection loading (both sites) maps skeleton blocks; the `Loading <child>...` text is gone.
3. Detail main loading maps skeleton lines; the `Loading <name>...` text is gone.
4. Description-only IR changes remain byte-identical; both example projects still generate.
5. Focused + related screen tests + full offline gates + both demos pass.
