# R-243 — Per-endpoint role enforcement

## Requirement

Add authorization on top of the R-242 JWT authentication (Brief §9/§27/§55): extend the Application IR
`ApiEndpoint` with an optional `required_roles` (role ids), validate it, and generate a per-endpoint
role check that returns **403** when the verified token's `roles` claim includes none of the required
roles. First additive change to the IR itself (`required_roles` defaults to `()` — backward compatible,
no schema-version bump). Deterministic and offline; nothing runs. Committed directly to `main` (R-243).

## Acceptance criteria

- `ApiEndpoint.required_roles` (tuple of role ids), validated in `__post_init__` (a non-empty value
  requires `auth=true`) and serialized via `to_dict`/`from_dict`; `validate_ir` errors on an undeclared
  role.
- Python emits `require_roles(*required)` in `app/auth.py` (verify the token, then require any role,
  else 403); routes with `required_roles` declare `dependencies=[Depends(require_roles("..."))]`.
- Go emits `RequireRoles(next, required...)` on a shared `verifyToken` + `hasAnyRole` (403 when no
  required role); `main.go` wraps role-gated endpoints with `handlers.RequireRoles(target, "...")`.
- Endpoints without `required_roles` keep the R-241/R-242 auth guard; output is byte-stable; nothing
  runs.
- Offline tests cover the IR field (serialize, auth-implication, unknown-role error) and Python/Go role
  wiring.

## Design notes

- `ir.py`: `ApiEndpoint` gains `required_roles: tuple[str, ...] = ()` (validated with `_str_tuple`;
  non-empty implies `auth`), added to `to_dict` and `from_dict`. `validate.py`: role-existence check.
  `normalize_ir` is unchanged (it reuses the `ApiEndpoint` objects).
- `auth_guard.py`: Python `require_roles` dependency factory; Go refactored to `verifyToken` (returns
  claims) + `RequireAuth`/`RequireRoles`/`hasAnyRole`.
- `backend_python.py` / `backend_go.py`: wire `require_roles` / `RequireRoles` when `required_roles` is
  set; keep `require_auth` / `RequireAuth` otherwise.
