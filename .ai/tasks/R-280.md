# R-280 — Deep-Linked Collection List State + Debounced, Race-Safe Search

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Continue the generated Next.js web-app trajectory (R-263→R-279) with real, enforced runtime behavior the
founder chose ("best, optimised, futuristic"). Two tightly-coupled improvements to the **top-level
collection screen** and its `useList<Entities>` hook — one surface, `nextjs.py`
`_collection_screen_page` + `_hooks_file`:

1. **Deep-link the list state (A).** The `useList<Entities>` hook hydrates `sort/order/q/page/pageSize`
   from `window.location.search` once on mount and reflects the current params back to the URL via
   `new URL(window.location.href)` + `window.history.replaceState` (writing only non-default values),
   reusing the R-276 detail-screen deep-link pattern. Refresh / bookmark / share restore the exact view.
2. **Debounced, race-safe search (C).** The collection search input commits to `setSearch` after a fixed
   300ms debounce (`setTimeout`/`clearTimeout`) instead of on every keystroke, and `useList.refetch`
   creates an `AbortController` per call (aborts the previous, passes `signal` to the API, ignores
   aborted/stale responses, aborts on unmount). The API client already forwards `signal` (ApiOptions
   extends RequestInit), so no `lib/api.ts` change is needed.

The `useList<Child>By<Parent>` subcollection hook and subcollection UI controls are intentionally out of
scope (a future candidate). Offline/deterministic; no new IR field; no npm dep; `"use client"` preserved;
strict diff invariance across `ir.description`.

## Acceptance criteria

1. `apps/web/lib/hooks.ts` `useList<Plural>` gains a URL-hydrate `useEffect` (parses `URLSearchParams`
   over `window.location.search`, guards `typeof window`, runs once) and a URL-sync `useEffect`
   (`replaceState` with `sort/order/q/page/pageSize`, only non-defaults).
2. `useList<Plural>.refetch` uses an `AbortController` (abort previous, `signal` passed to
   `api.list<Plural>WithCount`, `AbortError`/`signal.aborted` guarded, no state writes on abort) and
   aborts in-flight on unmount; `useRef` imported.
3. Collection `page.tsx` debounces search (`setTimeout` + `clearTimeout`, delay `300`), `onChange` only
   updates the local `searchInput`, the form submit still searches immediately, and the hydrated `q` is
   reflected back into the input; `useEffect` imported.
4. Strict diff invariance: changing only `ir.description` yields byte-identical `hooks.ts` and collection
   `page.tsx`.
5. `task verify` (new `test_collection_deeplink_state.py`), `task lint`, `task security:quick`, and both
   `builder:demo`s pass.

## Design notes

- `_hooks_file`: add `useRef` to the react import; wrap `refetch` in AbortController logic; add the
  hydrate + sync effects before the hook `return`. Only non-default params are written to the URL
  (`sort !== "id"`, `order !== "asc"`, `page > 1`, `pageSize !== 100`, non-empty `q`) to keep URLs clean
  and preserve diff-invariance.
- `_collection_screen_page`: always import `useEffect`; after the `searchInput` state, add a debounce
  effect (guarded `searchInput !== (params.q ?? "")` so it never clobbers a hydrated page offset) and a
  sync effect (`setSearchInput(params.q ?? "")` on `params.q`); drop the immediate `setSearch` in the
  input `onChange`.
