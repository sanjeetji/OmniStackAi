# R-435: Exact-compatible Solution Pack recommendations in ecosystem planning

## Status

DONE (2026-09-14). Sixth differentiating-spine brick; second Solution Pack task.

## Objective

Connect the R-434 immutable baseline registry to R-431/R-433 ecosystem planning as transparent metadata,
without applying a pack or changing any generated Application IR/repository. Compatibility is factual:
exact domain plus caller-required capabilities and the target set derived from the already planned apps.

## Requirements

- Extend registry selection with an optional required-target tuple. A candidate must contain every required
  target in addition to satisfying the existing exact-domain/capability rule.
- Add a frozen, JSON-safe recommendation value that records the canonical query and either the selected
  pack's id/version/digest/targets or an explicit no-exact-match result.
- Derive one canonical required-target tuple from the project plans of all apps already present in an
  `EcosystemPlan`; do not infer semantic capabilities from prose, entities, or surface names.
- Attach the recommendation to the plan and expose it in `to_dict()` and the deterministic plan CLI.
- A current blog-cms plan (Next.js + Python) must recommend `minimal-blog@1.0.0`. A current rideshare plan
  (Next.js + Python) must not recommend the Go-backed rideshare baseline; direct registry selection using
  Next.js + Go targets must still select it.
- Unsupported/custom domains return no match. No pack is loaded, applied, merged, or built by this task.
- Preserve deterministic ordering and backwards-compatible registry calls; Python 3.13 standard library only.

## Acceptance Criteria

- Recommendation objects are immutable, bounded, internally consistent, and byte-stable under JSON
  serialization.
- Target incompatibility fails closed rather than being described as a recommendation.
- Existing ecosystem IRs, entity/write scoping, roles, APIs, screens, builders, and both baseline packs are
  unchanged.
- Focused regressions and every repository gate pass with real output and zero model calls.

## Allowed Paths

The paths listed in `.ai/CURRENT_TASK.yaml` are authoritative.
