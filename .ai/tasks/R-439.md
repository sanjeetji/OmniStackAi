## Objective
Tenth brick of the differentiating spine and sixth Solution Pack task. Safely apply validated
`AIDeltaProposal` objects to a fresh pinned Solution Pack `ApplicationIR`, combining allowlisted
configuration updates and verified AI-delta additions into a single, unified `validate_ir`-clean derived
`ApplicationIR` with transparent, byte-stable provenance tracking. When no proposal is provided,
existing configuration application behavior is strictly preserved.

## Forbidden Changes
- Do not modify or stage the untracked `.claude/` directory
- Do not make model calls, network requests, or database queries during proposal application
- Do not mutate registered baseline Solution Packs in the registry
- Do not allow collisions between proposed entities, APIs, or screens and the base IR
- Do not permit broken cross-references (e.g. relations pointing to non-existent entities)
- Do not output a derived IR that fails `validate_ir`
- Do not generate source code or build repositories in this task (reserved for subsequent tasks)

## Acceptance Criteria
1. `SolutionPackApplicationResult` includes `applied_ai_delta_change_ids: tuple[str, ...] = ()` alongside existing configuration IDs, with all ID sets strictly partitioned, sorted, and unique.
2. `apply_solution_pack_manifest(manifest, *, proposal=None, registry=...)` accepts an optional `proposal: AIDeltaProposal | None = None`.
3. When `proposal is None`, behavior is strictly backward-compatible with R-437 (configuration applied, all AI deltas marked unapplied, `applied_ai_delta_change_ids` empty).
4. When `proposal` is provided:
   - Revalidates pins: `proposal.pack_id`, `proposal.pack_version`, and `proposal.base_ir_sha256` must match the manifest.
   - Revalidates change IDs: all `proposal.addressed_change_ids` must correspond to `ai-delta` changes in `manifest.changes`.
   - Revalidates collisions: proposed entity names, API endpoints, and screen IDs must not collide with the base IR.
   - Revalidates relation references: proposed entity relations must reference entities present in the base IR or proposal.
   - Merges entities, APIs, and screens immutably into the derived IR.
   - Ensures the derived IR is `validate_ir`-clean; any error fails closed with `SolutionPackError`.
   - Records `applied_ai_delta_change_ids` and remaining `unapplied_ai_delta_change_ids` in the result provenance.
5. Repeated application is byte-stable and deterministic.
6. Baseline registries and IRs remain completely unmutated.
