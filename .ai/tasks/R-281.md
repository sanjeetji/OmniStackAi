# R-281 — Pagination, Sort & Search Controls on Subcollection Master-Detail Lists

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Close the survey-identified **gap B**: the generated subcollection master-detail lists rendered only
`{sub.data.map(...)}` — no controls — even though the backend subcollection endpoints and the generated
`useList<Child>By<Parent>` hook already expose the full `limit/offset/sort/order/q` control surface
(`setSearch`/`setSort`/`setPage`/`page`/`totalPages`/`total`). Wire those controls into the UI. The
founder chose this offline option ("R-281 offline only").

Two small shared helpers in `nextjs.py`, called from **both** subcollection render sites (the collection
master-detail block in `_collection_screen_page` and the detail-screen block in `_detail_screen_page`,
which are byte-identical at the insertion points):

1. `_subcol_controls(sub, s_var)` — an **uncontrolled** search `<form>` (`defaultValue={…params.q}` +
   `new FormData(...).get("q")` on submit → `setSearch`) and a sort `<select>` (`id` + the subcollection's
   display fields, both directions → `setSort`). No new component state.
2. `_subcol_pagination(s_var)` — a **Prev / "Page X of Y (N total)" / Next** footer driven by
   `page`/`totalPages`/`total`/`setPage`, disabled at bounds and while loading.

Submit-based search (not per-keystroke) avoids a fetch storm, so the subcollection hook internals are
left unchanged (no abort/debounce added this task). No new IR field, no npm dependency, `"use client"`
preserved, strict diff invariance across `ir.description`.

## Acceptance criteria

1. Both the collection master-detail page and the detail page render, per subcollection: the search form,
   the sort select (`id` + display-field options in asc/desc), and the pagination footer — all bound to
   the `<child>Subcol` hook.
2. Entities without a parent→child subcollection emit no subcollection controls.
3. The subcollection search input is uncontrolled (no `useState`-backed sub-search state).
4. Strict diff invariance: changing only `ir.description` yields byte-identical list and detail pages.
5. `task verify` (new `test_subcollection_list_controls.py`), `task lint`, `task security:quick`, and both
   `builder:demo`s pass.

## Design notes

- Helpers added after `_subcollections_for_parent`; both take the per-subcollection `s_var`
  (`<child.lower()>sSubcol`) and emit fixed 16-space-indented JSX lines, so the same call site works in
  both render functions (identical structure/indentation).
- Insertion via `replace_all` on the two shared anchor blocks (empty-state open; list-close), so both the
  collection and detail sites receive the identical controls + pagination.
- Sort options come from `["id"] + sub.display_fields` (display fields already exclude `id` and the FK).
