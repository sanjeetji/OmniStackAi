# R-492: Console — auth screens + app shell (nav, user menu, skip-link, 404, dashboard)

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-19
**Completed:** 2026-09-19

## Objective

Second task of the Console UI overhaul (R-491..R-496). R-491 laid the stack (Tailwind v4 +
shadcn/ui on Radix + Geist + `next-themes`) without changing a single screen. This task is the
first one a user *sees*: the sign-in and create-account screens, a shared application shell
(brand, top navigation with current-page state, user menu with sign-out, skip-to-content link),
a branded 404, and a real home/dashboard in place of the three-link list. Everything is built on
the vendored shadcn primitives and Lucide, applying the loaded `redesign-existing-projects`
audit — real inline form validation and loading states, hover/active/focus on every control,
sentence case, no AI-cliché copy, no fabricated data.

## Design (verified against the real code and Next 16's bundled docs before writing any code)

- **No route-group move.** Eight earlier `scripts/test.sh` contract blocks (R-470, R-475, R-482,
  …) assert the current literal paths — `app/page.tsx`, `app/login/page.tsx`,
  `app/studio/layout.tsx` (and that it contains `getCurrentUser`), `app/settings/layout.tsx`,
  `app/studio/studio-icons.tsx`. Moving screens into `app/(app)/` and `app/(auth)/` would break
  all of them. Instead the shell is a shared server component, `components/app-shell.tsx`, that
  every authenticated layout/page wraps itself in; the existing per-route auth gates stay exactly
  where they are. Same visible result, zero contract churn.
- **`AppShell`** (server): a skip link (`href="#main"`, visually hidden until focused), a sticky
  56px header — brand mark + wordmark linking home, `AppNav`, and either `UserMenu` (signed in) or
  Sign in / Create account buttons (signed out — `/fabric` is public today and stays public) —
  and `<main id="main">` sized like the legacy `.studio-main` (1180px, same padding) so the
  untouched Studio grid (`.chat-rail: calc(100dvh - 160px)`) still fits until R-493 rebuilds it.
- **`AppNav`** (client, `usePathname`): Home, Studio, Settings, Fabric with Lucide icons;
  the current section gets `aria-current="page"` and a distinct style (the audit's "no indication
  of current page" item). Labels hide below `sm`, icons stay.
- **`UserMenu`** (client, shadcn `DropdownMenu` — a real keyboard-navigable, focus-managed menu):
  rounded-square initials avatar + name; content shows name/email, plan and credit balance
  (`tabular-nums`), links to Settings and Fabric, and a destructive Sign out item with a loading
  state. Sign-out logic moves here verbatim from `app/logout-button.tsx` (POST `/api/auth/logout`
  → `/login` + `router.refresh()`), and that file is deleted — its three importers are all
  rewritten by this task.
- **Auth screens**: `app/login/page.tsx` / `app/register/page.tsx` become server components
  (so they can carry `metadata` and redirect an already-signed-in user to `/`) rendering
  `components/auth-screen.tsx` — a split layout: a brand panel (grain, one soft brand glow, a
  display headline and three *true* product statements: real exportable code, live preview +
  multi-turn edits, local model free / cloud models spend credits) beside a centered card with
  the form; the panel collapses to a compact brand row on small screens. The forms
  (`login-form.tsx`, `register-form.tsx`, client) get real client-side validation mirroring the
  server's own limits (`app/api/auth/register/route.ts` + the control-plane: email format,
  name required ≤200, password 8–128), inline per-field errors wired with `aria-invalid` +
  `aria-describedby`, cleared on edit; a `role="alert"` banner for the server's error (its
  message shown verbatim, first letter capitalized); a spinner + disabled submit while
  in flight; a show/hide password toggle with `aria-pressed`. `noValidate` on the form so the
  same validation runs everywhere rather than the browser's inconsistent bubbles.
- **Home/dashboard** (`app/page.tsx`): greeting + primary "Open Studio" action; an asymmetric
  two-column layout (not three equal cards): a "Start building" card with the honest three-step
  loop (describe → build → preview & edit) on the left, account facts on the right — plan,
  credits (`tabular-nums`), role, BYOK — plus a live "Model provider" card reusing the existing
  `getProviderStatus()` client exactly as `/settings` does (Ready / Not ready / unreachable, with
  a link to Settings). No "recent projects" list: the Studio server has no per-user build history
  endpoint, so none is invented.
- **404** (`app/not-found.tsx`, per Next 16's `not-found.js` convention — read from the bundled
  docs: the root file also serves every unmatched URL): brand mark, "This page doesn't exist",
  Go home / Open Studio. Renders inside the root layout without the shell (auth state is unknown
  there).
- **Metadata**: page titles now use the root template from R-491 (`%s · OmniStackAI`), so the
  three pages that hard-coded "… — OmniStackAI Console" are trimmed to "Studio", "Settings",
  "Model Fabric"; Sign in / Create account / Page not found are added.
- **`/fabric`**: wrapped in the shell (user optional); its own "← Back" button and outer `.wrap`
  go away because the nav now covers navigation. The page body itself is R-495's job.
- **CSS**: new components use Tailwind utilities on the R-491 tokens; `globals.css` is only
  touched if a real gap appears. Legacy `.studio-topbar*` rules become dead and are removed with
  the rest of the legacy sheet in R-496.

**Two things worth knowing that the smoke surfaced** (neither a bug): React 19 serializes
`noValidate`, `autoComplete` and `maxLength` into SSR HTML with their camelCase names (HTML
attribute names are case-insensitive, so browsers honor them) — a naive lowercase grep reports
them missing; and React inserts `<!-- -->` between adjacent text nodes, so "Signed in as
{email}" is not one contiguous string in the markup. Both were verified by dumping the raw tags
rather than trusting the first grep. **No browser-automation tool exists in this session**: the
split auth layout, the sticky translucent header, the dropdown's open state and the focus rings
are verified by structure, not pixels — the founder is asked to eyeball `http://localhost:4321`
(sign in, open the account menu, tab to the skip link, try a bad password) before R-493.
