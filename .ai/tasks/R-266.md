## 1. Goal
Connect generated Next.js screens to existing backend update handlers (`PUT`/`PATCH`) and typed React mutation hooks (`useUpdate<Entity>` and `use<Entity>(id)`):
- In `_form_screen_page`: Support dual Create and Edit modes when `Op.UPDATE` is wired. Read `editId` via `useSearchParams().get("id")`, fetch existing item with `use<Entity>(editId)`, prefill `formData` via `useEffect`, submit using `update(editId, formData)` in edit mode vs `create(formData)` in create mode, and adapt headers, buttons, and success banners dynamically.
- In `_collection_screen_page`: Render an "Edit" action link in the master table pointing to `/{formScreen.id}?id=${item.id}` with `e.stopPropagation()` when `Op.UPDATE in ops` and `form_screen is not None`.
- In subcollection master-detail view: Render `+ New <Child>` link pointing to `/{childForm.id}?{foreign_key_param}=${selectedId}` when a complementary form screen exists for the child entity.
- Preserve diff invariance across `ir.description` changes and fallback safety for entities without `Op.UPDATE` (e.g. `minimal-blog` Post).
- Fully offline, 0 network, 0 external Python dependencies.
