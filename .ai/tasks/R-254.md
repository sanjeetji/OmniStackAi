# R-254 — Field-level validation error bodies (structured JSON errors instead of flat string)

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L2  

## Objective

Replace the flat "validation_failed" string with a structured JSON error body that names which
field failed which rule, so clients (web/mobile) can surface actionable per-field error messages.
Go validateStruct in internal/handlers/validate.go now iterates validator.ValidationErrors,
builds per-field error objects (field, rule, message), and returns 400 with {"errors":[...]} via writeJSON.

## Acceptance criteria

1. Go validateStruct returns a JSON body `{"errors":[{"field":"<name>","rule":"<tag>","message":"<text>"}]}`
   via `writeJSON(w, http.StatusBadRequest, ...)` instead of `http.Error` with a flat string.
2. Go validate.go imports `"fmt"` and uses `fmt.Sprintf` for violation messages.
3. Old flat string `"validation_failed"` is eliminated.
4. Wired CREATE and UPDATE handlers in `backend_go.py` use `if !validateStruct(w, m) { return }`.
5. Valid payloads still pass through to store.Create and store.Update.
6. Rule-free projects: `validate.go` is not emitted (unchanged gate); no `validateStruct` added.
7. Example IRs (`minimal-blog`, `rideshare-favourites`): unchanged.
8. `task verify` green; 398 tests pass (24 new); 0 network calls.
