## Objective

Founder-requested, researched before design (three parallel research passes: competitor
architecture, per-user isolation scoping, deploy/stack scope — see conversation record). Real,
live streaming of build progress from the agent-engine through the Go control-plane, replacing the
one-shot "Building…" blocking wait with genuine incremental progress — the first piece of the
"complete one by one all" post-roadmap work, prioritized first per the founder's own stated order
(streaming, then properly scope multi-tenant isolation).

Scoped as **backend only** (agent-engine SSE emission + Go relay, curl-verified against the real
running stack) — console UI consumption is R-485, a fast-follow. This mirrors this session's own
proven pattern (R-476 backend → R-477 UI; R-478 backend → R-479 UI): each half independently
gated, tested, and live-verified before the next depends on it.

## Design (verified by direct source read before writing any code)

- **Streaming already exists at the model_gateway layer, unused above it.**
  `model_gateway/contracts.py`'s `ModelProvider` Protocol already declares
  `stream(request) -> AsyncIterator[StreamEvent]` alongside `generate()`; every real provider
  (cloud HTTP providers via SSE parsing, Ollama via NDJSON) already implements it. `_build()`'s
  entire call chain (`build_app_from_prompt` → `generate_ir` → `provider.generate()`) never once
  calls `.stream()` — the gap this task closes is entirely in the intake/build layer, not the
  model layer.
- **New, additive streaming twins — the existing non-streaming functions are untouched**:
  `intake/nl_to_ir.py` gains `generate_ir_stream()` (an async generator yielding raw text deltas
  from `provider.stream()`, then the final `IntakeResult`). `intake/build_app.py` gains
  `build_app_from_prompt_stream()` (streams the same deltas through, then does the existing
  `build_app_from_ir()`'s pure-disk work — assemble + git commit — synchronously once the IR
  completes, since that part is fast and not usefully streamable token-by-token).
- **`studio/live_serve.py` gains `_build_stream()`** — an async generator mirroring `_build()`'s
  **plain-prompt-only** branch (matching the exact scope precedent `_edit()`/R-476 already set:
  Solution Pack, Ecosystem, and `hybrid_ui=True` builds are explicitly out of scope for streaming
  today, reported as a clean, honest rejection rather than silently falling back to blocking or
  guessing). Yields `{"phase": "generating_ir", "delta": "..."}` events as text streams in, then a
  final `{"phase": "done", ...}` event carrying the exact same payload shape `_build()` already
  returns (including history recording, turn recording, and preview handling — reusing that logic
  unchanged, not duplicating it).
- **New `POST /api/build/stream` route in `studio/server.py`**: reads the JSON body, rejects
  unsupported build kinds with a normal `400` *before* any streaming starts (clean, simple — no
  half-open SSE connection for a request that was never going to stream), then switches to SSE:
  `Content-Type: text/event-stream`, manual `self.wfile.write()` + `flush()` per event (confirmed
  architecturally sound with zero new dependencies — stdlib `http.server`'s `HTTP/1.0` default with
  no `Content-Length` header streams raw bytes until connection close). Driven via a small
  `asyncio.run()`-wrapped drain loop, the same "sync handler, async model calls via asyncio.run()"
  pattern `_edit()` already uses.
  - **Bug found and fixed by the test suite itself**: the route initially sent
    `Connection: keep-alive`. `BaseHTTPRequestHandler.send_header` special-cases that literal value
    to set `self.close_connection = False` — since this response has no `Content-Length`/chunked
    framing, the client's only signal that the SSE body has ended is the socket closing; with
    keep-alive set, the server never closes it and every real client hangs forever waiting for more
    bytes. The first HTTP-level streaming test (`test_stream_success_yields_events_in_order`) caught
    this immediately via a real client-side socket timeout. Fixed by sending `Connection: close`
    instead — honest about the fact this response is not reusable for a second request.
- **Go control-plane**: new `POST /jobs/build/stream` route. Because crediting requires the final
  event's `usage` data (only known once the stream completes), the relay cannot inject
  `credits_spent`/`credit_balance` into an already-sent SSE frame — instead it relays every
  upstream SSE frame verbatim via `http.Flusher` as it arrives, then appends one **trailing**
  `event: credits\ndata: {...}\n\n` frame after the upstream `"phase": "done"` event, computed the
  same way `proxyAndDebit` already does. No credit debit occurs for build kinds the agent-engine
  itself already rejected (the 400 happens before any SSE framing begins, proxied through
  unchanged).

## Scope boundary

- **Plain-prompt, non-`hybrid_ui` builds only.** Solution Pack, Ecosystem, and hybrid-UI-synthesis
  builds keep using the existing non-streaming `POST /jobs/build`/`POST /api/build` — both remain
  completely unchanged, still the only path for those build kinds.
- **Build only, not edit.** `_edit()`/`POST /jobs/build/{id}/edit` streaming is a natural, separate
  fast-follow once this pattern is proven — not attempted here to keep this task's diff reviewable.
- **No console UI changes** — R-485's job. This task is fully verified via real `curl` SSE sessions
  against the real running stack, not through the browser.
- **UI-synthesis streaming** (per-file model-written screens) is not attempted — only the IR
  generation call (the single largest, slowest LLM call in a build) streams in this task.

## Gates & Evidence

**Two real bugs found and fixed by this task's own tests/live smoke — not fabricated, not glossed
over:**

1. **`Connection: keep-alive` on the new SSE route hung every real client.** Caught by the very
   first HTTP-level test (`test_stream_success_yields_events_in_order`) via a real client socket
   timeout. Root cause: `BaseHTTPRequestHandler.send_header` special-cases the literal value
   `"keep-alive"` to set `self.close_connection = False`; since this response has no
   `Content-Length`/chunked framing, the client's only signal the body ended is the socket closing.
   Fixed by sending `Connection: close` instead (`studio/server.py`).
2. **`RecordingProvider` (the wrapper every real build call goes through for usage/cost tracking)
   had no `.stream()` method.** Not caught by any automated test (every test mocks
   `resolve_generation_provider_from_env` and hands `_build_stream()` a raw stub provider directly,
   bypassing the real `RecordingProvider` wrapping that happens in production) — caught by the
   task's own required live `curl -N` smoke test, which failed immediately with
   `'RecordingProvider' object has no attribute 'stream'`. Fixed by adding
   `RecordingProvider.stream()` (`model_gateway/recording.py`), mirroring `generate()`'s own
   success/failure ledger-recording shape, plus 4 new tests in `test_recording_provider.py`
   (`recording.py`/its test file added to `allowed_paths` mid-task once the gap was found).
