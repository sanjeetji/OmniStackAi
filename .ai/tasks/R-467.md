# R-467: Studio File Browser + Hybrid UI Toggle — wiring the R-465/R-466 engine into the product UI

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-17
**Completed:** 2026-09-17

## Objective

First slice of the "product-UI shell" brick: make the Studio (`studio/server.py` + `live_serve.py` +
`page.py`, a dependency-free stdlib-`http.server` app with one server-rendered HTML+vanilla-JS page —
confirmed by direct reading, not assumed) actually let a user **see what was built** and **opt into the
hybrid engine**, closing the two biggest gaps a full read of the Studio code surfaced:

1. **No way to inspect a build.** `/api/build`'s response embeds a flat, point-in-time list of file
   *paths* (`page.py`'s `<ul id="r-files">`, populated with plain `<li>` text nodes, no click handler).
   There is no endpoint to fetch the file tree or a file's contents after the fact — `git show`/opening
   the folder in an editor is the only way today.
2. **R-465 (`synthesize_screens`/`ui_outcomes`) and R-466 (compile-repair) are entirely unwired from the
   Studio.** `live_serve.py::_build`'s three build paths (plain-prompt, Solution Pack, Ecosystem Pack)
   never pass `synthesize_screens=`/`ui_outcomes=` into `build_app_from_prompt`/`build_app_from_ir`, and
   `app_build_result_to_dict` has no `ui_outcomes` key. The only place the hybrid engine runs end-to-end
   today is the standalone `task agent-engine:ui:synthesize` CLI, disconnected from the server users
   actually open in a browser.

This task wires both in, scoped to what is directly testable offline in one task:

- **File browser (v1):** new read-only, path-safe `GET /api/build/{id}/files` (flat sorted file list) and
  `GET /api/build/{id}/file?path=...` (one file's content) routes, backed by a new pure `studio/files.py`
  module reading straight off the recorded build's `target_dir` on disk (no re-run, no new state). The
  page's file list becomes clickable and shows the selected file in a read-only viewer pane.
- **Hybrid UI toggle:** `/api/build` accepts `hybrid_ui: bool` (default `false`). When true, it threads
  `synthesize_screens=True` + a `ui_outcomes` sink into the **plain-prompt** and **Ecosystem Pack** build
  paths (the two that already accept those kwargs — confirmed by reading `build_app_from_ir`/
  `build_app_from_prompt`'s signatures). `ui_outcomes` (already a JSON-safe, secret-free
  `UiSynthesisOutcome.to_dict()` list from R-465) is surfaced in the build response, recorded in
  `StudioBuildHistory`, and summarized in the page ("Hybrid UI: N/M pages written by the model", with a
  🤖 badge on synthesized files). `build_solution_pack_project` (Solution Pack path) has **no**
  `synthesize_screens`/`ui_outcomes` parameter — requesting `hybrid_ui` there is honestly reported back as
  `hybrid_ui_active: false` rather than silently ignored or guessed at.
- **Bugs found and fixed while implementing, in functions this task already touches:**
  `live_serve.py`'s ecosystem single-surface branch constructs `ApplicationIR(...)` (for a `custom_name`/
  `custom_description` override) with **no import of `ApplicationIR` anywhere in the file** — a latent
  `NameError` on that rarely-exercised path. And a live discovery, not just a static one: with the
  founder's real Groq credentials now sitting in the repo's gitignored `.env` (from the R-465/R-466 live
  proofs), running the *existing* Studio suite unmodified made **real outbound calls to Groq** — `pytest`
  hung for minutes, not seconds. Four pre-existing `live_serve._build(...)` test call sites never mocked
  `resolve_generation_provider_from_env` (a real, `.env`-reading, environment-sensitive function): the two
  already known in `tests/test_studio_ecosystem.py`, **plus two more found here** in
  `tests/test_studio_server.py` (`test_live_serve_build_with_solution_pack`,
  `test_live_serve_build_with_ai_delta_features`) — because *any* real provider reaching
  `build_app_from_ir`/`build_solution_pack_project` triggers the R-462 overview-page LLM synthesis
  regardless of `hybrid_ui`/`synthesize_screens`. This was a live, active violation of the standing "0
  model/network calls under `task verify`" constraint, not a theoretical one — confirmed by timing
  (`resolve_generation_provider_from_env()` alone: 0.02s; the unmocked ai-delta test: 23.5s of real Groq
  traffic, retried and paced by R-466's own logic before giving up). All four now patch
  `resolve_generation_provider_from_env` to `(None, "stub-model", 4096, 5.0)` — deterministic, and a
  legitimate real-world case (`provider=None` is exactly what an unconfigured account sees).

**Explicitly out of scope** (named, not silently dropped — see Follow-ups): multi-turn chat / "continue
editing this app" conversational state (the Studio has no session/thread/message concept at all today;
this needs real design — new state, and either a fresh build or an `edit/diff.py`-based in-place patch —
big enough to be its own Tracker ID, R-468); wiring R-466's `compile_and_repair` (needs the `pnpm`/`tsc`
toolchain) into the live server; live-refreshing the file browser while a preview is running.

## Acceptance Criteria

- [x] `studio/files.py` (new): `list_build_files(root_dir, *, max_entries=4000) -> dict` (sorted flat
      `files: [...]`, `truncated: bool`; excludes `.git`, `node_modules`, `__pycache__`, `.next`, `.venv`,
      `venv`, and any real `.env*` file — `.env.example` is kept, it never carries a secret) and
      `read_build_file(root_dir, rel_path, *, max_bytes=512_000) -> dict` (`path, content, truncated,
      binary, size`; a binary file is reported with `binary: true` and empty content, never raises for
      that). Typed errors `BuildNotFoundError`, `PathOutsideBuildError`, `FileNotFoundInBuildError`
      (`StudioFilesError` base) — path safety mirrors `edit/apply.py`'s `_safe_destination` (resolve, then
      `relative_to(root)`, reject on `ValueError`). Pure filesystem reads; no network/model/subprocess.
- [x] `studio/server.py`: `_make_handler`/`create_studio_server` gain `file_tree_fn: Callable[[str], dict]
      | None = None` and `read_file_fn: Callable[[str, str], dict] | None = None`. New routes
      `GET /api/build/{id}/files` and `GET /api/build/{id}/file?path=...` (build id has no `/`, else 404;
      missing `path` query → 400); unset function → 404 "not enabled"; `BuildNotFoundError`/
      `FileNotFoundInBuildError` → 404, `PathOutsideBuildError` → 400, any other exception → 502 (matches
      the existing error-mapping convention). `/api/build`'s accepted body gains `hybrid_ui` (coerced
      `bool`, only added to `options` when present) alongside the existing key whitelist.
- [x] `studio/live_serve.py`: `_build(..., hybrid_ui: bool = False, ...)`. Plain-prompt path passes
      `synthesize_screens=hybrid_ui, ui_outcomes=(sink if hybrid_ui else None)` into
      `build_app_from_prompt` and sets `payload["hybrid_ui_requested"] = hybrid_ui`,
      `payload["hybrid_ui_active"] = hybrid_ui` (a provider is already mandatory on this path). Ecosystem
      path (both single-surface and all-surfaces) passes the same kwargs into each `build_app_from_ir`
      call **only when a provider actually resolved** (`eco_provider is not None`), reports
      `hybrid_ui_active = hybrid_ui and eco_provider is not None` — no silent no-op — and attaches
      `ui_outcomes` (single-surface: top-level; all-surfaces: per surface entry). Solution Pack path adds
      `hybrid_ui_requested`/`hybrid_ui_active=False` when `hybrid_ui` was requested, unchanged otherwise.
      Fixes the missing `ApplicationIR` import (`NameError`) in the ecosystem single-surface branch.
      New `_resolve_build_dir(build_id, history)`, `_list_build_files(build_id, history)`,
      `_read_build_file(build_id, path, history)` (raise `BuildNotFoundError` via `studio/files.py` when
      the id is unknown or its `target_dir` is gone); wired unconditionally into `main()`'s
      `control_kwargs` (file browsing needs no toolchain — available in build-only mode too, like
      `history_fn`/`delete_build_fn`).
- [x] `intake/build_app.py`: `app_build_result_to_dict(result, *, max_files=500, ui_outcomes=None) -> dict`
      — adds an `"ui_outcomes"` key (list of `.to_dict()`) only when `ui_outcomes` is given; omitted
      entirely otherwise, so every existing caller's output is byte-for-byte unchanged.
- [x] `studio/history.py`: `StudioBuildHistory.record` additionally captures `hybrid_ui_requested` (bool,
      when present) and a bounded `ui_outcomes` list (when present) so "Recent builds" can show whether
      hybrid UI ran.
- [x] `studio/page.py`: the file list becomes a clickable, sorted list (kept flat — no new tree-widget
      code — a click fetches `GET /api/build/{id}/file?path=...` and renders it in a new read-only viewer
      pane with the path, a binary/truncated notice when applicable, and an 🤖 badge on files whose
      `ui_outcomes` entry has `mode === "llm"`); a "Hybrid UI (experimental — uses a model)" checkbox is
      added to the build form and sent as `hybrid_ui` in the `/api/build` POST body; on a successful
      build with `hybrid_ui_requested`, a one-line summary ("Hybrid UI: N/M pages written by the model" or
      "requested but no model was available" when `hybrid_ui_active` is false) is shown. Zero external
      assets preserved (no CDN, no new dependency) — the existing `test_page_has_no_external_resources`
      style checks keep passing unmodified.
- [x] `studio/__init__.py` exports `list_build_files`, `read_build_file`, `StudioFilesError`,
      `BuildNotFoundError`, `PathOutsideBuildError`, `FileNotFoundInBuildError`.
- [x] New `tests/test_studio_files.py` (pure filesystem, tmp dirs, 0 network/model/subprocess): exclusion
      list, `.env` vs `.env.example`, truncation at `max_entries`/`max_bytes`, path-traversal rejection
      (`../`, absolute, symlink-escape), binary-file reporting, not-found mapping.
- [x] `tests/test_studio_server.py`: new route tests for both endpoints (200 with a stub function; 404
      when unset; 404/400/502 mapped from each typed error; 404 on a build id containing `/`; 400 on a
      missing `path` query) and `/api/build` forwarding `hybrid_ui` to `build_fn`.
- [x] `tests/test_studio_ecosystem.py` and `tests/test_studio_server.py`: all four pre-existing
      `live_serve._build(...)` call sites (the two ecosystem tests, plus `test_studio_server.py`'s
      `test_live_serve_build_with_solution_pack`/`test_live_serve_build_with_ai_delta_features`, found
      while implementing) explicitly patch `resolve_generation_provider_from_env`, closing the live gap
      described above. `test_studio_ecosystem.py` gains a new test proving `hybrid_ui=True` threads
      `synthesize_screens`/`ui_outcomes` through the ecosystem path with a stub provider (0 real model
      calls) — plus one proving the Solution Pack path reports `hybrid_ui_active: false` honestly when
      `hybrid_ui=True` is requested there.
- [x] `tests/test_studio_history.py`: a test recording `hybrid_ui_requested`/`ui_outcomes` and asserting
      they round-trip through `.list()`/`.get()`.
- [x] `tests/test_build_app.py`: a test asserting `app_build_result_to_dict(result, ui_outcomes=[...])`
      includes the key and that omitting the argument leaves the dict exactly as before (regression guard
      for the "byte-for-byte unchanged when unused" claim above).
- [x] `task verify` stays green with 0 model/network/subprocess/toolchain calls; `task agent-engine:studio:

## Live discovery (found while implementing, not anticipated in the contract)

With the founder's real Groq credentials now sitting in the repo's gitignored `.env` (added during the
R-465/R-466 live proofs), running the *pre-existing, unmodified* Studio test suite made real outbound calls
to Groq — `pytest` took minutes instead of seconds. Four pre-existing `live_serve._build(...)` test call
sites never mocked `resolve_generation_provider_from_env` (a real, `.env`-reading function): the two already
suspected in `tests/test_studio_ecosystem.py`, **plus two more found here** in `tests/test_studio_server.py`
(`test_live_serve_build_with_solution_pack`, `test_live_serve_build_with_ai_delta_features`) — because *any*
non-`None` provider reaching `build_app_from_ir`/`build_solution_pack_project` triggers the R-462
overview-page LLM synthesis regardless of `hybrid_ui`. Timed precisely: `resolve_generation_provider_from_env()`
alone takes 0.02s; the unmocked ai-delta test took **23.5s of real, R-466-paced Groq traffic** (a genuine
413 "too large" → compact-grounding retry → validator rejection → 429 rate-limited → give-up sequence) before
falling back. This was a live, active violation of the standing "0 model/network calls under `task verify`"
constraint on this machine, today — not a theoretical one. All four now patch
`resolve_generation_provider_from_env` to `(None, "stub-model", 4096, 5.0)`.
