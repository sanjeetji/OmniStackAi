# R-287 — Race-Safe Generated Detail Refetches

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic codegen)

## Objective

The generated Next.js data hooks cancel superseded requests everywhere except the single-record detail
hook. R-280 made `useList<Entities>` race-safe and R-286 made `useList<Child>By<Parent>` race-safe, but
`use<Entity>` (the `# 2. use<Entity>` block in `nextjs.py` `_hooks_file`) still awaits
`api.get<Entity>(id, options)` and unconditionally `setData(item)`. During rapid record-selector /
prev-next / deep-link / id changes, an older in-flight GET can resolve last and overwrite the currently
selected record. R-287 gives the detail hook the same AbortController design, scoped to that hook only.

## Requirement

Reuse the R-286 LIST_BY template (the corrected pattern that passes the signal AFTER caller options).
The `use<Entity>` refetch must: own an `abortRef`; abort the previous request before the `if (!id)`
check; on missing ID reset `setData(null)`, `setError(null)`, `setLoading(false)`; on valid ID create +
register a new controller; call `api.get<Entity>(id, { ...options, signal: controller.signal })`; guard
success (`if (controller.signal.aborted) return;` before `setData`), catch (`AbortError`/aborted → no
error), and finally (clear loading only when not aborted); and the effect returns
`() => abortRef.current?.abort();`. `useRef` is already imported (R-280). No API-client, backend, IR,
list, or LIST_BY change.

## Acceptance criteria

1. `use<Entity>` emits `const abortRef = useRef<AbortController | null>(null);` and calls
   `abortRef.current?.abort();` before the `if (!id)` reset.
2. Missing-ID branch resets `setData(null)`, `setError(null)`, `setLoading(false)`.
3. GET call is `api.get<Entity>(id, { ...options, signal: controller.signal })`; old
   `api.get<Entity>(id, options)` form removed.
4. Success/catch/finally guarded by the aborted checks; effect cleanup aborts.
5. `useList<Entities>` and `useList<Child>By<Parent>` output unchanged; description-only IR changes
   byte-identical.
6. Focused tests + relevant detail/hook tests + full offline gates + both demos pass.

  spread, so no api-client change is needed.
