# R-296 — Generated Web App Accessibility Pass: Semantic ARIA Roles, Live Regions, Table Sort State, and Accessible Search/Pagination Controls

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2 (deterministic codegen)

## Objective

Elevate the generated Next.js web application to enterprise accessibility standards (WCAG 2.1 AA / WAI-ARIA best practices) across collection, detail, subcollection, and form screens. Assistive technologies (screen readers) currently lack key semantic markers for fetch/form error banners, search input fields, table header sort state, pagination controls, and empty-state list transitions. R-296 introduces semantic WAI-ARIA roles, live regions, accessible names, and sort state while maintaining 100% diff-invariance across `ir.description`, backward compatibility with all existing text assertions, and zero changes to public hook/API/backend contracts.

## Requirements

In `services/agent-engine/src/omnistackai_agent_engine/codegen/nextjs.py`:

1. **Error Banners (Live Regions & Alert Roles)**:
   - Collection top-level fetch error banner emits `role="alert"` and `aria-live="assertive"`.
   - Detail screen main fetch error banner emits `role="alert"` and `aria-live="assertive"`.
   - Subcollection fetch error banner (both collection master-detail and detail render sites) emits `role="alert"` and `aria-live="assertive"`.
   - Form screen submit error banner emits `role="alert"` and `aria-live="assertive"`.

2. **Accessible Search Inputs**:
   - Collection list search `<input>` emits `aria-label="Search <plural>"`.
   - Subcollection list search `<input>` emits `aria-label="Search <child_plural>"`.

3. **Sortable Table Column Headers (WAI-ARIA Sort State)**:
   - In `_collection_screen_page`, each sortable column `<th>` emits:
     `aria-sort={params.sort === "<field>" ? (params.order === "desc" ? "descending" : "ascending") : "none"}`.

4. **Accessible Pagination Controls**:
   - Collection pagination footer is wrapped in `<nav aria-label="Pagination">`.
   - Collection Previous button emits `aria-label="Previous page"`.
   - Collection Next button emits `aria-label="Next page"`.
   - Subcollection Previous and Next buttons emit `aria-label="Previous page"` and `aria-label="Next page"`.

5. **Status Announcements for Empty States**:
   - Contextual empty-state text containers in collection lists and subcollections emit `role="status"` for polite assistive announcements.

6. **Preservation & Invariance**:
   - All existing text labels, retry buttons, skeletons, and hook signatures remain unchanged.
   - Byte-identical output when only `ir.description` changes.

## Acceptance Criteria

1. Collection, detail, subcollection, and form error banners emit `role="alert"` and `aria-live="assertive"`.
2. Collection and subcollection search inputs emit the expected `aria-label` attributes.
3. Sortable table `<th>` elements emit dynamic `aria-sort` matching active parameters.
4. Pagination footer is enclosed in `<nav aria-label="Pagination">` with `aria-label` on buttons.
5. Subcollection pagination buttons emit `aria-label` attributes.
6. Empty state messages include `role="status"`.
7. Full offline test suite (`task verify`), lint, security check, env check, and both builder demos pass.
