# R-245 — Combined project-plan surface

## Requirement

Compose the existing plan builders into one per-app view a console/CLI can render (Brief §15/§26/§51):
for an Application IR, build a `ProjectPlan` whose `AppPlan` entries pair each assembled app (label,
directory, target — R-232 `assembled_targets`) with its local **preview** plan (R-233
`LocalRuntimeProvider`), its **verify** gate ladder (R-235 `verify_plan`), and — only when a
key-activated `DeploymentProvider` is supplied — its **deploy** plan (R-234). Provide a JSON-serializable
`to_dict` and a readable `render()`, plus `task plan:show`. Pure and deterministic; nothing is run,
verified, or deployed. Committed directly to `main` (R-245).

## Acceptance criteria

- `build_project_plan(ir)` → a `ProjectPlan`; each `AppPlan` pairs an assembled app with a preview plan
  (when the target runs locally) and a verify plan (when supported); a deploy plan appears only when a
  `DeploymentProvider` is passed.
- `ProjectPlan.to_dict()` is JSON-serializable and secret-free; `render()` is a readable multi-app
  summary (dir/target, preview url + commands, verify gates, deploy steps when present).
- `task plan:show -- <example>` prints the plan for an example IR; `task verify` stays green.
- Offline tests cover composition, deploy opt-in, JSON-serializability + no-secret, and determinism.

## Design notes

- New `omnistackai_agent_engine.projectplan`: `AppPlan`, `ProjectPlan`, `build_project_plan(ir, *,
  deploy=None)`. Composes `codegen.assembled_targets`, `runtime.LocalRuntimeProvider.preview_plan`
  (guarded by `.supports`), `verify.verify_plan` (guarded by `verify.supported_targets`), and an
  optional `DeploymentProvider.deploy_plan`.
- CLI `plan-show` in `scripts/agent-engine.sh` + `task plan:show`. Docs in `docs/RUNTIME.md`.
- No new execution; standard-library only.
