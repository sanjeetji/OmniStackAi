# R-495: Console — Settings + Fabric (provider cards, theme switcher, cost overview)

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-19
**Completed:** 2026-09-19

## Objective

Fifth task of the Console UI overhaul (R-491..R-496). `/settings` and `/fabric` are the last two
screens still built from the legacy hand-rolled classes (`.panel`, `.masthead`, `.badge`,
`.stat`, the raw `<table>` styles): Settings is one table titled "Model Providers"; Fabric is a
stack of five `.panel`s over a static snapshot. This task rebuilds both on the R-491 stack —
Settings as a real settings page (Account facts, Appearance with the theme switcher the R-491
contract deferred here, Model providers as status cards with an actionable "Needs key" hint),
Fabric as a proper data page with real data typography — and, since nothing else uses them
afterwards, removes the now-dead legacy CSS family (everything except the three selectors and
tokens the R-475 contract assertion still pins, which R-496 retires with that assertion).

## Design (verified against the real code)

- **Data stays exactly what it is.** Settings reads `getProviderStatus(token)` server-side as
  before (unreachable → an alert, never a fake). `ProviderInfo` carries `keyEnv` — the env var a
  cloud provider reads its key from — so a "Needs key" card can say precisely which variable to
  set, and never a key value (the API never returns one). Fabric renders `data/overview.json`,
  the snapshot `scripts/console.sh snapshot` regenerates from the agent-engine's
  `platform_console_snapshot()` on every `task console:build`; the page now says so, shows
  `snapshotVersion`, and renders the all-zero usage block as "no calls recorded in this
  snapshot" rather than hiding it.
- **Settings** (`app/settings/page.tsx`, server): page header; a `lg` two-column layout with a
  sticky in-page nav (Account / Appearance / Model providers anchors) and stacked sections:
  **Account** — a read-only `dl` (name, email, plan badge, credits `tabular-nums`, role, BYOK
  badge) with the honest line "Profile editing isn't available yet" and no fake Save button;
  **Appearance** — a new client `components/theme-switcher.tsx`: a three-way segmented control
  (System / Light / Dark, `Monitor`/`Sun`/`Moon`, `aria-pressed`, `role="group"`) on
  `next-themes`' `useTheme`, hydration-safe (renders a disabled placeholder until mounted), with
  the true note that the choice is saved in this browser; it is in Settings, not a sun/moon
  switch in the header, per the audit; **Model providers** — the live "next build uses …"
  summary (Ready / Not ready), routing mode + selected cloud tier from the status payload, and a
  grid of `Card size="sm"` per provider: id, tier badge (local/cloud), kind, default model in
  mono, status badge (Active / Needs key) and, when a key is missing, `Set KEY_ENV in .env` as a
  mono chip.
- **Fabric** (`app/fabric/page.tsx`, server, still public inside the shell with an optional
  user): header with a "Snapshot vN" badge and the regeneration note; **Routing ladder** as an
  ordered list with `L0…` level chips and tier badges; **Providers** and **Price book** as
  semantic tables styled with Tailwind (`tabular-nums`, right-aligned numbers, mono model ids,
  sticky header row, `overflow-x-auto`); **Usage & resilience** as stat cards (calls, success/
  failure, tokens, cost, p50/p95 latency, unpriced calls) with the "no calls recorded" note when
  empty, plus circuit-breaker and fallback-chain facts; **Builder showcase** as cards for the
  project plan's apps (gate chips) and the edit preview with a small `DiffBlock` that colors
  `+`/`-`/`@@` lines (the R-481 tokenizer has no diff language; this is line-prefix coloring, not
  a new dependency).
- **CSS sweep**: with both pages migrated, `.wrap`, `.wrap--wide`, `.masthead`, `.eyebrow`,
  `.panel`, `.field*`, `.button*`, `.error-banner`, `.grid`, `.stat*`, `.badge*`, `.muted`,
  `.mono`, `.num`, `.actions`, `.overflow`, `.pill-row`, `.settings-active-now`, `.studio-intro`
  and the legacy element rules that only served them are removed from `globals.css`. `.pill`,
  `.pill--accent`, `.spinner` and the `--radius-*`/`--surface-2` aliases stay because the R-475
  block asserts them; R-496 retires them together with that assertion.
- **No new dependencies; no API/lib/data changes; no agent-engine/control-plane changes.**

## Gates & Evidence

**Three real catches from the first gate run, all mine, all fixed before anything shipped:**
(1) `pnpm run lint` failed on `theme-switcher.tsx` — the `react-hooks/set-state-in-effect` rule
*is* enabled in this ESLint config (I had assumed otherwise from older code); the
`useEffect(() => setMounted(true))` mounted-flag pattern was replaced with a
`useSyncExternalStore` hook (server snapshot `false`, client snapshot `true`, no-op subscribe) —
hydration-safe with no setState in an effect. (2) `pnpm run build` failed with a real
`CssSyntaxError` at `globals.css:263` — my own sweep note contained the text `--radius-*/`,
whose `*/` closed the comment early; reworded. (3) `scripts/test.sh` reported `.wrap {` still
present: the dead `@media (max-width: 640px)` block at the very end of the file still carried
`.wrap`/`.masthead` overrides that my line-anchored check had missed; removed. After the fixes:
