# R-416: Prompt -> Application IR intake agent (`intake/nl_to_ir.py`)

## Status
DONE

## Objective
Build the first brick of the OmniStackAI "chat -> create an app" front door: a local, zero-new-dependency
**Prompt -> Application IR intake agent** (`omnistackai_agent_engine/intake/`) that turns a plain-English
application description into a validated, normalized `ApplicationIR` (the same framework-neutral spec the
code generators already consume). The deterministic core is fully offline-testable: `build_intake_messages`
constructs the system+user `Message` tuple (schema-by-example, using a real `example_ir(...).to_dict()` as
the format template so it never drifts from the IR schema); `parse_ir_response` extracts JSON from raw model
text (tolerating ```json fences and surrounding prose, injecting `schema_version` when omitted), builds an
`ApplicationIR` via `ApplicationIR.from_dict`, and `normalize_ir`s it; `generate_ir` performs the single I/O
step against the vendor-neutral `ModelProvider` protocol (so `task verify` runs it against an in-memory stub
provider — 0 model calls, 0 network) and raises `IntakeResponseError` when the model output cannot be parsed
or the resulting IR fails semantic validation (`validate_ir` / `has_errors`). Ships typed results
(`IntakeResult`) and errors (`IntakeError`, `IntakeResponseError`), and an opt-in live runner
(`intake.live_run`, excluded from static verify) wired as `task agent-engine:intake:run -- "<description>"`
that compiles a prompt through the local Ollama model and prints the resulting IR JSON.
