# R-523: Template marketplace in the console (Phase T, T-3)

**Phase:** Phase T (Template Marketplace)
**Status:** COMPLETED
**Started:** 2026-09-21
**Completed:** 2026-09-21

## Objective

Users can browse templates, understand one quickly, and start their own project from it, all in
the console. The founder's model applies: the original never changes, and "Use template" makes the
user's own editable project.

## Design

- **`/templates`**: title and intro, search (name, tagline, features, entities), category filter
  chips with counts, and a card grid. Each card has a cover (or a branded placeholder), name,
  category, tagline, app chips ("Web · Admin · Driver app · API"), a feature count and roles.
  - The catalogue is empty until T-6, so the page shows a designed empty state listing the
    categories on the way, never a blank grid.
- **`/templates/[slug]`**: header with cover, name, tagline, category, version and a **Use template**
  button. The button opens a dialog (project name defaulting to the template name, plus "your own
  copy; the original stays unchanged"), then sends the user to the new project in the Studio. The
  page also shows:
  - the description;
  - an **apps** grid (kind icon, name, what it is for);
  - features;
  - roles and demo logins (local preview only);
  - data entities;
  - integrations (with "mock, no credentials needed" badges);
  - the stack and screenshots.
- **Navigation:** a "Templates" item in the primary nav, and a "Start from a template" link under
  the home composer.
- **Studio:** a project started from a template shows a notice ("Started from the RideNow
  template, v1.0.0"). Chat edits for template projects arrive with the code-edit agent (T-4). The
  chat send is disabled with that explanation rather than failing.
- **Media:** template covers and screenshots are served through
  `GET /api/templates/{slug}/assets/{path}` (agent-engine, only files the manifest declares), then
  `GET /templates/{slug}/assets/{path...}` (control-plane, public, cacheable), then
  `/template-assets/{slug}/{path...}` (console).
- **Console API:** `POST /api/templates/{slug}/use` (session required), which proxies the
  control-plane `POST /templates/{slug}/use`. Catalogue pages render on the server.

## Gates

Agent-engine media tests. Control-plane media proxy tests and `go test ./...`. Console
typecheck/lint/build. `scripts/test.sh` R-523 block. `task verify`, `task lint`,
`task security:quick`, `task env:check`. Live against the fixture catalogue:
`/templates` → `/templates/corner-shop` → Use template → Studio shows the template project, and its
preview runs. Also the empty-state page on the real (empty) catalogue, and `./scripts/smoke-core.sh`.

## Delivered

- Agent-engine: `TemplateCatalog.asset()` serves declared covers and screenshots only, with an
  image content type. Route: `GET /api/templates/{slug}/assets/{path}`.
- Control-plane: `GET /templates/{slug}/assets/{path...}` (public, `Cache-Control: max-age=3600`,
  `nosniff`, 404s not cached). Wired into `newMux` and the route-table test.
- Console:
  - `/templates` (search, category chips with counts, cards, designed empty state, error state);
  - `/templates/[slug]` (header with cover and Use template, about, apps, features, screens, roles,
    demo logins as emails only, data entities, integrations with a "works without keys" badge,
    stack);
  - `TemplateUseButton` dialog, which names the project then opens it in the Studio;
  - `POST /api/templates/{slug}/use` and the `/template-assets/...` relay (sandboxed CSP for SVG);
  - a nav item, a home-page link, and the Studio template notice (composer disabled with an
    explanation);
  - types plus `listTemplates`, `getTemplate`, `createProjectFromTemplate` and
    `getProjectTemplate`.
