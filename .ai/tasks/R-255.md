# R-255 — Query parameter pagination (limit & offset) for LIST and LIST_BY in Go and FastAPI backends

**Status:** done  
**Phase:** BASIC/MVP — Founder Stage 0  
**Branch:** `main`  
**Complexity:** L2  

## Objective

Add query parameter pagination (`limit` and `offset`) to GET list and sub-collection list endpoints across both Go and FastAPI backends. Currently:
- Go handlers hardcode `100` and `store.List` only accepts `limit int` (no `OFFSET`).
- FastAPI router endpoints omit `limit` and `offset` query parameters even though the repository functions already support `(limit: int = 100, offset: int = 0)`.

R-255 provides complete feature parity for pagination across both backends.

## Acceptance criteria

1. **Go shared handlers** (`_handlers_shared_file`): emits `parsePagination(r *http.Request) (int, int)` parsing `limit` (default 100, >0) and `offset` (default 0, >=0) safely using `strconv.Atoi`.
2. **Go wired handlers** (`_handlers_file_wired`):
   - `Op.LIST`: calls `limit, offset := parsePagination(r)`, then `store.List<Entity>(r.Context(), h.DB, limit, offset)`.
   - `Op.LIST_BY`: calls `limit, offset := parsePagination(r)`, then `store.List<Entity>By<Rel>(r.Context(), h.DB, id, limit, offset)`.
3. **Go store** (`data_access.py`):
   - `List<Entity>`: signature `func List<Entity>(ctx context.Context, db *sql.DB, limit, offset int) ([]models.<Entity>, error)` with SQL `SELECT ... ORDER BY id LIMIT $1 OFFSET $2`.
   - `List<Entity>By<Rel>`: signature `func List<Entity>By<Rel>(ctx context.Context, db *sql.DB, <rel>ID string, limit, offset int) ([]models.<Entity>, error)` with SQL `SELECT ... WHERE <rel>_id = $1 ORDER BY id LIMIT $2 OFFSET $3`.
4. **FastAPI router** (`backend_python.py`):
   - `Op.LIST`: `async def <fn>(limit: int = 100, offset: int = 0) -> list[dict]:` calling `await <table>.list_<table>(limit=limit, offset=offset)`.
   - `Op.LIST_BY`: `async def <fn>(<id_param>: str, limit: int = 100, offset: int = 0) -> list[dict]:` calling `await <table>.list_<table>_by_<rel>(<id_param>, limit=limit, offset=offset)`.
5. **No query parameters needed**: Defaults apply when parameters are omitted (limit 100, offset 0).
6. **Existing tests & regression**: All existing tests updated where signatures are asserted.
7. **Task verify**: All tests pass offline, 0 network, no DB.
