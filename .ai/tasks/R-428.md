# R-428: Generated web app compiles — opt-in TypeScript typecheck gate + fix the bugs it reveals

## Status
DONE (run-blocking generated-code bugs fixed + opt-in gate added; the generated app now compiles and
renders in `next dev`/preview. The remaining ~82 strict *type* errors in the component library — which do
NOT block `next dev` but would fail a production `next build` — are catalogued as follow-up, R-429.)

## Objective
Generated Next.js apps have accumulated multiple compile-time bugs that `task verify` never catches because it
asserts generated code as strings and never compiles the TSX. Add an opt-in, live TypeScript typecheck gate —
`task agent-engine:web-typecheck -- <example> [out-dir]` — that generates an example app, ensures its web
dependencies, and runs `tsc --noEmit` on `apps/web`, reporting the errors. Then fix every generator bug the
gate reveals (inconsistent f-string brace escaping in event handlers and screens, an invalid character in a
component, import-path depth, etc.) until `tsc --noEmit` passes cleanly on both example IRs. Add deterministic
regression tests for each fixable class (e.g. no single/again-doubled inline braces, ASCII-only component
sources) so these cannot regress. Do not change screen structure, styling values, component behavior, or
logic — only correct malformed emitted TSX. The typecheck gate is opt-in/live (needs the toolchain) and is
never run by `task verify`.

## Requirements
- Add an opt-in `task agent-engine:web-typecheck -- <example> [out-dir]` (script + Task) that generates the
  example app, installs web deps (`pnpm install --ignore-scripts`), and runs `tsc --noEmit` in `apps/web`.
- Fix every generator bug the gate reveals so `tsc --noEmit` passes on `minimal-blog` and `rideshare-favourites`.
- Add deterministic regression tests codifying each fixed class (brace correctness in generated TSX, ASCII-only
  component sources, etc.).
- Do not change screen structure, styling values, component behavior, or generated logic — only correct
  malformed emitted TSX; do not break diff-invariance.
- Keep `task verify` offline/deterministic (0 model calls, no toolchain); the typecheck gate is opt-in only.

## Acceptance Criteria
- `tsc --noEmit` on a generated `minimal-blog` and `rideshare-favourites` app reports zero errors.
- Regression tests catch the fixed bug classes and pass.
- Existing generation/screen/diff-invariance tests remain green; focused + full verify + lint + security + env
  + both builder demos pass; 0 model calls in verify.

## Gates & Evidence
- Opt-in gate added: `task agent-engine:web-typecheck -- <example> [out-dir]` (generate + pnpm install + `tsc --noEmit`).
- RUN-BLOCKING generator bugs fixed (found via the gate + `next dev`):
  - search-input `onChange`/clear `onClick` handlers emitted `=> {{ ... }}}}` (extra braces) -> `=> { ... }}`.
  - `components/pdf-viewer.tsx` had a literal `\n` from a raw-string join -> real newline via adjacent concat.
  - nested screen imports used depth-relative `../components/`/`../lib/` (broke module resolution) -> the
    depth-independent `@/` path alias (24 generator import sites).
- Verified end-to-end: a generated `minimal-blog` app compiles under `next dev` and `/`, `/post_list`,
  `/post_editor` all serve HTTP 200 (were 500); 0 module-resolution errors in generated code.
- Regression tests: `test_generated_screen_styles.py` (R-427) + `test_generated_tsx_compile.py` (over-braced
  handlers, relative `../components|../lib` imports, literal backslash-n). Updated 9 screen/layout test files'
  import assertions from `../` to `@/`.
- `task verify` 2,873 passed; `task lint`/`security:quick`/`env:check` green; `builder:demo -- minimal-blog`
  (152) and `-- rideshare-favourites` (149) pass; 0 model calls.
- REMAINING (follow-up R-429): ~82 strict TYPE errors in the component library (TS2323 duplicate exports,
  TS2339 `displayName` on function components, TS2430/TS2322 prop-type conflicts). These do NOT block
  `next dev`/preview; they would fail a production `next build`/strict typecheck.
