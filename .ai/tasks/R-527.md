# R-527: RideNow template, part 2 of 4: rider web app and shared package (Phase T, T-6)

**Phase:** Phase T (Template Marketplace)
**Status:** COMPLETED

**Completed:** 2026-09-22

## Objective

`apps/rider` is the customer-facing RideNow website and app: a marketing landing page and every
page a rider needs, working against the R-526 API. `packages/shared` holds what all three apps
reuse. The master plan and page targets are in `.ai/tasks/R-526.md`.

## Design

- **Stack:** Next.js 16 (App Router, Turbopack) with React 19, Tailwind CSS v4 (the versions the console already uses, so they come from the local cache) (the theme is defined in
  `globals.css`) and `next/font` (Plus Jakarta Sans). `basePath` comes from `BASE_PATH` (the
  preview contract). Browser calls go to `NEXT_PUBLIC_API_URL`, server calls to `API_URL`.
- **RideNow rider look:** light and bold. Ink `#0B1B2B`, RideNow amber `#FFB020` for primary
  actions, a deep-teal secondary, large rounded cards, map-first booking.
- **`packages/shared`** (TypeScript source, used through `transpilePackages`):
  - `api.ts`: a typed client. Tokens live in `localStorage` under a per-app key; a 401 refreshes
    once through `/auth/refresh`, then sends the user to sign-in.
  - `types.ts`: Trip, Offer, Wallet and the other response types.
  - `format.ts`: INR, distance, duration and relative-time formatters (en-IN).
  - `use-stream.ts`: Server-Sent Events with reconnection.
  - `city-map.tsx`: a stylised Bengaluru map in SVG, drawn with no map tiles or API keys, so the
    preview works offline. It shows lakes, arterial roads and neighbourhood labels; pickup, drop and
    car markers with heading; the route; surge zones; auto-fit; and tap-to-pick (returns lat/lng).
- **Pages:**
  - `/`: landing (hero with a booking entry, how it works, live vehicle types and fares from
    `/config`, safety, cities, FAQ, footer).
  - `/login` and `/signup`: email and password, or phone OTP.
  - `/ride`: book. Map, pickup and drop search with suggestions and saved-place chips, "use my
    usual pickup", fare options per vehicle (ETA, drivers nearby, surge and discount shown), promo
    code, wallet or cash, request.
  - `/trip/[id]`: live trip. Map with the moving car over SSE, a status timeline, driver and
    vehicle card, a large PIN, cancel with reasons (showing the fee rule), share-trip link. When
    the trip ends: receipt (fare breakdown, payment) and rating (stars and tags).
  - `/trips` and `/trips/[id]`: history with a status filter and paging; detail with receipt,
    events and "get help with this trip".
  - `/wallet`: balance, add money (mock card; the decline test card is explained), paginated
    transactions.
  - `/places`: saved places (add by search or by tapping the map, then delete).
  - `/promos`: offers with conditions, uses left, and "use now".
  - `/account`: profile, phone, password, sign out.
  - `/help` and `/help/[id]`: FAQ, my tickets, new ticket (optionally about a trip), and a thread
    with replies.
  - `/notifications`: list and mark all as read.
- **App shell** for signed-in pages: logo, Ride, Trips, Wallet and Help, a notifications bell with
  the unread count (live over SSE), and an account menu. It is responsive, with a bottom tab bar on
  phones.

## Found in live testing and fixed (platform)

1. **Previews outlived Studio restarts.** `omnistack.sh` stops the Studio with SIGTERM, which
   skipped its cleanup. Template apps run in their own process groups, so `next dev` kept running
   (orphaned) and Next 16 refused the next start ("Another next dev server is already running").
   Fixes:
   - The Studio turns SIGTERM into a clean shutdown that stops all previews.
   - Sessions record their process groups in `<workspace>/.preview-pids.json`, and the next start
     reaps survivors, but only groups still running node, pnpm or next (tested: an unrelated
     `sleep` is left alone).
   - Three orphans from earlier test runs were cleared by hand.
2. **Next 16 blocks dev assets for other origins.** Opened from the LAN (a phone), the app's JS
   got a 403 and the page would never hydrate. The console proxy now presents requests to template
   UI apps with the app's own local `Origin`/`Referer` (after its session and project checks), and
   the template's `next.config` allows `127.0.0.1` plus `ALLOWED_DEV_ORIGINS`. Live: the LAN-origin
   asset request went from 403 to 200.
