# R-430: Ecosystem Scope Compiler — deterministic domain classification + multi-app scope proposal

## Status
DONE (2026-09-13). First brick of the DIFFERENTIATING SPINE (founder-approved pivot, per
`R_&_D/OmniStackAI_OS_Master_Architecture_Specification.md` §2). Competitors turn "create a food delivery app"
into a single customer screen; OmniStackAI proposes the whole business ecosystem (customer app + merchant
portal + driver portal + admin) BEFORE expensive generation. R-430 builds the deterministic core of that
Scope Compiler so it is fully testable under `task verify` with 0 model calls.

## Objective
Add a Python-3.13-stdlib-only `intake/scope_compiler.py` that turns a plain-English business prompt into a
structured, framework-neutral **ScopeProposal**: the detected domain (+ confidence + matched keywords), the
business actors, the multi-surface app ecosystem, and 1–3 build-scope options (Complete Business Platform
[recommended], Customer Experience Only, Custom) plus at most 3 high-materiality clarifying questions. The
classification is a deterministic, curated keyword-heuristic layer (no model, no network) — mirroring the
"deterministic core + opt-in model layer" pattern already used by the intake agent (`nl_to_ir.py` core vs
`live_run.py`). Ship a deterministic CLI (`task agent-engine:scope:propose -- "<prompt>"`) that prints the
proposal as JSON so the founder can see it. Do NOT wire it into the IR generators yet (mapping each surface
→ an Application IR/repo is a later brick); do not change the IR, adapters, DB engine, or `task verify`'s
offline/deterministic contract.

## Requirements
- New `omnistackai_agent_engine/intake/scope_compiler.py` (stdlib only): frozen dataclasses `Actor`,
  `AppSurface` (kind, name, audience "customer"|"operator", actor, description), `ScopeOption` (id, label,
  description, recommended, surfaces), `ScopeProposal` (prompt, domain, domain_confidence, business_model,
  actors, surfaces, options, questions, matched_keywords) — each with a JSON-safe `to_dict()`.
- A curated `DOMAIN_LIBRARY` of business domains (food-delivery, rideshare, marketplace, e-commerce,
  b2b-saas, healthcare-clinic, booking/appointments, social, blog/cms, learning/LMS, …), each with weighted
  keywords, actors, the full-platform surfaces, and ≤3 materiality questions.
- `classify_domain(prompt) -> DomainMatch | None`: deterministic, case-insensitive, weighted keyword scoring;
  highest score above a threshold wins; ties broken by stable library order; returns matched keywords + score.
- `propose_ecosystem(prompt) -> ScopeProposal`: classify → build the Complete (recommended) / Customer-only /
  Custom options + questions; a generic single-app "Custom Application" fallback when nothing matches.
- 100% deterministic and pure (same prompt → byte-identical proposal; no `Math.random`/clock/model/network).
- Export the public API from `intake/__init__.py`; add a deterministic CLI `intake/scope_propose.py` and a
  `task agent-engine:scope:propose -- "<prompt>"` (+ `scripts/agent-engine.sh scope-propose`).
- `tests/test_scope_compiler.py`: classification of representative prompts, determinism/purity, the Complete
  option carries all surfaces and Customer-only only customer-audience surfaces, ≤3 questions, JSON-safe
  `to_dict()`, the no-match fallback, and the public exports are importable.

## Acceptance Criteria
- Representative prompts classify to the expected domain with a non-empty ecosystem (e.g. "food delivery app"
  → food-delivery with Customer/Merchant/Driver/Admin surfaces); an unknown prompt returns the Custom fallback.
- `propose_ecosystem` is deterministic (equal output for equal input) and JSON-serializable.
- `task verify` stays green and offline (0 model calls); lint/security/env pass; both builder demos unaffected.
