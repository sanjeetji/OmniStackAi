# R-426: Remove a build from the Studio history

## Status
DONE

## Objective
Let the operator clear a recorded build from the Studio's in-session "Recent builds" list. Add
`StudioBuildHistory.remove(build_id) -> bool` (thread-safe; removes the entry by id, returns whether it
existed). Expose it over the stdlib Studio server as `POST /api/history/delete {id}` via a new injected
handler (`delete_build_fn(build_id) -> dict`), reusing the existing generic `{id}`-body reader; unset handler
returns 404, missing id returns 400. Because removing an entry only edits the bounded in-memory list (it
never executes generated code, touches the database, or deletes anything on disk), the delete handler is
wired in **both** Studio modes (alongside history listing). `live_serve` returns the refreshed, bounded,
secret-free history so the page can re-render in one call. The Studio page adds a per-build "Remove" action
that calls the route and re-renders the list. No change to build, preview, re-preview, open-folder, live
status, status/stop/restart, collision-free ports, single-session cleanup, PostgreSQL, or
`studio:serve`/`studio:preview` semantics; all verification stays deterministic and offline.

## Requirements
- Add `StudioBuildHistory.remove(build_id) -> bool` (thread-safe): removes the entry by id and reports whether
  it was present; unknown id is a safe no-op returning False.
- Add `POST /api/history/delete {id}` over the stdlib server via an injected `delete_build_fn(build_id) -> dict`
  (reusing the generic id-body reader); unset -> 404, missing id -> 400, handler errors -> 502.
- Wire the delete handler in both Studio modes (it only edits the in-memory history; no code execution); the
  handler returns the refreshed, bounded, secret-free history payload (`{removed, builds}`).
- Add a per-build "Remove" button on the Studio page that calls the route and re-renders the list, DOM-only
  (no HTML injection).
- Keep all payloads/logs secret-free; nothing on disk or in the database is deleted.
- Deterministic/offline verify via injected fakes; `task verify` runs no generated code, Docker, PostgreSQL,
  package install, model, or external network.

## Acceptance Criteria
- `remove` returns True and drops the entry when present (gone from `list`/`get`), and returns False for an
  unknown id without error.
- `POST /api/history/delete {id}` returns the handler payload when wired and 404 when not; missing id -> 400;
  the handler receives the build id.
- The delete route is available in build-only mode as well as preview mode (it manages only the in-memory list).
- The Studio page exposes a per-build "Remove" action wired to `/api/history/delete` and re-renders the list.
- Existing studio/preview/server/history/local-run contracts remain compatible; focused + full verify + lint
  + security + env + both builder demos pass; 0 model calls in verify.
