# R-234 — Tier switch + cloud provider drivers

## Requirement

Make the runtime/deploy layer switchable with one `OMNISTACKAI_TIER` knob and give every declared
provider a driver that produces a real command plan (Brief §15/§44/§51/§70/§75). Tier 0/1 run/preview
locally (executor included); Tier 2 deploy to vercel/render/netlify/fly and run in an
e2b/daytona/fly-machines sandbox — each activated by its key. Deterministic and offline; no key value
ever appears in a plan; nothing is run/deployed by `task verify`. Committed directly to `main`. New IDs
continue after the workbook backlog's R-010..R-219 (this is R-234).

## Acceptance criteria

- `OMNISTACKAI_TIER` (0/1/2) resolves default runtime/deploy selections; explicit
  `OMNISTACKAI_RUNTIME_PROVIDER`/`OMNISTACKAI_DEPLOY_PROVIDER` override. Tier 0/1 force local runtime +
  no deploy; tier 2 permits keyed cloud selections.
- Every provider has a driver: deploy (vercel/render/netlify/fly) → a `DeployPlan` of official-CLI
  commands; sandbox (e2b/daytona/fly-machines) → a `PreviewPlan`. The key is read from env and NEVER
  placed in a command or shown in a plan.
- `resolve_platform()` returns the active runtime + deploy providers; `platform_status()` summarizes
  tier, selected providers, which have keys, and what's missing; wrong-tier/keyless selection errors.
- `run_preview`/`run_deploy` execute a plan (opt-in). `task platform:status`, `task preview`,
  `task deploy` expose this; `task verify` stays green.
- Offline tests cover tier resolution, per-provider plans, no-key-in-plan, activation/selection errors,
  and the status summary.

## Design notes

- `runtime/drivers.py`: `CloudDeployProvider` + `CloudSandboxProvider` (generic, parameterized from
  recipe tables using each provider's CLI); `run_deploy` executor. `runtime/tier.py`: `resolve_platform`,
  `platform_status`, tier→selection defaults. `bootstrap.py` gains an optional `selection` override.
  Keys stay in env; recipes reference no secret.

## Model and cost trace

Deterministic; no model call, no run/deploy. No cloud key set; cloud_calls zero.
