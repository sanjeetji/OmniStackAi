# R-246 — Richer edit-loop diffs (hunk-level + rename detection)

## Requirement

Make an IR edit read as a focused patch instead of whole-file churn (Brief §6/§27): on top of the R-237
file-level `ProjectDiff`, add a line-level report that produces git-style unified (hunk) diffs for
modified files and detects exact-content renames. Pure and deterministic, standard-library `difflib`
only; additive — `diff_projects` / `apply_diff` / `plan_edit` are unchanged; nothing is run or written
to disk. Committed directly to `main` (R-246).

## Acceptance criteria

- `diff_report(old, new)` → `FileDiff` records (kind added/modified/deleted/renamed, path, old_path,
  unified `patch`); a deleted file whose content exactly matches an added file is a single `RENAMED`
  record (old_path → path), not delete + add.
- modified files carry a git-style unified (hunk) diff with `-`/`+` lines; added/deleted carry the
  one-sided unified diff; the report is deterministically ordered.
- `unified_patch(old, new)` → one git-style patch string (rename headers for renames), byte-stable.
- Additive only: `diff_projects` / `apply_diff` / `plan_edit` outputs are unchanged.
- Offline tests cover modified-hunk content, rename detection, add/delete, empty diff for identical
  projects, and determinism.

## Design notes

- New `edit/patch.py`: `DiffKind`, `FileDiff`, `diff_report(old, new)`, `unified_patch(old, new)`, using
  `difflib.unified_diff`. Rename detection pairs a deleted path with an added path of identical content
  (greedy, sorted for determinism), excluding both from add/delete.
- Export from `edit/__init__.py`. No change to `diff.py`/`apply.py`.

## Model and cost trace

Deterministic; no model call, no network, no disk write. cloud_calls zero.
