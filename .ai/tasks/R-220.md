# R-220 — True per-provider streaming for the cloud adapters

## Requirement

Replace the R-008 single-event stream wrapper with real incremental Server-Sent-Events streaming for
the cloud adapters (OpenAI-compatible: OpenAI/OpenRouter/Groq; Anthropic Messages; Google Gemini), so
tokens arrive live like the local Ollama adapter (Brief 57 streaming protocol, 18). Founder asked to
complete both true streaming and a second required item one by one; R-220 is streaming.

Reconstructed from Brief Sections 18, 57, 25, 26, 27, 74, 75, 84, 85, 90, 91, and 92.

## Acceptance criteria

- Each adapter streams incrementally by parsing provider SSE and yields ordered `StreamEvent` deltas
  plus one final event with `done=True` and measured token usage (usage only on the final event).
- Streaming reuses bounded line/response sizes, finite timeouts, redirect rejection, bounded
  concurrency, and maps failures to stable platform-owned errors without leaking the key or raw
  bodies.
- OpenAI-compatible streaming requests usage in the final chunk (`stream_options.include_usage`);
  Anthropic maps `message_start`/`content_block_delta`/`message_delta`/`message_stop`; Gemini uses
  `:streamGenerateContent?alt=sse`.
- The non-streaming `generate` path and all other adapter behavior are unchanged.
- Offline standard-library tests drive each provider's SSE parser with injected fake streaming
  responses (multi-chunk deltas, final usage, malformed/oversized lines), zero network access.
- Static `task verify` stays network-independent and green.

## Expected blast radius

`cloud.py` (streaming helpers + per-provider `stream`), `test_cloud.py` (SSE tests), and doc/state/
tracker evidence. No change to PostgreSQL, Compose, infrastructure, the Section 74 contract, or the
non-streaming behavior of prior tasks.
