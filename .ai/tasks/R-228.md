# R-228 — Git service v1 (materialize a generated project into a customer-owned repo)

## Requirement

Complete the first end-to-end builder slice (Brief §6/§20/§34/§71): write a `GeneratedProject` to a
target directory and initialize it as a real Git repository owned by the customer, with a first
commit. Deterministic and offline (git is available); writes only inside the caller-provided target,
never the platform repo. New IDs continue after the workbook backlog's R-010..R-219 (this is R-228).

## Acceptance criteria

- `materialize_project` writes every `GeneratedFile` under the target (creating parent dirs), refuses
  any path that would escape the target, and (unless `overwrite`) refuses a non-empty target;
  executable files get the executable bit.
- `create_repository` runs `git init`, stages all files, and makes one commit with the customer as
  author/committer via explicit `-c user.name/-c user.email` (no global git config), returning the
  commit SHA and file count.
- The written tree exactly matches the `GeneratedProject`; the repo has exactly one commit with those
  files.
- Standard-library + local `git` only; deterministic; offline; nothing outside the target is modified.
- Offline temp-dir tests cover materialization, escape refusal, non-empty refusal, repo init/commit,
  author identity, and tree/commit correctness. `task verify` stays green.

## Design notes

- New package `omnistackai_agent_engine.git_service`: `materialize.py`
  (`materialize_project`, `create_repository`, small result dataclasses), `errors.py`
  (`GitServiceError`, `TargetNotEmptyError`, `MaterializeError`, `RepositoryError`). Uses `subprocess`
  for git with an explicit identity and env; validates the resolved path stays within the target.
