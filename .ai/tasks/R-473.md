# R-473: Studio v1 in the real console — build an app from the product, not curl

**Phase:** MVP
**Status:** COMPLETED
**Started:** 2026-09-18
**Completed:** 2026-09-18

## Objective

Phase D of `R_&_D/OmniStackAI_Commercial_Platform_Kickoff_v1.md`, first slice: a logged-in user can
open `apps/console-web`, type a plain-English app description, click Build, and get a real app
built through the now-real Job API (R-472) — with their credit balance updated to match the real
cost incurred. This is the first time the console's own UI (not curl, not the agent-engine's local
`studio/page.py`) drives an end-to-end build.

## Scope decision — why this is a slice, not the full Phase D vision

The kickoff doc's Phase D describes a full IDE-like surface: persistent chat, top tabs
(Preview/Files/Code/Problems/Publish/More), Model Provider settings, a Problems tab wired to
`verify/compile.py`. Building all of that in one task would repeat the mistake this project's own
history explicitly avoids (compare: the agent-engine's own hybrid-UI engine took four separate,
gated Tracker IDs — R-465 synthesis, R-466 compile-repair, R-467 file browser + toggle, R-468
multi-turn edit — each shipped and proven before the next). This task ships the smallest real,
end-to-end slice: prompt in, real build out, real credit debit reflected in the UI. Later Phase D
tasks add the file browser, live preview, chat history, and the rest of the tab surface on top of
this foundation — named, not silently dropped.

## Design

- **`app/studio/page.tsx`** (new, Server Component): mirrors `app/page.tsx`'s auth gate exactly
  (`getCurrentUser()` → redirect to `/login` if signed out). Renders `<StudioForm user={user} />`.
- **`app/studio/studio-form.tsx`** (new, Client Component): owns the interactive build flow — a
  prompt textarea, a Build button, a pending/building state (real builds take real time: a local
  Ollama or cloud call plus repo assembly, observed 3s–3min live in R-472's own manual smoke test —
  the UI must set that expectation, not imply an instant result), an error banner on failure, and a
  result panel (name/description/entities/file_count/commit_sha/files, plus the `usage` block and
  `credits_spent` when the agent-engine reported them). Updates the displayed credit balance from
  the response's `credit_balance` — no separate re-fetch of `/auth/me` needed, the Job API already
  returns the authoritative post-debit balance.
- **`app/api/jobs/build/route.ts`** (new Route Handler): server-side only — reads the session cookie
  (`getSessionToken()`), 401s immediately with no upstream call if absent (matching the control-plane's
  own contract, but cheaper), then proxies the request body to the control-plane's `POST /jobs/build`
  with the bearer token attached (never exposed to client-side JS, same boundary every existing
  `app/api/auth/*` route already draws). No artificial timeout — the control-plane's own R-472 fix
  (`http.ResponseController.SetWriteDeadline`) is what makes waiting out a real multi-minute build
  possible; this route does nothing that would cut that short.
- **`lib/control-plane.ts`**: add `BuildJobResponse` (typed for the fields this UI actually reads —
  `name`, `description`, `entities`, `file_count`, `commit_sha`, `files`, `usage`, `credits_spent`,
  `credit_balance` — plus an index signature since the Job API is a generic proxy and can carry
  build-kind-specific fields, e.g. `pack_id`, this UI does not render) and `buildApp(token, prompt)`,
  following the exact `callControlPlane` pattern `login`/`registerAccount` already use.
- **`app/page.tsx`**: one new link to `/studio`, mirroring the existing `/fabric` link.
- **`app/globals.css`**: a `.field textarea` rule (only `input` is styled today) and a small
  `.pill`/file-list treatment for the result panel — reusing existing tokens/panel/grid classes
  everywhere else, no new UI dependency.

## Explicitly out of scope for this task (named, not silently dropped)

## Acceptance Criteria

- [x] `/studio` redirects to `/login` when signed out, exactly like `/`.
- [x] `POST /api/jobs/build` 401s with no upstream call when the session cookie is missing.
- [x] A real `/jobs/build` call's JSON response renders in the UI (name, entities, file_count,
      commit_sha, files) and the displayed credit balance reflects the response's `credit_balance`.
- [x] A build with no `usage` key (e.g. a Solution Pack response, if ever sent) does not crash the
      UI — the usage/cost block is simply omitted (`{result.usage ? ... : null}` guard).
- [x] An upstream error (agent-engine unreachable, invalid build, insufficient... — any non-2xx)
      renders as a clear error banner, not a silent failure or an unhandled exception. Proven live
      by a real, unforced local-model IR-validation failure (see below) — not a synthetic test.
- [x] `pnpm run typecheck`/`lint`/`build` all clean; `task verify` stays green.

## Live discovery (found while implementing, not anticipated in the contract above)

- **A real bug in the repo's own `.gitignore`, found only by double-checking `git status` before
  committing:** a bare `build/` rule (line 12, pre-existing) matches any directory named `build` at
  any depth, not just an intended top-level build-output directory. This product's own Job API is
  literally `/jobs/build`, so `app/api/jobs/build/route.ts` — this task's server-side proxy route —
  was silently excluded from every `git add`. `next build`/`next start` still compiled and served it
  correctly (Next.js's file-based routing does not care about Git state), so this was invisible in
  every gate and in the live smoke test itself; it would only have surfaced as a missing file after
  a fresh clone. Fixed by removing the overly broad `build/` line (confirmed nothing in the repo
  actually relied on it: the only two directories anywhere literally named `build` were this route
  and its own `.next/` mirror, already covered by the pre-existing `.next/` rule). Re-verified with
  `git check-ignore` before and after the fix, and by confirming `git status` now lists the route
  file as addable.

   `credits_spent: 0`, `credit_balance: 100` - correct (local Ollama stays credit-exempt) and an
   exact shape match for every field `BuildResult` in `studio-form.tsx` renders.
9. Cleanup: killed the console/Studio server processes, `docker compose down`, removed temp
   response/cookie files - `git status --short` confirmed a clean tree with only this task's
   intended files changed.
