# R-425: Per-build repo actions — copy path + open folder

## Objective
Let the operator jump from a recorded Studio build to the owned code on disk. Add per-build actions to the
"Recent builds" list: a purely client-side **Copy path** (copies the recorded repo `target_dir` to the
clipboard; works in both Studio modes), and an **Open folder** action that opens the recorded repo directory
in the OS file browser via a new trusted-local route `POST /api/history/open {id}`. The open route reuses the
same injected-handler pattern (an `open_dir_fn(build_id) -> dict`) and is wired only in trusted-local preview
mode (build-only Studio returns 404); it looks up the recorded build, launches the platform folder opener
(`open` / `xdg-open` / `os.startfile`) best-effort, and returns a bounded, secret-free status
(`opened`/`error`) — it never runs generated code, echoes a command, or exposes an environment. No change to
build, preview, history, status/stop/restart, collision-free ports, single-session cleanup, PostgreSQL, or
`studio:serve`/`studio:preview` semantics; all verification stays deterministic and offline (the folder
opener is opt-in/live and injected/stubbed in tests).

## Status
DONE

## Requirements
- Add a trusted-local `POST /api/history/open {id}` route over the stdlib Studio server via an injected
  `open_dir_fn(build_id) -> dict`; unset handler returns 404; missing id returns 400; handler errors -> 502.
- Wire the opener only in trusted-local preview mode (build-only exposes no open route); it looks up the
  recorded build and opens its `target_dir` with the platform folder opener, returning a bounded,
  secret-free status (`opened`/`error`); an unknown/removed build returns a bounded error.
- Add a client-side "Copy path" per build (clipboard write of the recorded `target_dir`, with a fallback and
  transient feedback) that works in both modes without a server call.
- Add an "Open folder" button per build that calls `POST /api/history/open` and shows a bounded result.
- Keep all payloads/logs secret-free; the opener never echoes the command, path env, or a traceback.
- Deterministic/offline verify via injected fakes; `task verify` runs no generated code, Docker, PostgreSQL,
  package install, model, external network, or folder opener.

## Acceptance Criteria
- `POST /api/history/open {id}` returns the opener's bounded status when wired and 404 when not; missing id ->
  400; the handler receives the build id.
- The opener default returns `opened` on success and a bounded `error` message otherwise, and returns a
  bounded error for an unknown build id.
- The Studio page exposes per-build "Copy path" (client clipboard) and "Open folder" (`/api/history/open`)
  actions without HTML injection.
- Existing studio/preview/server/history/local-run contracts remain compatible; focused + full verify + lint
  + security + env + both builder demos pass; 0 model calls in verify.
