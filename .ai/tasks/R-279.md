# R-279 — Global Notification Toast System & Action Feedback in Generated Next.js Web App

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Implement a lightweight, dependency-free global notification toast system in the generated Next.js web application
(`apps/web/components/toast.tsx`, `apps/web/app/layout.tsx`), and wire real-time toast feedback into generated
collection screens, detail screens, and form screens:

1. **`ToastProvider` and `useToast` Hook** (`apps/web/components/toast.tsx`):
   - `"use client"` React context provider managing floating toasts.
   - Provides `addToast(message, type, duration)` and typed helpers `toast.success()`, `toast.error()`, and `toast.info()`.
   - Render floating viewport container (fixed bottom-right, z-index 9999, flex-col, gap 8).
   - Toasts render with distinct status accents (emerald for success, red for error, blue for info), iconography, auto-dismiss timers, and dismiss `×` buttons.
2. **RootLayout Integration** (`apps/web/app/layout.tsx`):
   - Import `ToastProvider` from `../components/toast` and wrap `{children}`.
3. **Screen Action Feedback**:
   - Collection screens: trigger `toast.success` on single and batch delete; `toast.info` on CSV export.
   - Detail screens: trigger `toast.success` on delete; `toast.info` on JSON export.
   - Form screens: trigger `toast.success` on create and update.
4. **Offline & Safety**:
   - 100% offline, zero new external npm dependencies, zero new IR fields, strict diff invariance across `ir.description`.

## Acceptance criteria

1. `apps/web/components/toast.tsx` is generated as a client component exporting `ToastProvider` and `useToast`.
2. `apps/web/app/layout.tsx` imports and renders `<ToastProvider>`.
3. Collection screens import `useToast` and display toasts for delete and CSV export actions.
4. Detail screens import `useToast` and display toasts for delete and JSON export actions.
5. Form screens import `useToast` and display toasts on successful create/update.
6. Strict diff invariance: changing only `ir.description` produces byte-identical output across toast components.
7. Stage 0 verification (`task verify`), `task lint`, `task security:quick`, and builder demos pass.
