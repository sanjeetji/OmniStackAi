# R-238 — PostgreSQL schema/migration generation from the Application IR

## Requirement

Give the generated backend a real persistence layer (Brief §9/§34/§42): render a deterministic
PostgreSQL schema from the IR entities + relations and emit it as `migrations/0001_init.sql` in the
backend target. Emitted only when the IR declares entities and `database_strategy=postgres`. Pure,
deterministic, offline — no DB connection, no migration run, no network. The R-237 edit loop diffs the
migration automatically when the IR changes. Committed directly to `main`. New IDs continue after the
backlog's R-010..R-219 (this is R-238).

## Acceptance criteria

- `render_postgres_schema(ir)` → deterministic SQL DDL: one `CREATE TABLE` per entity, snake_case table
  names, FieldType→PostgreSQL column types, `NOT NULL` for required fields, a UUID primary key (the
  entity's own `id` field if present, else a surrogate `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`).
- `many_to_one`/`one_to_one` relations → a `<name>_id UUID REFERENCES <target>(id)` column;
  `many_to_many` → one deterministic join table with a composite primary key; empty string for an IR
  with no entities.
- The Python (FastAPI) and Go backends emit `migrations/0001_init.sql` exactly when the IR has entities
  and `database_strategy=postgres`, without changing any previously emitted file.
- Output is byte-stable across runs; `plan_edit` picks up a migration change when entities change.
- Offline tests cover the type map, required→NOT NULL, PK selection, FK columns, the join table,
  determinism, the postgres/entities gate, and adapter emission.

## Design notes

- New `codegen/schema_sql.py`: `render_postgres_schema(ir)` + `_snake`, `_PG_TYPE`. Iterates entities in
  IR order; join tables collected, de-duplicated by sorted pair, and sorted by name for determinism.
- `backend_python.py` / `backend_go.py`: append the migration file when
  `ir.entities and ir.project_strategy.database_strategy is DatabaseStrategy.POSTGRES`. No other emitted
  file changes.
- No DB connection, no migration execution, no network. Standard-library only.

## Model and cost trace

Deterministic; no model call, no network, no DB connection. cloud_calls zero.
