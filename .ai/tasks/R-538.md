## Outcome (2026-09-23)

**Completed.** `templates/catalog/care-clinic` v1.0.0 is published and listed (healthcare, 4 apps,
48 screens, a composed cover). The draft `templates/catalog/_care-clinic` was removed at publish,
as with `ride-now` and `bazaar`.

### What the draft console actually was

All 18 pages of `apps/admin` rendered hard-coded arrays, and sign-in wrote
`"mock-jwt-admin-token"` to local storage without calling the API. Three files in the app
referenced the API client and none of them fetched anything. The console was rewritten against the
API: a staff session and guard, one shared event-stream connection, a fallback poll, and every page
reading live clinic data.

### API added for it

`/api/admin/rooms`, `/api/admin/doctors/:id/schedule` and `/schedule-override`,
`/api/admin/invoices/:id` and `/collect`, `/api/admin/appointments/:id/cancel`,
`/api/admin/labs/:id` and `/labs/:id/status`, `/api/admin/queue/:id/call`, `/api/admin/reports`.
`POST /auth/login` now takes the role the app is for and answers 403 for an account of another
kind. `src/lib/document-number.ts` replaces `COUNT(*) + 1` numbering.

### Defects found in R-535 to R-537 and fixed here

| What | Effect |
|---|---|
| 48 appointment end times were `HH:60:00` | the seed aborted on load; the template had never run |
| `queue_status` copied from the appointment status | `no_show` is not in its check constraint; the load aborted |
| Nine tables never written | vitals, lab orders and results, invoice line items, refunds, reviews, telehealth sessions, notifications, schedule overrides were all empty |
| The demo patient's appointments all cancelled or no-show | the account the demo signs in with had an empty chart |
| Seven patient route folders URL-encoded (`%5Bid%5D`) | every detail page 404'd on a real id |
| Doctor cards read `doctor_id`, the directory returns `id` | every card linked to `/doctors/undefined` |
| Three doctor-app links hard-coded `pat-1` | dead links |
| `services/api` did not type-check | untyped Hono context, 44 errors |
| Shared types named columns the API never returns | `fee_inr`, `paid_amount`, `is_abnormal`, `clinical_indication` |
| Document numbers from `COUNT(*) + 1` | the first prescription issued against the seed collided |
| Surnames allocated in blocks of 50 | a screen of patients read "Deshmukh" all the way down |

### Known, not fixed

`apps/doctor` (R-537) has the same defect the console had: the consultation, SOAP, prescription,
lab-order, telehealth, reviews, earnings, schedule and patient-history screens render hard-coded
state rather than API data. Only the dashboard, the queue and the patient chart read the API at
all, and those overlay mock values. The pages render and the screenshots are of real pages, but the
workstation is not wired to the backend. It needs its own task.

`apps/patient` keeps invented fallback rows when an API call fails, so a backend failure shows
plausible fiction rather than an error. Worth removing at the same time.
