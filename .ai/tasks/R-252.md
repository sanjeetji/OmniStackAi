# R-252 — Enforce go-playground validation in the generated Go create handlers

## Requirement

R-251 made the Go models carry go-playground `validate:"..."` struct tags, but nothing evaluated them —
the tags were declarative. R-252 closes that gap so the generated Go backend actually rejects invalid
create payloads (Brief §9/§26/§27). FastAPI already enforces at construction time via Pydantic, so this
task is Go-only.

When at least one wired CREATE endpoint's entity carries validation rules, the Go backend now:

1. declares `github.com/go-playground/validator/v10 v10.22.1` in its own `go.mod`;
2. emits `internal/handlers/validate.go` — a shared `var validate = validator.New()` and a
   `validateStruct(v any) (int, string)` helper returning `400` / `"validation_failed"` on a tag
   violation (`""` message means valid);
3. calls `validateStruct(m)` in each such CREATE handler, right after the JSON decode block and before
   the `store.Create<Entity>` call, writing `http.Error(w, msg, status)` + `return` on failure.

Rule-free projects (no field carries a rule) are byte-identical to R-251: no validator dependency, no
`validate.go`, no call. The dependency lives ONLY in the generated project's `go.mod`; the agent-engine
adds no dependency. Additive/offline; nothing is installed, built, run, or DB-connected. Committed
directly to `main` (R-252).

## Acceptance criteria

- Rules+create IR: `go.mod` has `require github.com/go-playground/validator/v10 v10.22.1`;
  `internal/handlers/validate.go` exists with `var validate = validator.New()` and
  `func validateStruct(v any) (int, string)` returning `http.StatusBadRequest` / `"validation_failed"`,
  importing the validator package.
- Each such CREATE handler calls `validateStruct(m)` AFTER the decode block and BEFORE `store.Create…`,
  returning `http.Error(w, msg, status)` on failure.
- Rule-free IR (existing Go fixture, minimal-blog, rideshare-favourites): no validator require, no
  `validate.go`, no `validateStruct` call — CREATE handler byte-identical to R-251.
- Rules-without-create IR: no `validate.go` / dep; models still carry the R-251 tags.
- Offline tests cover enforcement emitted, enforcement absent (both reasons), handler call ordering, and
  examples-unaffected.

## Design notes

- `field_validation.py`: add `VALIDATOR_REQUIRE = "github.com/go-playground/validator/v10 v10.22.1"` and
  `go_validate_file() -> str` (the `validate.go` source), mirroring `auth_guard.GOLANG_JWT_REQUIRE` /
  `go_auth_file`. Export both from `codegen/__init__.py`.
- `backend_go.py`: compute `repo_entities` / `fk_by_entity` up front; `_validated_entities(ir)` = entity
  names with a non-empty `go_validate_tag`; `has_validation` = any wired CREATE whose entity is in that
  set. Add `require VALIDATOR_REQUIRE` to `go.mod` and emit `validate.go` only when `has_validation`.
  Pass `validated_entities` into `_handlers_file_wired`; the CREATE branch emits the `validateStruct(m)`
  guard only for entities in that set. No new import in the segment file (same `handlers` package).
- Examples unchanged (no rules) → no behavioral change to example output.

## Model and cost trace

Deterministic; no model call, no network, no DB connection. cloud_calls zero.
