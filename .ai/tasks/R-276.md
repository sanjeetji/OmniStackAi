# R-276 — Record Selector Dropdown, Prev/Next Record Navigation & Deep-Link Sync in Generated Next.js Detail Screens

**Status:** done
**Phase:** BASIC/MVP — Founder Stage 0
**Branch:** `main`
**Complexity:** L2

## Objective

Enhance generated Next.js detail screens (`apps/web/app/<screen>/page.tsx`) with an interactive
record selector dropdown, sequential previous/next navigation buttons, automatic URL query param
sync (`?id=...`), and a quick-pick recent records grid in the empty state:

1. When `Op.LIST` is wired for the entity, import `useList<Plural>` from `../lib/hooks`.
2. Render a styled `<select>` dropdown in the ID selection section offering `"-- Choose {name} --"`
   followed by existing items labeled with the best descriptive field (e.g. `title`, `name`, `label`, `email`, or `id`).
3. Selecting an item from the dropdown or clicking a recent record updates `selectedId`, `idInput`, and
   synchronizes the URL search params (`?id=<id>`) using `window.history.replaceState`.
4. When an entity record is displayed and list data is available, render contextual `"&larr; Prev"` and `"Next &rarr;"`
   navigation buttons allowing users to cycle through records sequentially.
5. In the empty state (when no record is selected), render a "Recent {plural}" grid of clickable card tiles
   so users can immediately inspect a record with one click instead of needing to know a UUID.
6. Fall back cleanly when `Op.LIST` is not available (keeps manual ID input, no hook import, no broken code).
7. 100% offline, zero new external npm dependencies, zero new IR fields, strict diff invariance.

## Acceptance criteria

1. Detail screen imports `useList<Plural>` when `Op.LIST` is wired.
2. Detail screen does not import `useList<Plural>` when `Op.LIST` is not wired.
3. Dropdown `<select>` is rendered with placeholder and options when `Op.LIST` is wired.
4. Prev and Next buttons are rendered and properly disabled at boundary indices.
5. Empty state displays recent records card grid when list items exist.
6. URL synchronization logic via `window.history.replaceState` is emitted.
7. Strict diff invariance: changing only `ir.description` produces byte-identical output.
8. Stage 0 verification (`task verify`), `task lint`, `task security:quick`, and builder demos pass.
