# R-421: Managed live generated-app preview inside the local Studio

## Status

DONE — 2026-09-13

## Objective

Make instant browser preview the first visible post-build result in an explicit trusted-local Studio
mode. Reuse the R-419 run plan and executor work: do not invent another runtime, service, or process
launcher. The Studio must own exactly one active generated-app session, replace it safely after a new
build, embed the real Next.js URL, and clean up all child processes on replacement or shutdown.

## Architecture and acceptance

- Preserve `task agent-engine:studio:serve` as build-only. Add `task agent-engine:studio:preview` as the
  explicit local generated-code execution command, with `db:up` as a Task dependency and clear trusted-
  local labeling. This mode is not a cloud sandbox and must not be presented as one.
- Extract a reusable managed `LocalAppSession` from the current R-419 CLI executor. It owns the run plan,
  started processes, readiness results, and idempotent cleanup; the existing `app:run` CLI delegates to it.
- Add a small Studio preview coordinator with an injected session starter. It serializes replacement,
  stops the prior session, emits a bounded JSON-safe payload (`ready`, `error`, or `unavailable`), and
  never leaks credentials or a raw traceback. A preview failure does not erase a successfully generated repo.
- The static Studio page adds a sandboxed iframe, an open-preview link, and accessible preview status.
  It sets URL-bearing DOM properties rather than injecting response HTML.
- Verification uses only stubs/mocks and ephemeral loopback for the pre-existing HTTP tests. It never
  executes generated code, installs dependencies, touches Docker/PostgreSQL, or calls a model.

## Blast radius

The change is limited to the existing `localrun/` and `studio/` packages, their focused tests, Task/shell
entrypoints, runtime documentation, and required project state files listed in `.ai/CURRENT_TASK.yaml`.
No Application IR, generator, provider, database, Git, deployment, infrastructure, or mobile contract changes.

## Verification plan

Write the lifecycle, failure, replacement, iframe, and explicit-task assertions first; prove them red;
implement the smallest managed-session and Studio composition; then run focused tests, existing studio/
local-run regressions, lint, full offline verify, security, environment, and both builder demos. Inspect
the opt-in task and preview payload without invoking Ollama. Model trace target: 0 local, 0 cloud.

## Completion evidence

  cleanup, cleanup on partial failure, occupied-port preflight, and exited-child detection. The existing

- Added `StudioPreviewManager`: one serialized active session, replacement/shutdown cleanup, and bounded
  secret-free `ready`/`error`/`unavailable` payloads. A launch failure preserves the successful build.
- Added the sandboxed iframe and safe loopback URL validation. Added separate `studio:serve` build-only and
  `studio:preview` explicit trusted-local commands; the latter depends on `db:up`.

  demos passed. Static command/export inspection passed. No model or generated code ran in verification.
- Existing ports 3000/8000 were already owned by an earlier user app session and were not interrupted; the
