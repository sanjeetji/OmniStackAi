# R-237 — IR-diff → patch-apply edit loop

## Requirement

Add the "edit an existing app" motion (Brief §6/§27/§34): compute the minimal file-level change set
between two generated projects and apply only that delta to an existing project on disk, then record it
as a new commit on the customer-owned repo. This is the builder motion after generate (R-225..R-232)
and verify (R-235): change the IR → regenerate → apply just the diff. Diffing is pure/offline; applying
and committing are bounded, path-safe disk steps (like the R-228 git service). Committed directly to
`main`. New IDs continue after the backlog's R-010..R-219 (this is R-237).

## Acceptance criteria

- `diff_projects(old, new)` → a `ProjectDiff` classifying every path as added / modified (content or
  executable differs) / deleted / unchanged; identical projects diff to an empty change set.
- `plan_edit(old_ir, new_ir, registry=None)` assembles both IRs and returns their `ProjectDiff`; a
  changed IR (new description/entity) yields the expected modified/added files.
- `apply_diff(diff, target_dir)` writes added/modified and removes deleted files inside a path-safe
  target (refuses escapes), returns an `ApplyReport`, and leaves the dir equal to the new project.
- `commit_edit` applies a diff and records one commit as the customer identity (reusing an additive
  `git_service.commit_all`); previous history is preserved.
- Offline tests cover diff classification, empty diff, plan_edit over a changed IR, apply round-trip,
  path-safety refusal, and the commit_edit history.

## Design notes

- New `omnistackai_agent_engine.edit` package: `diff.py` (`ChangeKind`, `FileChange`, `ProjectDiff`,
  `diff_projects`, `plan_edit`), `apply.py` (`ApplyReport`, `apply_diff`, `commit_edit`), `errors.py`.
- `git_service` gains an additive `commit_all(target_dir, *, author_name, author_email, message)` that
  stages and commits an already-materialized change; `create_repository`/`materialize_project` unchanged.
- Path safety mirrors `materialize_project` (resolve under the target, refuse escapes). No network, no
  code execution, no writes outside the target.

## Model and cost trace

Deterministic; no model call, no network, no code execution. cloud_calls zero.
